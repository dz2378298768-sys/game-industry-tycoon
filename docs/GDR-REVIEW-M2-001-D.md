## 1. P1（阻断，必须清零）

### P1-1 退市语义自相矛盾（一致性）

§6.4 表格写"产品不存在 / 已 `retired` → `LIFECYCLE_IMMUTABLE`"，§10 表又写"已退市再退市按幂等成功处理"。同一动作两种结果，编码无法实现。

**改法**：退市 = 幂等成功（重复调用不改状态、不发事件，返回 `{ alreadyRetired: true }`）；`LIFECYCLE_IMMUTABLE` 只用于"退市后改价/打折"。§6.4 表格与 §10 统一。

### P1-2 折扣冷静期的论证不成立（数值/一致性）

规格称"冷静期 14 天与退款窗口同值，堵首日打折刷量再退款套利"。这条不成立：退款金额按 `unitPriceAtSaleCents` 全额退，打折卖出、退款退回的就是折后价，玩家拿不回差价，**不存在套利空间**。同时它把两个不同维度混为一谈——退款窗口是"销售日 + 14 天"，折扣冷静期是"上市日 + 14 天"。

**改法**：理由改写为"首发价格可信度与首日价格战防护"（首发 14 天内不打折，避免'首发即降价'的观感与后续定价失去锚点）；数值保留 14 天，但删掉"堵套利"表述与"与退款窗口同值"的因果链，并明确二者独立。

### P1-3 交付后到 G 批之前，定价不可达（体验闭环/可验收）

D 批补了定价命令，但 UI 属 G 批。若修复路径只有 UI，则 D 交付到 G 完成这段窗口里"真实产品无定价 → 无销售 → M2 出口条件（解释销量变化）不可达"，而 M2 出口验收若排在此窗口必挂。

**改法**：D 的验收显式要求"定价命令在无 UI 条件下可达"（`gameWorld.setProductPrice(...)` 直接调用可产生次日销售记录），并在 §13 增设"最小可玩脚本"：建公司 → 立项 → 上市 → `setProductPrice` → D+1 有销售记录；把它列为 M2 出口试玩的强制步骤。UI 呈现仍归 G 批，不越界。

## 2. P2（不阻断，但须在 v1.1 一并处理）
