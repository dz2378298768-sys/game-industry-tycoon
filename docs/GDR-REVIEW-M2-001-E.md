| 属性 | 内容 |

| 审查对象 | `DESIGN-M2-001-E-SAVE-MIGRATION.md` **v1.0** |
| 结论 | **REVISE_REQUIRED** —— P1×3、P2×3 |
| 日期 | 2026-11-19 |

## 1. P1（阻断）

### P1-1 返回类型没定义清楚（一致性）

§7 写"`ok:true`（`migratedFrom:1`）"，但现有 `ParseSaveResult` 只有 `{ok:true; state}`，`loadGame` 也按该形状解构。规格没说 `parseSave` 是否扩字段、扩了以后 `loadGame` 怎么拿。实现时两种写法会打架。

**改法**：`ParseSaveResult` 扩为 `{ ok:true; state; migratedFrom?: number }`；`loadGame` 增加 `migratedFrom?` 与 `backupWritten?` 两个可选字段，其余分支不变。

### P1-2 备份单槽会丢档（数据安全）

INV-4 规定"备份键已存在则跳过"，但全局只有 `git_save_backup_v1` 一个槽。玩家若先后产生两份 v1 档（换 seed / 重开），第二份迁移时备份被跳过 → **第二份旧档永久没有备份**，与"失败不破坏原档"的初衷相反。

**改法**：备份键改为 `git_save_backup_v1:<saveSeed>`（seed 在档内，天然唯一）；同 seed 重复读档仍跳过（幂等），不同 seed 各留一份。键前缀常量集中一处。

### P1-3 迁移档白送 7 天改价自由度（公平性）

D 批的改价冷却以 `lastPriceChangeDay` 为基准，缺省视为"从未变更"。迁移时该字段保持缺省 → 迁移档玩家可在读档当天立刻改价；原生 v2 玩家首次定价当天则被锁 7 天。同一规则对两类玩家不等价。

**改法**：迁移时对已定价产品写 `lastPriceChangeDay = 0`（v1 时代没有改价概念，语义等价于"价格自上市起未变、冷却早已走完"），并补一条不变量与测试；不写 `currentDayIndex`（那会凭空锁玩家 7 天，属于反方向的错）。
