# M3 总纲 R1 审查（v0.2）

审查对象：`docs/DECISION-M3-SCOPE-001.md`（v0.2 DRAFT）
结论：**NOT READY**，P1=8，P2=5
放行条件：P1 全部逐项回应并出 v0.3，才能进入 P0-2 修订与 C1 v1.1

## P1

### P1-1 多平台产品会重复计算同一批需求

现状：`Product.supportedPlatformIds` 是数组，`market-simulation-service.ts` 对每个平台都取完整 `eligibleAudience`，没有按平台拆分需求池。一个产品支持 3 个平台，就会在同一市场卖 3 份全量受众。

同时 `audienceSegmentIds` 是数组，但服务层只取 `segments[0]`，并打 `SALES_MULTI_SEGMENT_DEFERRED` 警告；多受众产品实际只卖第一个受众。

必须定义：

- 需求池按 `market × platform × segment × day` 切分；
- 产品按支持平台/受众获得池的准入，不是每个平台拿全量；
- 同一消费者不能在同一日被同一产品重复计入；
- 多平台产品的池分配按平台装机量/触达比例拆分，拆分后总和守恒。

### P1-2 认知度作用域与需求池不一致

现状：`Product.awarenessByMarket` 只按市场存认知度，但竞争与营销要按平台/受众定位。若继续按市场存，营销无法区分平台，竞争也无法按平台计算份额。

必须定义：

- 认知度按 `market × platform × segment` 存，或明确从市场级投影到池级的规则；
- 旧档 `awarenessByMarket` 的回填/迁移规则；
- 营销投放目标与认知度作用域一致。

### P1-3 需求模型契约缺失

v0.2 只写了“吸引力份额”，没有冻结：

- 池总量公式（eligible audience × purchase intent × 平台活跃度？）；
- 吸引力公式（认知度、质量、价格价值、匹配、品牌、营销的权重/指数）；
- θ 的取值与头部集中度；
- 守恒不变量与数值容差；
- 产品进入/退出池时份额重算规则；
- 零需求、零吸引力、全零池的边界。

没有这些，Stage 2/3 的选址和定价无法验收。

### P1-4 合同与渠道没有进入吸引力

v0.2 说合同要影响竞争，但需求模型没有“渠道覆盖/发行准入”项。渠道分成、联合营销、预付款目前只影响现金流和认知度，不改变产品能否进入某个池、能触达多少受众。

必须定义：

- 合同带来的 `availability` / `channelReach` 因子；
- 自发行与签约发行的池准入差异；
- 合同排他/范围限制如何影响份额；
- 合同控制权对定价/营销的约束在需求模型里的体现。

### P1-5 平台生命周期数据不存在

现状 `platforms.json` 只有可用起始年份，没有结束年份、衰退曲线、装机量曲线。平台只增不减，所有 AI 仍会拥向“最新平台”。

必须补：

- `lifecyclePhase`（增长/成熟/衰退）；
- `endYear` 或 `sunsetDay`；
- 装机量/活跃用户曲线；
- 旧平台衰退后产品销量如何衰减；
- 数据覆盖 1970–2026 的最小集。

### P1-6 破产重整的会计口径未定义

v0.2 只写了 90/180/360 天和“现金回到恢复线”，没有定义：

- 现金、应收、合同债务、退款、尾货收入各自如何入账；
- 工资按出勤还是按合同；
- 已售未结分成是否算应收；
- 资产处置的估值规则；
- 延长到 180 天的客观条件；
- 重整期是否继续计提固定成本。

这必须先修订 P0-2，否则 C1 无法编码。

### P1-7 验收指标缺少可计算定义

- “有效竞争者”没有定义（份额 ≥5%？在售产品 ≥2？收入 ≥ 阈值？）；
- CR4 的“市场”是全行业、平台还是受众；
- “成熟市场”阈值 $50M / 8 家是否按年代调整；
- “单一公司连续 3 年平台收入份额 >65%”在平台只有 1 家公司时如何判；
- HHI 用销售额、销量还是利润；
- 样本不足时哪些指标不判。

### P1-8 需求池的确定性与性能未定义

需求池按池聚合全部在售产品，若每日全表扫描，复杂度随产品数平方增长；确定性还依赖产品遍历顺序、浮点求和顺序、份额重算顺序。

必须定义：

- 池索引结构（按 platform × segment 建桶）；
- 稳定排序键（productId）；
- 浮点份额的容差与归一化；
- 单日复杂度上限；
- 与现有 `salesByPeriod` / 退款 / 结算链路的兼容。

## P2

1. 四类战略姿态没有映射到具体评分权重，容易变成“标签”。
2. 决策节奏只写了月度/季度/事件，没有事件清单与优先级。
3. 最小 AI 决策日志 UI 没有验收项。
4. 破产重整、平台生命周期会改存档结构，未写 schema 版本策略。
5. C2 的启动条件只写“Stage 0 后并行”，没有内存/耗时基线。

## 放行条件

1. P1-1 至 P1-8 逐项在 v0.3 回应，给出公式、数据结构、边界与反证用例；
2. P0-2 修订单独出裁定，不混在总纲里；
3. C1 v1.1 只引用冻结后的总纲，不再自行改规则；
4. 通过 R2 后，才允许编码代理进场。
