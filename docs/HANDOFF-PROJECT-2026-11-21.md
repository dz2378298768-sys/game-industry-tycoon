## 1. 项目定位与首发范围

### 1.1 定位

- 类型：单机、回合/日推进的经营管理模拟；
- 视角：游戏研发商 + 轻量发行经营；
- 核心张力：**研发投入 vs 现金安全 vs 市场窗口**；
- 情绪目标：让玩家感到“每一次立项、每一次延期、每一次破产重整都是真实取舍”，不是数值堆叠。

### 1.2 首发范围（DECIDED）

做：

- 公司创建、招聘、员工管理；
- 项目立项、预算、组队、研发、QA、砍范围、延期、上市；
- 定价、折扣、销售、退款、平台抽成、营销；
- 财务流水、月末结算、负现金、破产重整、解散；
- 有限 AI 公司、AI 决策、发行合同；
- 平台生命周期、市场/受众、统一需求池；
- 存档/读档、迁移、基础 UI。

明确不做（DEFERRED）：

- 玩家运营平台、游戏引擎、硬件制造；
- IPO、股票、股权、并购、多事业部；
- 联机、创意工坊；
- 复杂税制、劳动法；
- 数百个历史事件、深度 IP 授权/订阅/云生态。

**范围红线**：任何新系统先问“它是否服务首发范围内的研发商+发行经营”；不服务就不要进 M3。

## 3. 玩家现在能做什么

按真实 UI 路径：

1. **创建公司**：选城市、公司名、初始现金；
2. **招聘**：岗位、技能、薪资、管理容量；
3. **立项**：选类型、平台、受众、预算、计划上市日；
4. **组队与研发**：分配员工、推进阶段、处理暂停/预算耗尽；
5. **QA**：提前 QA 有惩罚、修缺陷、最终质量 = 100 - 缺陷；
6. **砍范围 / 延期**：用目标完成度换现金/时间；
7. **上市**：定价、平台年代校验、首日销售；
8. **销售与退款**：按日销量、平台费、退款窗口、口碑；
9. **营销**：上市前/上市后按渠道投日预算；
10. **财务**：流水、月末工资/房租、负现金、破产；
11. **产品管理**：调价、折扣、退市、产品详情；
12. **存档/读档**：Zod 校验、v1/v2→v3 迁移。

尚未对玩家开放：

- AI 公司默认不出现（需开 `aiCompetition`）；
- 发行合同玩家侧只有基础结算，没有完整谈判 UI；
- 破产重整面板 T10 未做；

## 4. 工程架构

### 4.1 分层

```
src/
  app/          应用壳、创建公司、导航
  ui/           React 页面、Zustand store、组件、样式
  application/  GameWorld：编排所有 Service、玩家/AI 共用入口
  domain/       实体、值对象、枚举、错误、事件（纯类型，无 React）
  simulation/   日历、财务、员工、项目、QA、销售、营销、合同、AI、调度
  infrastructure/ 存档（Zod）、内容加载
  content/      JSON 数据 + tuning.ts + queries.ts
  i18n/         en / zh-CN
```

### 4.2 八条硬约束

1. `GameCalendar` 是唯一日期推进入口；
2. `FinanceService` 是唯一现金修改入口；
3. `RandomService`（mulberry32）是唯一模拟随机入口；
4. `domain/` 与 `simulation/` 不得依赖 React/DOM/浏览器 API；
5. `simulation/` 禁止 `Math.random()`、`Date.now()`；
6. UI 只能通过 `application/` 层操作游戏状态；
7. `DailyScheduler` 是唯一每日调度入口；
8. 所有可调参数集中在 `src/content/tuning.ts`。

违反这八条的改动，短期能跑，长期一定让存档/复现/审核崩。

### 4.3 每日管线

`DailyScheduler.executeDay` 的顺序是设计的一部分：

```
暂停超时 → 销售 → 生命周期 → 退款 → 营销 → 合同结算
→ 项目研发 → 员工日更新 → 月末结算 → 预算耗尽
→ 现金同步 → 破产检查 → 清仓模式 → 重整时钟 → 月末解散
```

关键约束：

- 销售先于研发：当日研发完成的产品最早 D+1 销售；
- 破产判定在所有结算之后；
- 解散只在月末判定；
- 同日重复调用幂等。

### 4.4 月度 AI

- 每月 1 日，`GameWorld.runAiMonthly` 对每个非玩家、非 dissolved 公司跑 `planAiMonth`；
- 决策记录保留 24 个月，包含候选、约束失败原因、最终动作；
- 正常期 9 个动作，破产期 3 个动作；
- 恢复不是动作，由每日现金/现金流判定自动发生。

### 4.5 存档

- `SAVE_SCHEMA_VERSION=3`；
- 解析器兼容 v1/v2/v3，不做降级；
- v2 破产档按 `bankruptSinceDay` 回填阶段与 90 天期限；
- 认知度按 scope 拆分，旧 `awarenessByMarket` 只读汇总；
- 合同补 `rateProfile='legacy'`；
- 读档校验现金与流水一致、引用完整。

## 5. 已实现系统清单

### 5.1 公司、员工、财务

- 公司创建、初始现金唯一 `advance` 入账；
- 员工招聘、解雇、士气/疲劳、管理容量、工资；
- 月末工资 + 城市租金；
- 负现金允许，破产由 M3-P0-1 接管；
- 财务流水按 category 记录，现金变化可追。

### 5.2 项目与 QA

- 阶段：CONCEPT → PRE_PRODUCTION → PRODUCTION → QA → READY_TO_LAUNCH → LAUNCHED；
- 工作量门控、QA 进/出守卫、暂停/超时、预算耗尽；
- 砍范围、延期上市、追加预算；
- 质量：提前 QA 惩罚、缺陷修复、最终质量；
- 一项目一产品。

### 5.3 销售、退款、定价、营销

- `SalesRecord` 按日、按市场、按平台记录；
- 平台抽成、退款窗口、退款批次、幂等键；
- 定价、折扣、7 天冷却、产品生命周期；
- 营销按渠道日预算，上市前/上市后，`marketingLift` 1.0–2.0；
- 市场输入、认知度、平台可用性。

### 5.4 发行合同

- 三模板：`revenue_share`、`minimum_guarantee`、`hybrid`；
- 预付款、回收、分成、控制权、合同期限；
- `rateProfile: legacy | realistic` 隔离旧合同与新合同；
- 合同结算在退款之后，基数含退款冲减。

### 5.5 AI 与生命周期

- 24 家 AI 公司，1970–1990 入场，三类画像；
- AI 月度决策 12 动作 + 破产 Phase B；
- AI 与玩家共用 `ProjectService`、`MarketingService`、`FinanceService`；
- 破产、恢复、延长、winddown、解散；
- 资产出售（当前仅产品）；
- C1 统一需求池、多平台多受众、平台生命周期。

## 6. 关键设计口径（容易改错）

| 主题 | 口径 |
|---|---|
| 项目预算 | 覆盖全工期全负荷人工 + QA/本地化/认证 + 10% 预备金；`remainingCap = totalCap - committed - spent` |
| runway | `cash / (corporateFixedMonthly + Σ projectMonthlyBurn)`；不预扣整个项目预算 |
| 需求池 | `audienceUnits = installBase × activity × marketShare × segmentShare`；`poolUnits = audienceUnits × purchaseIntent`；份额 `attraction^1.5`，整数最大余数法 |
| 价格 | 只进 `value`，不进 `purchaseIntent`；降价 50% 不应带来超过 2 倍销量 |
| 营销 | 营销基数剔除营销本身；上市前 90 天窗口 + 90 天淡出 |
| 破产恢复 | 现金 ≥ `max($4,000, 6×固定支出+保留项目 burn)`，且 30 天经营现金流非负 |
| 破产延长 | 90 天一次到 180 天；两次窗口正现金流、现金改善、真实降本 |
| 解散 | 360 天月末；幂等；现金 0、产品退市、合同终止、项目取消、员工离职 |
| 合同 | legacy 不改旧金额；realistic 新合同按现实费率 |
| seed | 只影响 AI 评分与内容选择，不影响现金/需求总量 |
