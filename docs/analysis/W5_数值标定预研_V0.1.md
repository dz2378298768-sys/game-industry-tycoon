## 1. 结论摘要（可直接摘录的汇报数字）

| 指标 | 数量 | 口径说明 |
|---|---|---|
| 盘点的可调数值项 | **约 302 项**（叶子数值项口径：命名键 + 向量元素 + map 条目展开） | 分布在 6 个 TUNING 配置文件 + 内容数值表；命名可调键约 155 个，详见 §2 |

| 规格/代码冲突 | **3 处**（其中 1 处 P0） | 见 §4 |

## 4. 规格/代码冲突清单（单独列出）

### 冲突 1（P0）：`cashRecoveryThresholdCents` 双入口取值相反

- `src/content/tuning.ts:179-184`：取 $4,000 = 400,000 cents，注释主张"与 L1 同线形成滞回区间（0~$4,000 不反复切换），并修订 DESIGN-OI-21 §2.4 的 $5,000 口径（引 DECISION-M3-P0-BANKRUPTCY-CLOSURE-001 §3）"。
- `src/domain/value-objects/finance-tuning.ts:20-21,116`：取 $6,000 = 600,000 cents，注释主张"严格高于 warning 线，形成真实滞后带"（FIN V0.2 §6.4 `:475`、F-06 滞后带机制 `:483-485` 同口径）。
- 影响：两条入口对**同一个字段名**给出语义相反的值——一个是"零宽度滞后 / 同线恢复"，一个是"$4k~$6k 真实滞后带"。破产恢复时机相差 $2,000 = 200,000 cents，直接影响危机状态机与 UI 横幅消失时点。
- 建议：**不得由本预研裁定**。W5 须先由主 AI 判定哪个入口为权威（考虑 `tuning.ts:5` 明令"禁止重复定义同名参数"），再统一两处值并补量级自检（CODEBUDDY.md §13.4）。登记为 §6-OPEN-3。

### 冲突 2（P1）：财务阈值在两个 TUNING 入口重复定义

- 重复字段：`budgetOverrunWarnAt`、`cashWarningThresholdCents`、`cashBankruptThresholdCents`、`cashRecoveryThresholdCents`（`tuning.ts:172-185` vs `finance-tuning.ts:114-123`）。
- `src/content/tuning.ts:5` 明确禁止重复定义同名参数；FIN V0.2 又声明 `finance-tuning.ts` 是"唯一默认值来源"（`finance-tuning.ts:7`）。
- 影响：W5 若只改一处，另一处成为隐式旧值；且两处 `cashRecoveryThresholdCents` 已实际分叉（冲突 1）。
- 建议：主 AI 裁定"单一事实源"归属（P-01 §7.1），W5 按裁定收敛，禁止双写。

### 冲突 3（P2）：技能→产能系数两套口径

- `tuning.ts:69-75 skillMultiplier`（1–5 级：0.7/0.85/1.0/1.15/1.3，基准员工技能3=1.0）。
- `project-execution-tuning.ts:53 fSkill`（0–5 级：0/0.6/0.8/1.0/1.2/1.4，技能3=1.0）。
- 两者在 L1/L2/L4/L5 均不同（0.7 vs 0.6、0.85 vs 0.8、1.15 vs 1.2、1.3 vs 1.4）。可能是"日常产能"与"项目执行产能"的不同语义，但注释未说明，且 `tuning.ts:6` 要求唯一入口。
- 建议：W5 试玩前由主 AI 确认是否刻意分域；若否，统一映射并补一条量级自检断言。
