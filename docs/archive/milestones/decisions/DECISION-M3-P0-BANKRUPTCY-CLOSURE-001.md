# 裁定：破产闭环（触发 → 恢复 → 终局边界）

- 编号：DECISION-M3-P0-BANKRUPTCY-CLOSURE-001
- 版本：v1.1（R1 修订后，R2 PASS_WITH_NOTES）
- 状态：**DECIDED**（本裁定修订 `DESIGN-M1.2-OI-21` §2.4 的恢复阈值口径）
- 范围：只解决「破产后能否活回来」，不含清算/资产变卖/游戏结束（另立 `M3-P0-2`）

## 1. 问题（事实先行）

- 触发已实现：`daily-scheduler.ts applyBankruptcyCheck`，`balance < 0` → `status='bankrupt'` + `CompanyBankrupted`。
- 命令守卫已实现：`assertCompanyActive()` 拦招聘、立项、追加预算；自查、取消、砍范围、上市保留。
- **恢复未实现**：全仓检索无 `bankrupt → active` 的写回，无 `CompanyRecovered` 事件。OI-21 §2.4 写明「M2 实现自动恢复」，M2 交付未覆盖。
- 后果：破产即永久状态。销售把现金救回正数后，玩家仍不能招聘/立项，自救弧线断裂；M3 要统计的「存活率 / 破产率 / 恢复率」在当前状态下不可定义。

## 2. 为什么必须先修（M3 前置理由）

M3 出口是「AI 公平性、现金约束、长期存活测试」。存活测试必须能区分三种状态：活着、破产但可恢复、退出市场。当前只有前两种的入口，没有出口，AI 与玩家共用规则时，任何一年的破产都是不可逆的，长期模拟必然收敛到「全灭」，这会把 M3 的失败阈值测试变成必然失败。

## 3. 裁定

**D1 恢复条件：现金 ≥ $4,000（`cashRecoveryThresholdCents = 400_000`）即恢复 `active`。**
不采用 OI-21 §2.4 的 $5,000：$4,000 正是 L1 警告线，与之同线形成 `0 ~ $4,000` 的滞回区间，避免「刚恢复又破产」的抖动。本条修订 OI-21 §2.4 数值，其余不变（自动、无需玩家宣告）。

**D2 恢复在每日调度末尾与破产判定同点执行，只对 `active`/`bankrupt` 生效，`dissolved` 不参与。**

**D3 恢复必须留痕：追加 `CompanyRecovered { companyId, day, balanceAtRecovery }`，与 `CompanyBankrupted` 对称。**
没有事件就无法解释「这家公司怎么又活了」，也无法做长期审计。

**D4 恢复不补历史：不追溯破产期间的工资/租金欠款，不重置品牌或产品；只改状态。**

**D5 终局不在本裁定：清算、资产折价出售、强制退市、玩家失败结算，作为 `M3-P0-2` 单独立项。**
理由：终局牵涉 UI（结算页）、存档（终局标记）、AI（同规则退出），必须单独评审，不能夹在恢复修复里。

## 4. 验收

| 编号 | 断言 |
|---|---|
| K01 | 余额 -$5,000 → 破产；收入 +$5,000 → 次日 `active` + `CompanyRecovered`（余额 500,000 分） |
| K02 | 余额 $1,000（0 < x < $4,000）→ 仍 `bankrupt`，无恢复事件 |
| K03 | 破产期 `hireEmployee` 返回 `FIN_COMPANY_BANKRUPT`；恢复后可招聘成功 |
| K04 | 恢复后连续推进 5 天，`CompanyRecovered` 仍只有 1 条 |

反证：移除恢复分支 → K01/K03/K04 红，K02 绿（滞回不受影响）。已实测。

## 5. R1 审查（v1.0 → v1.1）

- **P1-1 恢复阈值与 L1 线不一致**：v1.0 沿用 $5,000，与 `cashWarningThresholdCents = 400_000` 冲突，会造成「UI 已显示脱离警告、公司仍是破产」的错位。→ 改 $4,000，写滞回。
- **P1-2 只改状态、不写事件**：v1.0 未要求恢复事件，破产/恢复不对称，长期审计无法解释。→ 增 D3。
- **P1-3 终局与恢复混在一份裁定**：会把「清算/游戏结束」的争议拖住恢复修复。→ 拆出 `M3-P0-2`。
- P2：未写「恢复不补历史」→ 增 D4；未写 `dissolved` 排除 → 增 D2。

## 6. R2 审查

PASS_WITH_NOTES（P1=0）：N-1 恢复事件字段名与破产事件对齐（`balanceAtRecovery`）；N-2 禁止在恢复时顺手加品牌/现金奖励；N-3 测试不得放宽为「只要不抛就算过」。
