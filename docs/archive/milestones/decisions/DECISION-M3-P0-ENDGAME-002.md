# 裁定：终局（破产 → 解散 / 玩家失败结算）

- 编号：DECISION-M3-P0-ENDGAME-002
- 版本：v1.1（R1 修订后，R2 PASS_WITH_NOTES）
- 状态：**SUPERSEDED（破产路径由 `DECISION-M3-P0-ENDGAME-002-AMEND.md` v2.0 修订；`dissolved` 终态与玩家失败结算仍有效）**
- 上游：`DECISION-M3-P0-BANKRUPTCY-CLOSURE-001`（恢复线 $4,000）；`spec/02/01 §7`「破产不能由一次随机事件瞬间触发」
- 范围：三态转换的最后一态（`dissolved`）与玩家失败结算；不含并购、资产拍卖给 AI

## 1. 现状（事实）

- `CompanyStatus = 'active' | 'bankrupt' | 'dissolved'` 已存在，存档枚举已兼容。
- `dissolved` **没有任何写入点**：全仓无 `status='dissolved'` 的赋值；只有 `project-service.ts:336` 在读它。
- UI 已有 `dissolved` 横幅分支（`company-alerts.ts`），但永远不会被触发。
- 结论：破产可以永远挂着，没有「退出市场」这一态，M3 的破产率/存活率只能统计到一半。

## 2. 裁定

**D1 三态转换（唯一合法路径）**

```
active ──(余额 < 0)──→ bankrupt ──(余额 ≥ $4,000)──→ active
                          │
                          └──(破产满 360 天仍未恢复)──→ dissolved（终态，无出口）
```

- 破产与恢复：每日调度末尾判定（已实现）。
- 解散：**仅月末判定一次**，条件为 `bankruptSinceDay + 360 ≤ 当日` 且当日余额 `< 恢复线`。取 360 天而非 12 个自然月，避免闰年与月长差异带来的口径漂移。

**D2 解散清算（一次性、幂等、不再产生现金流）**

| 对象 | 处置 |
|---|---|
| 现金 | 按 0 结算，负余额债务不再追偿（不产生新交易） |
| 产品 | 全部 `status='retired'`，停止销售、停止退款计提；历史销售记录保留 |
| 合同 | 全部 `status='terminated'`，未结部分不再结算 |
| 项目 | 全部 `phase='CANCELLED'`（reason=`company_dissolved`） |
| 员工 | 全部标记离职，**不支付遣散费**（避免清算时再产生负现金与死循环） |
| 品牌/技术/管理 | 冻结为历史值，不重置 |

**D3 玩家失败结算**

- 触发解散当日弹出结算页：天数、现金、产品数、累计销量、峰值现金、失败原因（`bankruptcy_timeout`）。
- 两个出口：**读取最近存档**（回到破产前的存档）与**开新公司**（新 seed）。
- **不自动覆盖存档**：结算页出现时不写盘，避免把失败态写成唯一存档。

**D4 AI 同规则，无难度豁免**

- AI 公司同一套 360 天与清算规则；不得给 AI 额外现金、销量或质量加成（`spec/03/04 §3`）。
- 解散后从竞争集合移除，其市场份额回到市场池，由存活公司按既有销售公式自然竞争。
- 首发不做 AI 之间的并购与资产收购。

**D5 事件与观测**

- 新增 `CompanyDissolved { companyId, day, reason, cashAtDissolution, lifetimeDays }`。
- 长期测试指标：`存活率`、`破产率`、`恢复率`、`解散率`、`平均破产时长`、`市场集中度`。
- 破产/恢复/解散三类事件必须能在同一时间轴上追溯，不允许只有状态没有事件。

**D6 存档兼容**

- `CompanyStatus` 枚举不变，`SAVE_SCHEMA_VERSION` 不升版。
- 新增可选字段 `bankruptSinceDay?: number`：破产时写入，恢复时清除。
- 旧档若 `status='bankrupt'` 且无该字段，**读档当日回填为当日**（宽限从读档起算），不得立即解散。

## 3. 验收（编码阶段）

| 编号 | 断言 |
|---|---|
| E01 | 破产满 360 天且余额 < $4,000 → 月末变 `dissolved`，`CompanyDissolved` 1 条 |
| E02 | 破产第 359 天 → 仍 `bankrupt` |
| E03 | 破产期间恢复到 `active` → `bankruptSinceDay` 清除；再次破产重新起算 |
| E04 | 解散后：产品全 `retired`、合同全 `terminated`、项目全 `CANCELLED`、无新交易产生 |
| E05 | 解散后再次推进 30 天：状态不变、无重复事件、无现金变动 |
| E06 | 旧档 `bankrupt` 无 `bankruptSinceDay` → 读档回填当日，不立即解散 |
| E07 | 玩家结算页出现时不触发写盘（读档路径可回退） |

## 4. R1 审查（v1.0 → v1.1）

- **P1-1 宽限起算点未定义**：v1.0 只写「连续 12 个月」，没说从破产日、读档日还是月末算。→ 增 `bankruptSinceDay` 与旧档回填规则（D6）。
- **P1-2 清算只写「状态改 dissolved」**：会留下仍在结算的合同、仍在销售的 retired 之外的产品、仍在计薪的员工，产生「死了还在花钱」的幽灵。→ 增 D2 处置表。
- **P1-3 玩家失败后写盘风险**：若结算页触发即时保存，失败态会覆盖唯一存档，读档出口失效。→ 增 D3「不写盘」与 E07。
- P2：解散事件缺失 → D5；AI 难度豁免未写死 → D4；解散判定时点未写 → D1 月末。

## 5. R2 审查

PASS_WITH_NOTES（P1=0）：
- N-1 解散判定必须在所有结算（工资/租金/合同/退款）之后，避免当天先解散又产生交易。
- N-2 `lifetimeDays = dissolvedDay - foundingDay`，不得用存档序号。
- N-3 解散后禁止任何「复活」命令，包括读档以外的 UI 按钮。
