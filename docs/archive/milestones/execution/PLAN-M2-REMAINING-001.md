## 2. M2-D 具体细节（设计稿开工即按此填 16 项）

### 2.1 生命周期推进（纯时间函数）

| 阶段 | 进入条件（上市后天数） | 备注 |
|---|---|---|
| `launch` | 0 ≤ d < 21 | 上市初期 |
| `growth` | 21 ≤ d < 90 | 营销响应系数 100k（TUNING 现值） |
| `mature` | 90 ≤ d < 180 | 系数 200k |
| `decline` | 180 ≤ d < 365 | 系数 300k（边际递减） |
| `long_tail` | 365 ≤ d | 系数 300k，销量按基础衰减 |
| `retired` | 手动退市，或连续 **90 天**日销量为 0 | 退市后不再产生销售记录 |

- 阈值全部进 `TUNING.product.lifecycle`（新键），默认值同上；**不读日历**，用 `dayIndex - product.launchDay`。
- 阶段推进只改 `Product.lifecycleStage` 与 `version/updatedAt`，追加 `ProductLifecycleChanged` 事件（payload: `productId, from, to, day`）。
- 幂等：同一 `(productId, day)` 至多一条事件；阶段只升不降（`retired` 为终态）。

### 2.2 定价

- `pricePerUnitCents`：正整数、≥1 美分；变更只影响**变更日之后**的销售日。
- 历史保护：`SalesRecord.unitPriceAtSaleCents` 一经写入不得被改价逻辑触碰（测试须断言"改价后旧记录逐字段不变"）。
- 改价冷却：同一产品 **7 天**内至多改价 1 次（错误码 `PRICE_COOLDOWN`）。
- 非法值：非整数 / ≤0 / 超过上市价 5 倍 → `PRICE_INVALID_AMOUNT`。

### 2.3 折扣

- 冷静期：`dayIndex - launchDay < 14` 时禁止打折 → `PRICE_DISCOUNT_COOLDOWN`。
- 折扣率 `rate ∈ [5%, 50%]`，越界 → `PRICE_DISCOUNT_RANGE`。
- 折后价 = `round(pricePerUnitCents × (1 - rate))`，最低不低于上市价的 50%。
- 折扣与退款窗口同值（14 天）是**有意的**：两者共同封住"低价刷量再退款"的套利路径，这条要在设计稿里写清理由，避免后人"优化"掉。

### 2.4 退市

- 手动退市：`phase` 无关，产品 `status='active'` 才可退市；退市后 `lifecycleStage='retired'`，不再生成销售记录与退款批次。
- 自动退市：连续 90 天日销量 0 由调度器判定；需日销量历史——**复用 `salesByPeriod`**，不新增字段。

### 2.5 错误码（6 个，全部要测试）

`PRICE_INVALID_AMOUNT` / `PRICE_COOLDOWN` / `PRICE_DISCOUNT_COOLDOWN` / `PRICE_DISCOUNT_RANGE` / `LIFECYCLE_IMMUTABLE`（退市产品改价）/ `LIFECYCLE_NOT_ELAPSED`（未到阈值强推阶段）。

### 2.6 用例草案（D01–D36）

阶段推进 8 条（含边界 20/21、89/90、364/365、事件幂等、只升不降）；定价 8 条（正/负/冷却/历史零改写/倍数上限）；折扣 8 条（冷静期 13/14、5%/50% 边界、折后价下限、四舍五入）；退市 6 条（手动/自动 90 天/退市后零销售/改价拒绝/退款不受影响）；集成与存档 6 条（调度推进、存档往返、v1 旧档缺字段回退）。

## 3. E / F / G 的细节约束（先锁，防后期扯皮）

- **E**：`schemaVersion 1→2`；`canMigrate(1,2)=true`；迁移函数纯函数化（入参旧档，出参新档）；补 `pricePerUnitCents = launchPriceCents`；**不重算** `salesByPeriod`；失败返回错误码且不写存储；保留 `save:v1-backup:<seed>` 键；迁移后 `parseSave` 必过。
- **F**：营销渠道每渠道有"预算 → 认知度"的边际曲线，系数取 `marketingResponseScaleCents[stage]`（已存在，直接复用，不新建表）；合同只能引用已上市产品；分成合同按净收入比例逐日入账，里程碑按达成日一次性入账；全部走 `FinanceService`，幂等键 `marketing:<productId>:<day>` / `contract:<contractId>:<milestone>`。
- **G**：只读服务层输出；净收入展示规则沿用 A 批口径（不含未发生退款）；新增 3 个下钻面板 + 约 120 个 i18n 键；不新增业务状态。
