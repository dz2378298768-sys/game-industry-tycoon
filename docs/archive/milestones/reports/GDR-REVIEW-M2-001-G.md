# GDR-REVIEW-M2-001-G：UI/i18n 规格 R1

| 属性 | 内容 |
|---|---|
| 对象 | `../../../design/milestone-specs/DESIGN-M2-001-G-UI.md` v1.0 |
| 结论 | **REVISE_REQUIRED** —— P1×3、P2×2 |
| 日期 | 2026-11-20 |

## 1. P1

**P1-1 净收入口径没定义清楚（数值）**
§4 只写"`Σ netSalesRevenueCents − Σ posted 退款`"，但没写：
- 退款金额用 `refundAmountCents` 还是 `refundedUnits × unitPriceAtSaleCents`（两者可能不等，尤其折扣期）；
- pending 批次不计入，但"预估退款件数"是否要在 UI 上显形（不折金额）；
- 跨产品/跨市场聚合时是否按日截断。
实现者会各写一套，同一产品两个页面能差出钱。

**改法**：写死"退款一律取 `refundAmountCents`（实际金额，不做二次换算）"；pending 只在退款表出现、不计净收入；预估件数单独列，标"预估、未发生"；聚合按 `dayIndex` 分组，不分市场截断。

**P1-2 下钻数据结构没给 join 规则（体验/正确性）**
退款批次挂在 `world.refundBatches`，销售记录挂在 `product.salesByPeriod`，两者只有 `salesRecordId` 关联。规格没说 join 失败怎么办（老档/被删记录），也没说详情页数据来源是 store 快照还是 `gw.world` 实时。

**改法**：join 键 `salesRecordId`；查不到时展示 `—` 并在该行标"记录缺失"；详情页一律读 store 快照（`refresh()` 后），不直接摸 `GameWorld`，避免 UI 越权。

**P1-3 错误码没有全量双语映射（i18n）**
只说"按错误码展示双语"，但 Pricing 6 码 + 营销 3 码 + 合同 5 码共 14 个新码，`ERROR_I18N` 现有表没有。按当前 `localizeError` 逻辑，缺键会回退到英文/中文后端文案，出现"PRICE_COOLDOWN"这种原始码——正是 G 要消灭的东西。

**改法**：§7 明确 14 个码逐一入 `ERROR_I18N`，并补 G13 断言每个码都能 `t()` 出非原始码文案。

## 2. P2

| 编号 | 问题 | 改法 |
|---|---|---|
| P2-1 | 价格按钮未定义禁用态（未定价/退市） | 未定价只允许「定价」，退市后三按钮全禁 |
| P2-2 | 营销预算输入未定义单位（元/分） | 输入按"元/天"，提交转分，避免玩家输入 10000 变成 $10,000 |

## 3. 八维

可行性 通过｜游戏性 通过（终于能看到销量/退款）｜完整性 **不通过**（P1-1/P1-2）｜一致性 **不通过**（P1-3 会露原始码）｜数值 待补｜体验闭环 通过｜异常 待补（join 缺失）｜可验收 待补（错误码用例）

## 4. 结论

P1×3 + P2×2，v1.1 修订后进 R2。
