# R1 审查：DESIGN-M2-001-I（v1.0）

- 结论：**REVISE_REQUIRED**（P1×2 / P2×2）
- 审查对象：`../../../design/milestone-specs/DESIGN-M2-001-I-NEGATIVE-BALANCE.md` v1.0
- 审查方式：对设计基线逐条核对生产代码，不采信描述

## P1（阻断）

**P1-1 「只加 allowNegativeBalance」会把缺陷从崩溃改成隐性透支，且没有可见出口。**
v1.0 只写「销售入账允许负余额」，未处理日历跳日、未处理 UI 异常。若只改一行，崩溃消失但负余额无上限、无提示，玩家仍可能永远还不清且不知道发生了什么。**要求**：必须同时给出（a）日程边界不跳日；（b）UI 必须把失败转成可见提示；（c）明确负余额的现有语义（禁招聘/禁建项目）与不做的部分（破产终局另立议题）。

**P1-2 批量选项若默认放开，会静默改变所有 `bulkPostTransactions` 调用点语义。**
现有唯一调用点是销售，但 API 一旦把 `allowNegativeBalance` 默认设为 true，未来任何批量支出都会绕过现金检查。**要求**：选项必须**默认关闭**、显式传参，并加 I02 用例锁住「不传即拒绝且原子回滚」。

## P2（应改）

- **P2-1 缺少「日历跳日」的回归断言。** 只测「不抛」不足以证明世界与日期对齐，必须断言失败后 `currentDayIndex === startDay`。
- **P2-2 未声明残余风险。** `executeDay` 抛错前可能已写入账务，回退日历后重试依赖幂等键；若不写明，后续 agent 会误以为本批做到了整日事务化。

## 处置

全部接受。v1.0 → v1.1：新增 D2（日历回退 + `GameCalendar.rewindTo`）、D3（store 兜底）、D4（破产另立）、D5（残余风险显式声明）、I02/I04/I05 用例。转 R2。
