## 0. 已知范围限制（**不得计为缺陷**）

主持人在开场已告知（`../execution/PLAYTEST-KICKOFF-M1.1.md` §1.5），记录与汇总时按以下口径处理，避免把"版本还没做"记成"做坏了"：

| 现象 | 性质 | 记录方式 |
|---|---|---|
| 游戏上市后没有任何收入，现金只降不升 | M1.1 范围外（销售/退款/抽成属 M2，`OI-24`） | 记为"已知"，不算卡点；但**玩家对此的反应要记**（是否因此放弃？是否误以为 bug？） |
| 公司现金转负仍能继续经营 | 已知缺口（无破产规则，`OI-21`） | 记为"已知"；若玩家因此失去目标感，记为**体验问题**（有价值） |
| 默认 $30,000 预算约第 130 天耗尽需追加 | 设计上要观察的决策点（`OI-20`） | **必须记录**：玩家追加多少、是否理解"追加后要手动恢复"、是否干脆取消 |
| 分配团队后进度不涨（需先"推进阶段"） | 阶段规则正确、提示文案误导（`OI-19`） | 若玩家卡住超过 3 分钟，记为**卡点**（说明文案确实误导） |
| 界面只有中文/英文两种，无音效、无存档槽位管理 | M1.1 范围外 | 不计 |

> 判定原则：**"版本没有的功能"不算缺陷；"版本有的功能让人困惑或挫败"必须记为体验问题。** 两者的区别写在每条记录里。
