## G-1 长任务分段提交与中断恢复

任何**预计执行超过 30 分钟**的编码任务，强制执行：

1. **分段 commit**：每完成一个可独立验证的块（实体层/状态机/服务层/测试批次等）即本地 commit，message 标注 `(part N)`。禁止为省事攒单个大 commit 跨长时间运行窗口。
2. **派发时写明恢复流程**：任务包必须含一行"若运行中断：先 `git log --oneline` 与 `git diff --stat` 复盘已改内容，再跑定向测试确认基线，从断点继续，不得凭记忆重写已完成部分"。
3. **主 AI 处置**：发现子代理超预期静默（无 commit、无报告）超过其正常节奏 2 倍时间，主动查其工作区状态并断点唤醒，不得无限等待。

背景事故：2026-11-22 晚 CODE-03-REWORK 因执行环境休眠中断，在途 7 文件改动停摆 11 小时（万幸未提交的改动保留在工作区，经断点续跑挽回）。

## G-2 并行窗口内的红相归因协议

同一仓库内有多个 Agent 并行写码时，**任何一方跑全量 vitest/typecheck 都可能被他人未提交的在途改动染红**。为此：

1. **派发隔离纪律（主 AI 必下）**：每个并行 Agent 只 `git add` 自己修改的文件，明令禁止 `git add -A` / `git add .` / `git commit -a`；commit 前须 `git status` 确认暂存区只含本人文件；明列他人占用的禁区文件。
2. **红相归因表（审核 Agent 必附）**：并行窗口内出具的审核报告，若全量命令存在非绿结果，必须附归因表——每条红列出：文件归属（被审 commit / 某并行任务在途 / 真回归）、判定判据。无归因表的红相结论一律不采信。
3. **降级验证路径（合法）**：改动面 ≤ 10 文件的小批任务，允许以"定向套件全绿 + 红相复现 + `--stat` 涉及面比对"替代全量复跑，但报告须如实标注降级路径；全量四命令为里程碑节点与最终验收的强制项。
4. **隔离验证技巧**：需要干净基线时，用 `git worktree add /tmp/<name> <被审commit>`（钉住 commit，不受并行 HEAD 前移影响）+ 符号链接 node_modules，在隔离树复跑；用毕清理。

背景事故：2026-11-23 CODE-08 与 CODE-03-REWORK 并行，双方全量命令均被对方在途改动染红（27 条 typecheck 报错 + 18 个测试失败），靠临场人工归因解决；R3B 复审期间又遇 CODE-06 提交导致 HEAD 前移，以钉住 commit 的隔离 worktree 解决。

## G-3 派发环境须知（附录 A 补充项）

向子代理派发涉及本地命令执行的任务时，指令中必须包含以下环境事实，避免重复空转：

1. **每次命令调用的工作目录可能重置**：`cd` 前缀可能不生效。涉及仓库操作统一用免 cd 写法：`git -C <仓库绝对路径> ...`、`npm --prefix <仓库绝对路径> run ...`。
2. **管道退出码不可信**：`cmd | tail` 的退出码是 tail 的。真实退出码必须用 `cmd > /tmp/x.log 2>&1; echo EXIT:$?` 记录（与规范 §13.12 反证判据配套）。
3. **worktree 首次使用**：新 worktree 无 node_modules，先符号链接主 worktree 的 node_modules 再跑测试。

背景事故：2026-11-23 主 AI 与 R3B 复审 Agent 各自在同一坑上空转 4~5 次调用（在 /workspace 找 package.json 失败，EXIT 254 假红）。
