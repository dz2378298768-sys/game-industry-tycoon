# Game Industry Tycoon：总体设计基线 V3.0

**版本日期：2026-11-21**  
**文档性质：项目长期产品设计权威基线**  
**适用对象：Owner、主设计负责人、设计代理、设计审核代理、编码代理、编码审核代理**

## 本版本的目的

V3.0 不是对 V2.1.7 已完成工程内容的包装，也不是要求当前代码推倒重做。它重新定义项目最终要成为怎样的游戏，并据此规划系统边界、玩法结构和开发顺序。

**设计目标优先于既有实现。** 已有代码和测试是可复用资产，不是限制产品方向的设计宪法。后续应先判断现有实现是否符合 V3.0，再决定保留、适配、重构或废弃。不得为了保护沉没成本而牺牲最终游戏品质；也不得为了追求理想设计而无理由重写已正确工作的底层基础设施。

## 权威文件

1. `00_项目总纲/01_总体设计基线.md`：项目定位、世界规则、核心体验、设计原则和系统边界。
2. `01_系统总体规划/01_系统地图与领域规则.md`：系统清单、职责、输入输出、依赖、玩家决策与自动化边界。
3. `02_版本路线图/01_开发阶段与验收门槛.md`：从核心可玩闭环到完整产业世界的阶段计划。
4. `03_决策基线/01_已确认设计决策与待验证事项.md`：已确认方向、设计负责人默认裁定、待验证事项。

## 与 V2.1.7 的关系

- V2.1.7 是既有工程规格与历史实现基线，保留作为代码、接口、测试和迁移参考。
- 本 V3.0 取代 V2.1.7 中与长期产品定位、首发范围、系统优先级和未来路线有关的旧设计口径。
- V2.1.7 中的确定性、唯一写入口、存档兼容、领域层隔离、可追溯账本等工程约束，若经审查仍服务于 V3.0，则继续保留。
- 旧规格与本版冲突时，以 V3.0 的产品设计方向为准；具体工程迁移必须另出影响分析和实施任务，不允许直接把愿景文本当成编码接口。
- 任何系统进入编码前，必须形成该系统的可执行规格：状态、实体、规则、公式、边界、失败行为、玩家操作、反馈、日志、性能预算和验收用例。

## 状态标记

- `CONFIRMED`：用户已明确确认的方向。
- `DESIGN_BASELINE`：总设计师基于整体目标作出的默认设计裁定，后续可经证据推翻。
- `TUNING`：结构已定，参数需要模拟校准。
- `VERIFY`：历史事实或外部数据需要来源核验。
- `OPEN`：确实需要后续专项设计，暂不伪装成已定。
- `DEFERRED`：明确后置，不进入当前阶段。
- `REJECTED`：当前规划明确不做。

## 总设计师工作原则

本项目不是系统数量竞赛。任何新增机制必须通过：必要性、游戏性、重复性、扩展性、实现成本、运行成本六项审查。模拟可以深，玩家操作必须有层次；自动化必须可解释、可干预、可追溯；真实细节只有在创造有价值的机会、约束或后果时才进入模拟。
