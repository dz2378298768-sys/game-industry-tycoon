## 3. C7 默认配置走上市验证（重点，实测数据）

**验证口径**：`createGameWorld(42)`（生产内容 provider，AI 竞争关闭）→ `createCompany`（默认 $120,000）→ 4 学科各 1 人按 `defaultStartingSalaryCents` × 城市系数招聘（旧金山 1.4 → $1,820/人/月）→ 立项推进至 PRODUCTION、全员 100% 分配 → 逐日推进至 Day 200 → 调用 `launchProject`。

### 路径 A：预算帽 $20,000 = 2,000,000 cents（ADJ-12 S4-2 `minProjectBudgetCents` 锚点）

| Day | 现金（cents） | 现金（USD） | 公司 status | 项目 phase | 预算耗尽 / 暂停天数 |
|---|---|---|---|---|---|
| 0 | 10,980,800 | $109,808.00 | active | PRODUCTION | false / 0 |
| 30 | 9,751,600 | $97,516.00 | active | PRODUCTION | false / 0 |
| 60 | 8,522,400 | $85,224.00 | active | READY_TO_LAUNCH | **true / 2** |
| 200 | 4,370,000 | $43,700.00 | active | **CANCELLED** | false / 0 |

- 首次 READY Day **48**；首次预算耗尽 Day **58**；暂停 60 天超时自动取消 Day **118**（`applyPauseTimeout`，`PAUSE_TIMEOUT_DAYS=60`）
- `launchProject@Day200` → `success=false, errorCode=PRJ_NOT_READY`
- **公司现金全程为正（未耗尽），最低 $43,700，远高于 $6,000 恢复线与 $4,000 警告线**

### 路径 B：UI 向导默认 HRB 0.45 × $20,000 容量 = $9,000 = 900,000 cents（真实玩家默认路径）

| Day | 现金（cents） | 现金（USD） | 项目 phase | 预算耗尽 / 暂停天数 |
|---|---|---|---|---|
| 0 | 10,980,800 | $109,808.00 | PRODUCTION | false / 0 |
| 30 | 9,751,600 | $97,516.00 | READY_TO_LAUNCH | **true / 0** |
| 60 | 8,522,400 | $85,224.00 | READY_TO_LAUNCH | **true / 30** |
| 200 | 3,860,400 | $38,604.00 | **CANCELLED** | false / 0 |

- 首次 READY Day **23**；首次预算耗尽 Day **30**；暂停超时取消 Day **90**
- `launchProject@Day200` → `success=false, errorCode=PRJ_NOT_READY`

### 结论

> **默认配置走不到上市（不能）**。与 OI-20 历史问题（公司现金 Day130 耗尽、上市需 $48k）不同：当前默认起始资金已上调到 $120,000，**公司现金不会耗尽**；失败根因是**项目预算帽相对 200 天计划上市周期过小**——项目在 Day 48/23 即达 READY_TO_LAUNCH，但 Day 58/30 预算耗尽进入暂停，60 天暂停超时在 Day 118/90 自动取消，早于 Day 200 计划上市日，导致上市命令被 `PRJ_NOT_READY` 拒绝。

**处置**：严格按 ADJ-19 C7「不擅自改 ADJ 锚定的预算数值」，本任务**未改任何预算/周期/薪资数值**；登记 **P1 OPEN-W5-C7-01** 上报主 AI 裁定（见 §5）。

## 4. C3 派生可行性核查与 C8 占位处置

### C3 定价三档 / 营销预算档（保持 `NUMERIC_PENDING_P2`）

核查结论——**无权威档位映射，禁止臆造**：

1. `referencePriceCents(genre, platform, segment)`（`c1-content.ts:212`）返回单一组合的权威参考价，既有调用链（`demand-pool.ts:164` 的 `value=clamp(ref/price,0.5,1.5)`）把它当价格比值输入，**代码中不存在** low/medium/high 三档到该参考价的权威换算；
2. ADJ-12 S9-1 仅写「引用 p0 §4.3 区间取整，数值 TUNING」，但规格正文未给出三档区间数值；ADJ-16 R-5 明令「三档名称固定，具体数值 TUNING 占位标 `NUMERIC_PENDING_P2`，UI 与规格正文均不得臆造终值」；
3. `basePurchaseConversion=0.05` 是购买转化率（比例），不是价格倍率，无法据此把参考价换算成三档价格；
4. 交付页立项的 `audienceSegmentIds` / `targetPlatformIds` 可能为空，缺具体组合时 ADJ-19 C3 明示保持占位并登记 OPEN；
5. 营销预算档 × 单渠道（S9-2）在既有 TUNING 中**无** `dailyBudgetCents` 档位字段；`marketingResponseScaleCents`（launch $500 / growth $1,000 / …）是生命周期阶段响应尺度，语义不符，不得挪用。

处置：6 档全部保持 `priceCents/dailyBudgetCents = null` + `status='NUMERIC_PENDING_P2'`，UI fail-closed 显示「数值待标定」；数据层与 UI 层均有断言锁定。登记 **OPEN-W5-C3-01**。

### C8 招聘/薪资（锚点保持，量级自检通过）

- `recruitFeeMonths=1`（ADJ-12 S5-3）保持；
- `defaultStartingSalaryCents=$1,300=130,000 cents/月` × 城市系数区间 0.6~1.45；最高城市（纽约 1.45）月薪 = 188,500 cents = $1,885；
- `severancePerEmployeeCents=$5,000=500,000 cents/人`（FIN §8.4）；188,500 < 500,000，**不倒挂**（自检通过）；
- 无硬占位，无新增 OPEN。
