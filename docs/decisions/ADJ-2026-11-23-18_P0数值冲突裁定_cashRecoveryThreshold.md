# ADJ-2026-11-23-18：P0 数值冲突裁定——cashRecoveryThresholdCents 单一事实源

- **触发**：§11.7 旁路任务《W5 数值标定预研 V0.1》§4 冲突 1（P0）
- **状态**：**DECIDED**（结构裁定；数值本身仍为 W5 待校准候选）

## 1. 冲突事实（已实证）

| 入口 | 当前值 | 依据 | 版本 |
|---|---|---|---|
| `src/content/tuning.ts:184` | 400,000 cents = **$4,000** | `DECISION-M3-P0-BANKRUPTCY-CLOSURE-001` D1（v1.1，修订 OI-21 §2.4 的 $5,000 为 $4,000，与警告线同线零宽度滞回） | 早期 M3 裁定 |

## 2. 裁定依据（权威链）

1. **FIN V0.2 是财务唯一权威**：ADJ-2026-11-22-04 明确「FIN V0.2 已过完整审核链并验收，是财务唯一权威；人才规格不应反向定义财务规则」。V0.2 §6.4 将恢复线由 V0.1 的 $4,000（同线）改为 $6,000（严格高于警告线），是 F-06 滞后带机制的正式整改。
2. **新旧关系**：$4,000 来自 M3 早期裁定（v1.1），FIN V0.2 是后出的、经独立审核的规格修订；按「新审核规格 > 旧裁定」的优先级，旧值属跨版本继承遗漏，不是并行有效口径。
3. **数值仍待校准**：FIN V0.2 §6.4 自我标注所有阈值为「默认候选值（TUNING，待校准），不构成终值（F-12）」；因此本裁定只定结构与权威入口，不宣称 $6,000 是最终数值——最终值由 W5 数值标定 + 试玩验证确定。

## 3. 裁定内容

1. **权威值**：`cashRecoveryThresholdCents` 以 **$6,000 = 600,000 cents** 为当前实现口径，语义为「严格高于警告线 $4,000 的真实滞后带」（FIN V0.2 §6.4 / F-06）。
2. **单一事实源**：以 `src/domain/value-objects/finance-tuning.ts` 为财务阈值的唯一默认值来源（FIN V0.2 声明）；`src/content/tuning.ts` 中重复的四个财务字段（`budgetOverrunWarnAt`、`cashWarningThresholdCents`、`cashBankruptThresholdCents`、`cashRecoveryThresholdCents`）须收敛——改为从 finance-tuning 派生或删除重复定义，禁止双写。
3. **实施时机**：本裁定不并入 07B（已收口推送）；列入 **W5 数值专项标定任务包的前置整改项**，由 W5 编码子代理统一两处入口，并补量级自检（CODEBUDDY.md §13.4：$6,000 = 600,000 cents，严格大于 $4,000 = 400,000 cents，量级自检通过）与对应测试断言。
4. **历史裁定处置**：`DECISION-M3-P0-BANKRUPTCY-CLOSURE-001` D1 的 $4,000 口径**不再作为财务阈值权威**，但保留其历史裁定效力（破产恢复机制本身仍有效）；在 W5 定值后如需最终确定阈值，以新裁定覆盖，不回改历史文档正文，仅加状态批注。
5. **禁止事项**：不得在 07B 或本裁定中直接改代码；不得在 W5 之前的任何批次「顺手」统一该值（避免与在途任务双写冲突）。
