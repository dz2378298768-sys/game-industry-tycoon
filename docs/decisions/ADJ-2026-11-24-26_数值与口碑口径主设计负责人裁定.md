## 二、定价三档裁定（SUP-02 / 解除披露 3）

| 项 | 裁定 | 结论 | 理由 |
|---|---|---|---|
| A1 | 定价 factor 三元组 | ✅ **采纳 0.75 / 1.00 / 1.25** | 对齐既有 AI 定价锚点（质量 0/50/100 分的 factor，`ai-planner.ts:285`）；落在权威夹逼带 `[0.5,1.5]×ref` 内；档距 ±25% 玩家可感知（DP-2），比边界方案 0.5/1.5 温和，避免饱和区"改价无感" |
| A2 | 结构 | ✅ **动态倍率（相对 `referencePriceCents`）** | 固定绝对 cents 与 432 行参考价表冲突（arcade ~$0.14 vs home_console ~$45.99）；动态倍率跨组合自洽 |
| A3 | 空组合兜底 | ✅ **默认参考价 2,999 cents（$29.99）派生 + UI 明示"按默认参考价估算"** | 解决玩家不选受众/平台时无法定价→零收入（PT-OBS-1）；这是 SUP-05 零收入引导的数值基础 |
| A6 | 是否接线内核 | ✅ **必须接线到 `setProductPrice`** | 只改展示不改内核 = 假反馈，违反 DP-2/DP-3；当前 `deliver.tsx:47-51` 仅 `useState` 展示，必须消除 |

**定价公式（REC-02 实现口径）**：
```
priceCents(tier) = round(referencePriceCents(genre, platform, segment) × factor[tier])
  空组合 → referencePriceCents = 2,999 cents，UI 明示"按默认参考价估算"
  factor: low=0.75 / medium=1.00 / high=1.25
```
默认参考价下：low $22.49 / medium $29.99 / high $37.49。

## 五、补充裁定（材料 NOT_VERIFIED 的处置）

1. **价格弹性失效（`basePriceCents = priceCents`，材料 NOT_VERIFIED #2）**：**保持现状，不在 REC-02 改动**。理由：价格已通过需求池 `value = clamp(ref/price, 0.5, 1.5)` 单一路径真实影响销量与收入；若把 `basePriceCents` 改为 `referencePriceCents`，价格会经需求池 + 销售管线 log 弹性**双重生效**，动摇已在 PATH-A 验证的销量基线，风险高且当前不阻断可玩性。登记为开放项 OPEN-PRICE-DUAL-PATH，**转 REC-05 数值专项**：由系统模拟与数值平衡 Agent 用多 seed 模拟判定"有意中性化"还是"实现遗漏"，再决定是否启用第二路径。禁止在 REC-02 顺手改销量公式。

2. **六个档位标签词条缺失（NOT_VERIFIED #3）**：`deliver.pricing.low/medium/high`、`deliver.marketing.low/medium/high` 在中英词典均缺。REC-02 须**补齐这 6 个 key 的中英双语**（属于本任务 UI 落地必需），其余 i18n 残留中文仍归 SUP-08（REC-09）治理，两者不冲突。

3. **经济平衡（NOT_VERIFIED #1）**：本裁定不构成经济平衡结论。REC-02 只验证"默认可达 + 至少两种策略产生可解释差异"，不宣称三档净收入区间。是否启动 V2.2 §5.2-C 系统模拟与数值平衡 Agent 做平衡专项，由主设计负责人视 REC-02 实测结果决定。

4. **默认预算帽校准（B-01，REC-02 核心）**：裁定边界——默认开局（$120,000 起始 + 默认 4 人招聘 + HRB 0.45）必须能在 200 天周期内**自然走到上市成功**；校准对象为默认预算帽 / HRB / 工期 / 招聘成本，按**最小改动**原则；保留 PATH-A 充足预算作对照，但不得只靠 PATH-A。**具体数值由数值平衡 Agent 跑扫描后提出、编码 Agent 实现、独立审核验证，主 AI 不在此拍死数字**（避免重演 C3 臆造）。当前 $9,000 帽 Day90 耗尽是明确的失败锚点，必须消除。
