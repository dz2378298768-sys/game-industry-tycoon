## 规则

1. 公司进入 `bankrupt` 时，对该公司所有非终态项目按本规则处理。普通项目当日暂停，`pauseReason='bankruptcy'`、`pausedDays=0`；计时从次日开始。
2. 每家公司至多保留一个例外项目。资格必须同时满足：破产判定当日 `phase='PRODUCTION'`；design、programming、art 三项生产工作完成度均至少 80%；剩余成本不超过阈值。
3. 多个项目同时满足资格时，按 `project.id` 升序取首个，保证结果确定。
4. 剩余成本定义为 `max(0, budgetTotalCapCents - budgetSpentCents - budgetCommittedCents)`。破产现金阈值定义为 `max(0, bankruptcyCashCents) * 10%`。因此现金为负时阈值为 0，只有剩余成本为 0 才能例外保留；不对负现金取绝对值。
5. 被保留项目不暂停、不累计破产暂停天数，并打 `bankruptcy_retained` 标记；预算耗尽标记不得阻止该项目继续完成。破产期间只有带此标记的项目可以上市。
6. 普通项目保持暂停，破产暂停累计满 30 天当日取消，原因 `restructuring`，清空团队分配并派发系统 `ProjectCancelled` 事件，`reasonCode='bankruptcy_timeout'`。第 30 天计为触发日。
7. 公司恢复经营后清除项目的 `bankruptcy_retained` 标记；破产之外现有手动/预算暂停规则保持不变。

## 验收

- Day 0 破产可资格判定；同日未累计暂停天数，Day+29 未取消、Day+30 取消。
- 合格候选最多保留一个且稳定选择；负现金配正剩余成本不能满足例外。
- 取消时项目进入终态、团队释放、事件与原因码一致。
- 普通破产项目不能上市；唯一保留项目可上市；dissolved 仍禁止上市。
- 存档 schema 接受 `pauseReason='bankruptcy'`，旧值继续兼容。
- 定向测试、typecheck、lint 通过；随后完成 REC-04 要求的电脑端 UI 交付/上市/销售收入体验验收，未完成前 REC-04/SUP-01 不得关闭。
