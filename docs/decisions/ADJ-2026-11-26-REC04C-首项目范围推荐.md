## 规则

1. 首个玩家 ExecutionProject 的向导默认采用 `scopePolicy=recommended`：一个核心玩法模块和一个章节内容模块，二者强度均为 1。
2. 玩家可切换到 `scopePolicy=custom`，主动追加最多两个支援模块，并使用完整强度 3；该选择必须在锁定快照前明确可见。
3. 推荐范围不改变通用 WorkPackage 公式、起始资金、薪资、HRB、预算承诺、AvailableCash 或破产规则；它只改变首项目向导传入的模块快照。
4. 预算确认页必须同时显示预算承诺额、承诺后可用现金和当前现金跑道。承诺后可用现金是当前可用现金减预算承诺额；现金跑道沿用财务单一来源，不在 UI 重新估算。
5. 推荐范围不是保证成功。招聘承诺、技能选择和现金变化仍是玩家策略；低技能或过度招聘导致失败时必须保留真实原因。
6. 候选池“应聘截止日”只约束玩家确认招聘的日期。确认后进入 `PendingHire` 的候选已被预留，到岗日允许晚于应聘截止日；不得因候选池刷新/过期再次拒绝已确认的到岗。确认当天仍必须满足未过期、容量和财务守卫。

## 验收

- 同一 seed 下首项目默认请求包含 core + episodes，强度为 1，且不包含 support。
- 切换 custom 后可加入支援模块，快照输入变更且预览工作量变化。
- 页面显示 scope policy、预算承诺、承诺后可用现金和当前跑道；不隐藏负值。
- 历史项目和非首项目路径不被该向导默认值改写。
- Day 60/90 延后招聘策略中，候选到岗日晚于应聘截止日时，确认招聘仍可进入待到岗并在到岗日生效；确认日已过期的候选仍被拒绝。
