## 0. 文档立场与阅读方式

1. 本文是 **D-01 的前置输入包**，不是 D-04 完整规格。它把 D-01 标为 `OPEN` 的三类前置依赖（受众标签词表粒度 OPEN-O6、类型库种子、平台存在性）收敛为 P1 最小可用数据契约。
2. **与 D-01 冲突时以 D-01 为准**。本文只定义"被 D-01 引用但 D-01 未定义"的数据对象，不修改 D-01 的任何实体字段（尤其不向 `PositioningProfile` / `DesignVersionSnapshot` 增字段）。
3. D-01 对这三个对象的定位：
   - `SegmentTag`：D-01 §8.1 标为"前置输入、只读词表、仅供玩家宣称选择、不回写蓝图"（OPEN-O6 粒度属 D-04）。
   - `GameplayArchetype`：D-01 §4.13 已定义完整字段与生命周期，本文只提供**种子数据**（字段与 §4.13 严格一致，不新增/改名）。
   - `Platform`：D-01 §8.1 要求"平台列表 + 技术标准"，§4.8 要求 `platform.techStandards: list<TechGate>`；本文只提供**存在性与输入能力**，不提供平台经营。
4. 所有未定口径标 `OPEN`/`TUNING`，不得写成确定规则。

## 3. 实体与字段

> 约定：字段类型 `id / string / enum / bool / int / decimal / ref / list / map`；ID 均稳定不可变。所有实体的具体取值见 §6。

### 3.1 `SegmentTag`（受众标签词表条目）

D-01 中 `PositioningProfile.targetSegmentClaims: list<ref SegmentTag>, 1–3`（§4.3）与本包 `ModuleTemplate.audienceAffinity: map<SegmentTag, weight>`、`Option.audienceAffinityDelta: map<SegmentTag, weight>`（§4.6/§4.10）的**键值来源**。本包只定义词条，不定义权重。

| 字段 | 类型 | 含义 | 约束 / 状态 |
|---|---|---|---|
| `tagId` | id | 标签唯一标识，**稳定不可变** | 不可变；deprecated 不物理删除（§4.3） |
| `code` | enum | 稳定枚举码（如 `hardcore`） | 不可变；与 `tagId` 一一对应 |
| `displayName` | string(1–16) | 玩家可见名称 | 可本地化（P4）；P1 中文 |
| `dimension` | enum{demographic, preference} | 标签维度：人口/年龄型 vs 偏好/心理型 | DESIGN_BASELINE；用于避免"受众"与"类型"混淆 |
| `granularity` | enum{broad, niche} | **粒度**：广谱 vs 细分 | DESIGN_BASELINE；P1 以 broad 为主，niche 保留少量（§6.1） |
| `regionScope` | {kind: enum{global, regional}, regionIds: list<ref Region>} | **地区适用范围** | P1 种子 `kind=global`；regional 明细 `OPEN`→P4/D-04 完整（§6.1） |
| `eraRange` | {fromYear, toYear: int} | 词条在世界中可用的年份区间 | D-01 仅"越界提示"（软，`E-ERA`）；具体年份 `TUNING` |
| `state` | enum{active, deprecated} | 是否可被新版本选择 | 见 §4.3 |
| `source` | enum{seed_data, game_master} | 来源 | 本包 P1 全为 `seed_data` |
| `vocabularyVersion` | ref SegmentTagVocabulary | 所属词表版本 | 见 §4.1 |

**约束**：
- `code` 与 `tagId` 在同一词表版本内唯一；加载期校验重复 ID → 加载失败（§8.1）。
- 一个标签同时属于某一 `dimension` 与某一 `granularity`；`dimension=preference` 的标签不得与 `GameplayArchetype` 的玩法域语义重复（如禁止把 `combat` 当受众标签）——边界判定 `OPEN`（§10 OPEN-4）。
- D-01 不校验标签语义，只校验引用存在性与 `state`（§5）。

### 3.2 `GameplayArchetype`（类型库种子数据条目）

**字段严格对齐 D-01 §4.13**（不新增、不改名、不改类型）。本文只给种子取值与来源标记。

| 字段 | 类型 | 含义 | 本包种子约束 |
|---|---|---|---|
| `archetypeId` | id | 类型唯一标识，稳定不可变 | 不可变 |
| `name` | string(1–24) | 类型名 | P1 由种子给定，不触发玩家确认 |
| `coreSlotDomains` | list<ref GameplayDomain> | 核心槽接受域集合 | **至少 1 个**；来自 D-01 §5.1 十个玩法域 |
| `typeAffinity` | map<GameplayDomain, decimal> | 对各玩法域的推荐强度，值 ∈[0,1] | 供 D-01 §6.5 `genreFit`；缺省域取 0（D-01 §6.5 已定义）；数值 `TUNING` |
| `subtypeTableId` | ref / null | 子类型表引用 | P1 种子为 `null`；`OPEN`（§10 OPEN-5） |
| `isProvisional` | bool | 是否临时类型 | 种子为 `false` |
| `state` | enum{provisional, active, deprecated} | 生命周期状态 | 种子 `active`（D-01 §4.13 种子入口）；见 §4.2 |
| `successCount` | int | 作次类型成功上市累计次数 | 种子为 `0`；`K` 阈值 `TUNING`（D-01 §14.4） |
| `source` | enum{seed_data, player_created, ai_created} | 来源 | 种子为 `seed_data` |
| `createdAt` / `promotedAt` | datetime / null | 创建与升级时间 | 由 Calendar 提供；种子 `promotedAt=null` |

**与 D-01 的一致性约束（不得冲突）**：
- `PositioningProfile.primaryTypeId` 只引用 `state=active`；`secondaryTypeIds` 可引用 `active` 或 `provisional`（D-01 §4.13）。
- 种子 `coreSlotDomains` 用于派生 `GameplaySlot.requiredForType` / `domainAcceptance`（D-01 §4.4）；本包不定义槽位本身。
- `typeAffinity` 向量以 D-01 §5.1 固定十维顺序为维度；`genreFit` 算法归 D-01，本包不实现。

### 3.3 `Platform`（存在性与技术标准引用格式）

**只提供存在性与对 D-01 的输入能力，不做平台经营**（基线 §10.2：玩家经营平台非核心业务，完整经营后置）。

| 字段 | 类型 | 含义 | 约束 / 状态 |
|---|---|---|---|
| `platformId` | id | 平台唯一标识，稳定不可变 | 不可变；deprecated 不物理删除 |
| `code` | enum | 稳定枚举码（如 `arcade`） | 不可变 |
| `displayName` | string(1–24) | 玩家可见名称 | |
| `existence` | {available: bool, eraRange: {fromYear, toYear}, regionCoverage: list<ref Region>} | **存在性**：在世界中是否可及、何时/何地可及 | P1 取 1978 北美（P0-B §4.1）；越界由 D-01 `E-ERA` 提示（§5.3） |
| `techStandards` | list<TechGate> | **技术标准引用格式**，D-01 §6.4 `T` 集合来源之一 | 格式 CONFIRMED（下）；**档位含义与具体门槛 `OPEN`→D-06** |
| `state` | enum{active, deprecated} | 是否可被新版本选择 | 见 §4.3 |
| `source` | enum{seed_data, historical} | 来源 | 种子标 `historical`（史实存在）或 `seed_data` |

**`TechGate` 引用格式（与 D-01 §4.8 严格一致）**：
```
TechGate: {
  gateId: id,
  domainId: ref TechnologyDomain,   // D-06 领域引用；本包不定义领域
  minCapabilityLevel: int ≥ 0,      // 档位含义 TUNING / OPEN→D-06
  note: string
}
```
- 本包 P1 种子平台 `techStandards = []`（空列表，CONFIRMED 占位），**不填具体门槛**——避免在 D-06 未定义档位时伪装确定规则。D-06 就绪后按版本补充。
- `min=0` 的 TechGate 恒满足、不入 `T_unsat`（D-01 §6.7）。

**对 D-01 的输入能力（提供什么）**：
| 输入 | D-01 消费点 | 说明 |
|---|---|---|
| 平台候选列表 | `PositioningProfile.platformTargets: list<ref Platform>, ≥1` | 玩家 ≥1 多选的候选项 |
| `platform.techStandards` | §6.4 `T` 集合来源之一（§4.8 四类来源表） | 进入技术门槛与 `RiskProfile` |
| 存在性（era/region） | §11 `E-ERA`、可及性 | 越界仅提示（软） |

**明确不提供**：抽成比例、用户规模、平台独占/准入规则、平台生命周期经营、平台对销量的直接影响——全部 `DEFERRED`/归平台系统（D-01 §2.2 O 外、基线 §10.2）。

## 4. 状态与版本

### 4.1 词表版本化

| 字段 | 类型 | 含义 |
|---|---|---|
| `vocabularyVersion` | string | 词表版本标识，格式 `D04-VOCAB-v{major}.{minor}`；P1 = `D04-VOCAB-v0.1` |
| `effectiveFrom` | date / world-year | 生效起点；由 Calendar 提供 |
| `changelog` | list<string> | 版本变更摘要（追加式） |
| `tagIds` | list<ref SegmentTag> | 该版本收录的标签 |
| `sealed` | bool | 已发布版本只读 |

**版本规则**：
1. 已发布版本 `sealed=true`，不得修改词条取值；变更（增/改状态）必须发新版本。
2. **ID 稳定 + 不物理删除**：旧蓝图/快照中的 `tagId` 在新版本仍可解析（即便已 `deprecated`），因此 D-01 不需要新增"词表版本"字段，也不存在旧存档悬空引用（G4）。
3. 新增标签在三处生效：词表新版本、`ModuleTemplate.audienceAffinity`、`Option.audienceAffinityDelta`。**新标签若在模块库中无 affinity 数据，D-01 计算时按缺省 0**（D-01 §6.5`affinity` 公式对未列标签自然为 0），不报错。
4. 词表版本变化属 D-01 §6.6 的"外部输入变化"：估算**可以变化并显示原因**，但**不强制升 `formulaVersion`**（与 D-01 §6.6/S5 一致）。
5. P1 全局单版本；"玩家/存档绑定特定词表版本"是否开放 → `OPEN`（§10 OPEN-6）。

### 4.2 `GameplayArchetype` 生命周期

沿用 D-01 §4.13，本包不改写，只明确种子入口：

```
[种子数据 seed_data]  ──D-01 §4.13──► [active]                // 本包 3 个种子，直接 active
[ModuleArchetype 提升] ──D-01 §14.4──► [provisional]          // isProvisional=true，仅可作次类型
[provisional] ──successCount ≥ K──────► [active]              // K=TUNING，设置 promotedAt
[active|provisional] ──长期无产品/改版─► [deprecated]          // 只读保留，旧档案仍引用；阈值 OPEN
```

- 任务所述 `provisional→active→deprecated` 是**完整生命周期**；本包种子按 D-01 §4.13 从 `seed_data` 直接进 `active`，不经过 provisional（与 D-01 无冲突）。
- `provisional`/提升逻辑归 D-01 §14；`deprecated` 触发阈值 D-01 未给定 → `OPEN`（§10 OPEN-3）。
- AI 与玩家共享类型库（D-01 §14.4），本包种子对 AI 同样可见，无特权。

## 5. 规则

### 5.1 D-01 如何消费本词表

| 消费点 | D-01 章节 | 本包提供 | 方向 / 性质 |
|---|---|---|---|
| 宣称受众候选 | §4.3 `targetSegmentClaims`（1–3） | `SegmentTag(state=active)` 列表 | **前置只读**；玩家只宣称，蓝图只存 `tagId`，不回写词表（D-01 §3.1/§8.1） |
| `affinity` / `positioningFit` 分母 | §6.5 | 标签 ID 集合（`C=set(claims)`；`S={tag:affinity>0}`） | D-01 算 Jaccard；本包不出权重 |
| 主/次类型候选 | §4.3 `primaryTypeId`/`secondaryTypeIds` | `GameplayArchetype(state=active/provisional)` | 只读；D-01 校验 state（§4.13） |
| `genreFit` | §6.5 | `GameplayArchetype.typeAffinity` 向量 | D-01 算 cosine；本包不出算法 |
| 平台候选与门槛 | §4.3 `platformTargets`（≥1）、§6.4 `T` | `Platform(existence, techStandards)` | 只读；D-06 定档位 |
| 锁定 / 返工完成 / 交付闸门 | §7.2.1、§11 | 引用存在性与 state 校验（§5.2/§5.3） | 同步动作点校验 |

**接口方向澄清（继承 D-01 §3.1）**：本包 → D-01 是**前置输入**；D-01 → D-04 的 `MarketAppealProfile` 是**下游输出**。二者不构成同一数据的回写环，本包不读 D-01 画像、不算需求。

### 5.2 锁定校验 E 级规则如何使用

本包数据参与 D-01 §11 的 E 级校验与 §7.2.1 `RevalidationGate`（返工完成切快照 / `EXECUTING→COMPLETED` 交付）。**复用 D-01 错误码与通用格式，不新增同义码**：

| 情形 | 触发 D-01 码 | 级别 | 处理 |
|---|---|---|---|
| `primaryTypeId` / `targetSegmentClaims` / `platformTargets` 为空 | `E-10`（断言空值） | 硬 | `IN_REVIEW`/锁定阻断 |
| 无任何平台（`platformTargets` 空） | `E-11`（平台缺失） | 硬 | 锁定阻断（与 `E-10` 可同时命中，去重展示） |
| 主类型引用非 `active` | §4.13 约束（非独立 E 码） | 硬 | 锁定阻断；UI 提示改选 active 类型 |
| `platform.techStandards` 含本时代不可能的门槛（由 D-06 判定） | `E-TECH` | 硬 | 锁定阻断；技术可突破时允许并标高风险（D-01 E-6） |
| 标签/平台/类型在该时代/地区不可用（经旧存档/API 带入） | `E-ERA` | 软（提示） | 打开时标记，不自动删除 |
| 引用 `deprecated` 词条 / 完全未知 ID | `E04-DEPRECATED-*` / `E04-UNKNOWN-*`（§5.4） | 硬 | 锁定阻断；旧快照只读例外 |
| 返工完成 / 交付时引用已失效 | 复用上列全部 E 码 | 硬 | `RevalidationGate` FAIL → 不切快照/阻断交付，返回修正或撤销（D-01 §7.2.1） |

**通用错误输出格式（与 D-01 §11 一致）**：
`{ code, severity(E|W), ruleId, subjectIds[], message, suggestedAction }`

### 5.3 未知标签 / 未知平台处理

| 情形 | 判定 | 草稿期 | 锁定 / 闸门 |
|---|---|---|---|
| `tagId` 在当前版本 `active` | 合法 | 可选 | 通过 |
| `tagId` 在历史版本存在但 `deprecated` | 已知但过期 | 只读显示，禁止新选 | 新蓝图：`E04-DEPRECATED-TAG` 阻断；旧快照：只读保留、不阻断 |

| 新版本新增 `tagId`，模块无 affinity | 合法 | 可选 | 通过；`affinity` 按缺省 0（D-01 §6.5） |
| `platformId` 在当前版本 `active` 且存在性可及 | 合法 | 可选 | 通过 |
| `platformId` `deprecated` | 已知但过期 | 只读显示，禁止新选 | 新蓝图：`E04-DEPRECATED-PLATFORM` 阻断；旧快照只读 |

**不自动修复**（对齐 D-01 §9.3）：本包不自动替换未知/过期引用，只给 `suggestedAction`；玩家自行改选。

1. **创建/编辑蓝图**：`getVocabulary/getArchetypes/getPlatforms` 拉候选；草稿期未知引用仅 `W04-*` 警告，不阻断。
2. **`request_lock`（D-01 §7）**：`resolveRefs` 硬校验；命中 E 码阻断。

## 8. 异常与边界、存档要求、性能要求

### 8.1 异常与边界

| 编号 | 情形 | 处理 |
|---|---|---|
| X-1 | 词表包加载失败 / 为空 | `E04-NO-VOCAB`，阻断蓝图创建，不静默用空词表 |

| X-3 | 引用未知 / 过期词条 | 见 §5.3；草稿软、锁定/闸门硬；不自动替换 |

| X-8 | 同引用同时命中 `E-10`/`E-11`/`E04-*` | 全部计算、去重展示，不吞码 |
| X-9 | 多版本共存时同一 `tagId` 语义变更 | ID 稳定；语义变更须发新版本，旧版本 `sealed` 只读 |

### 8.2 存档要求

| 编号 | 要求 |
|---|---|
| A1 | 词表/类型种子/平台作为**静态策划数据随版本包发布**，不随每个玩家存档复制；存档只记录"使用的词表版本"字符串。 |
| A2 | 蓝图按 D-01 §4.3 只存 `tagId`/`archetypeId`/`platformId` 引用，**不存词表快照**；因 ID 稳定且 `deprecated` 不物理删除，旧快照引用不过期（G4）。 |
| A3 | **不向 `DesignVersionSnapshot` 增加任何词表字段**（D-01 §4.12/§12 S2 不变，避免冲突）；若需按词表版本重放，版本字符串外置记录，具体机制 `OPEN`（§10 OPEN-6）。 |
| A4 | 词表版本变更须记 `changelog`；`sealed` 版本只读，满足 D-01 §6.6 确定性/可回溯。 |
| A5 | 本包加载为纯数据、无随机；符合 D-01 §12 S5 确定性要求。 |

### 8.3 性能要求

| 编号 | 要求 |
|---|---|
| PF1 | 词表规模 ≤12 标签 / 3 类型 / 3 平台；加载期一次构建 ID 索引，O(n)。 |
| PF2 | `resolveRefs` 引用存在性校验 O(1) hash 查找；单次校验 < 1ms。 |
| PF3 | 词表加载 < 16ms（与 D-01 §13 P1 帧预算一致）。 |
| PF4 | **不参与每日 tick**；只在玩家操作 / 锁定 / 返工完成 / 交付 / 读档时调用（对齐 D-01 §13 P4）。 |
| PF5 | 候选列表随蓝图页加载缓存，不在每帧重建（对齐 D-01 §13 P5）。 |
