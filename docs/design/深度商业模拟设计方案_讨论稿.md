# 游戏产业大亨 · 深度商业模拟设计方案

2026-11-27 · V0.1 设计讨论稿

消费者优先、工作室经营随后、联盟在 P3 展开的顺序已纳入 [二次规划基线](../GameIndustryTycoon_二次规划基线_V1.1.md) 和 [P2-01 首个纵向切片](../tasks/P2-01_产品模块与市场差异纵向切片.md)。本文保留设计理由，实施顺序与进度以规划基线和任务卡为准。

**建议先让消费者对同类型的不同游戏做出不同选择，再让这些结果改变工作室的下一款和合作条款。** 首个试玩目标是让玩家做完两款游戏，并能指出第一款的实际经营结果怎样改变了第二款的设计、预算或发行决策。

《维多利亚 3》给本方案三个启发。人口群体把购买力传给市场需求。国家的财政、产能和利益关系约束同一个行动。外交把能力与筹码转成有条件的承诺。对应到本游戏，模拟单位是消费者群体、工作室和商业伙伴，玩家通过立项、生产、定价和签约来推动它们。

| 借鉴 | 在游戏里变成 | 玩家需要做的决定 |
|---|---|---|
| POPs 的购买力、需求和群体差异 | 有规模、可支配游戏预算、模块偏好与品牌记忆的消费者群体 | 给谁做，投入哪些模块，以什么价格卖 |
| 国家财政与生产能力之间的制约 | 公司经营表和生产配额，由账本、团队、技术积累及合同推导 | 钱留给工资、做新作、维护旧作，还是换成眼下的发行机会 |
| 外交中的共同利益、承诺和筹码 | 有适用地区、平台、期限和退出条件的商业合作 | 自发行还是换取渠道与现金，愿意让出多少收益和选择权 |

## 1. 消费者群体：同类型的游戏，为什么有人想买、有人会等折扣

首批只选一个历史窗口、一个地区、一个合法平台和两个实际有不同偏好的群体。群体可暂定为「偏快速上手」和「偏深度挑战」，名称和分布由该时期的内容资料确定。每组人数是该地区活跃玩家的互斥份额。年龄、题材和玩法标签是用来描述或查找群体的维度，叠加标签不会额外生成人口。平台可及性从地区与平台事实读取，未来加入多平台时再处理重复触达。

| 群体信息 | 玩家能看到的影响 |
|---|---|
| 活跃玩家规模与购买预算 | 群体有多少人、对当前价位有多敏感、这个月还有多少购买空间。预算由时代和地区条件驱动，随时间恢复或变化。 |
| 玩法偏好与接受门槛 | 同样是动作游戏，上手反馈和精细操控能吸引不同人。更高模块强度可带来更深体验，也可增加上手成本和研发成本。 |
| 对某品牌的记忆 | 群体记住这家公司在哪类体验上兑现承诺。相近定位的下一作可继承一部分认知，跨类型的继承较弱，未兑现的承诺会逐步侵蚀信任。 |
| 已有选择与观望 | 候选产品、竞品和延期购买共用群体预算。即使市场只有一款游戏，玩家也可能等折扣或暂不购买。 |

运行链建议为 **合法触达 → 了解产品 → 比较同类与等待 → 购买 → 体验与退款 → 群体口碑**。选定受众表示营销和设计意图，其他可触达群体仍可按实际匹配考虑购买。模块满足偏好决定这部分人有多想要，价格与预算决定买不买得起，QA 与交付事实影响体验及退款。销售页面把这些因素分开解释，避免把同一因素叠成多个加成。

实现以现有需求池为唯一销量入口。第一批只给每组一个按时间刷新的预算和简化的购买记录，限制同产品重复购买。退款按既有账本处理，避免退款后反复购买刷销量或品牌。月度更新群体预算与结构，日度使用同一份可重放的群体状态结算。市场页只展示足以取舍的预估，复盘才显示带证据的实际销量、退款与等待原因。

## 2. 工作室经营：让能力意味着能做什么、要放弃什么

按「可用能力」「已经占用」「做决定后还剩什么」显示四组经营信息。每组有独立事实来源，避免重复录入公司属性。

| 维度 | 事实来源 | 能约束的动作 |
|---|---|---|
| 财务与承诺 | 现金账本、薪资、项目预留、合同付款和分成 | 现金撑不到上市时先缩范围、改档期或谈预付款。付款预览同时列出下月固定开支和要让出的后续收入。 |
| 技术与制作经验 | 团队实际技能、完成工作包和已交付项目的技术或模块记录 | 复用旧项目流程节省特定学科研发。做过街机动作不等于有任何类型的技术加成。 |
| 管理与并行能力 | 负责人、分配比例、活跃项目和合同承诺 | 同时维护旧作和开发新作会争夺设计、编程或测试时间。超配会在确认前显示具体被挤占的工作。 |
| 市场与履约信誉 | 受众口碑和伙伴履约记录，分别记账 | 已服务的客群更容易认识续作。按期交付可以改善同一伙伴的条款，违约会增加担保要求或缩小合作范围。 |

首批建议先做决策预览和一条可验证的继承链。第一款练熟了某模块，第二款复用时说明哪类工作量减少、节省多少只是估计、熟练团队是否仍在职。公司看板可深挖数据，新手需要先看见现金跑道、当前最紧缺岗位和下一次合同义务三件事。后续再做管理结构、贷款或经营政策。

## 3. 商业关系：把外交博弈变成双方都算得过账的承诺

**交易条款解决眼下的事，履约历史改变以后的谈判。** 公司之间可在一个地区联合发行，也可在另一个平台竞争。关系先按「伙伴 × 业务范围」记事实。按期交付、付款、独家冲突、解除等事件汇成可解释的合作记录。双方对合作的估值从现金、覆盖、替代伙伴、竞品风险和已有义务派生。

首批沿已有发行合同做一张可比较的报价单。工作室可自发行，或向一个合适伙伴换取一个明确的能力，例如某地区触达，或上线前的预付款。合作方用分成、限定期限的优先窗口、交付条件等收回风险；工作室可调整少量关键条款、接受或退出。报价上列净收入区间、最差情况、互斥条款和撤约后果，实际分账仍走同一个账本。AI 用相同合同和财务规则评估交易。

P3 再展开多方联盟。将「共同目标、承诺、期限、争议」落实成具名项目，例如数家独立工作室共摊联合展会预算，按各自支付额与可覆盖受众计算效果。一方退出时依合同改分摊或取消活动。平台、供应商和其他企业也可以成为伙伴。工商关系优先从有实际代价的交易积累，减少玩家靠反复点击提升关系的空间。

## 4. 两款产品的试玩例

以下为待校准的试玩脚本。设定在同一地区、平台和类型，具体规模、售价和收益由数值验证再定。

1. **第一款做取舍。** 同为动作街机，「短关卡 + 快速反馈」便宜、容易上手。「精细操控 + 高难挑战」要占更多程序和 QA，可能更适合愿意玩深的客群。玩家选后者，也能看到更小的受众和更长的工期。
2. **上市读结果。** 深度客群的留存与口碑较好，广泛曝光带来的不少消费者选择观望。复盘指出难度和价格分别影响谁，退款原因另列。第一款同时留下该客群的品牌记忆和制作经验。
3. **第二款做选择。** 玩家可复用操控经验做同客群续作，承担受众偏小的风险。也可转成大众设计，放弃部分品牌和技术继承。若短期现金紧张，发行商可给预付款，但要求限定期限的地区独家。玩家能在确认前比较现金时点、开发工期、可触达群体和合同分成。

这条链要求一种方案可以少卖但挣钱，另一种可能卖得多却因研发或分账成本赚得少。具体是否出现取决于场景和数值，试玩应能说明结果为何不同。

## 5. 推进和验证

| 时点 | 做到什么 | 通过依据 |
|---|---|---|
| P2 首个试玩切片 | 单地区单平台、同类型两套配置、两个可分辨客群、设计与销售归因、第一款反馈进入第二款 | 同价、同档期、同营销的对照能分辨谁更愿意买；交换模块配置能改变结果；试玩可指出一个明确的第二款改动。 |
| P2 后续 | 补品牌记忆衰减、同类产品复用与预算预览，比较自发行和现有发行选项 | 两套策略能面对不同条件生存；复用产生真实成本差，口碑可因失约转坏；存读档续跑一致，现金与销量对得上。 |
| P3 | 多伙伴报价、履约历史、有限联盟、同规则 AI 和产业关系 | 自发行一直可选；能拒绝不划算的条款；同一对手既能合作也能竞争；违约与退出会产生可复核后果。 |
| P4 / P5 | 分地区和时代的群体结构、平台更替、技术扩散，以及关键人才和组织授权 | 地区和年代会改变可行策略，组织扩张改变资源分配，长期模拟和存档可验证。 |

第一批按现有产品蓝图、交付、市场分配、账本和存档做集成。正式排期前先用相同开局测试四组脚本：交换模块、交换价格、跳过或接受发行、退款与读档。数值 Agent 负责区分价格和配置影响。体验 Agent 在桌面检查三个决定能否被理解。技术风险集中在受众重复计数、累积品牌导致赢家恒赢、旧档日结算变化和每产品每日计算量，分别用份额守恒、品牌衰减、版本化读档和聚合性能验证。

## 6. 纳入排期的三项取舍

| 设计取舍 | 纳入排期的选择 | 备选方案 |
|---|---|---|
| P2 第一个可玩切片从哪里开始？ | **消费者优先。** 同类型不同设计先出现可解释的市场后果，给公司和伙伴系统提供实际经营数据。 | 先做现金与发行约束，经营压力较早可见，产品组合反馈随后补齐。 |
| 首批消费者模拟到什么程度？ | **先跟踪预算、选择和口碑。** 人数慢变，购买与反馈每天可观察，能较早验证玩家决策。 | 首批就做多地区、平台迁移和群体结构变化，历史模拟更完整，校准面更大。 |
| 商业联盟多早做到可玩？ | **P2 可比较自发行与一份真实报价，P3 再做多方联盟。** 首款的销售和履约会成为第二款的谈判依据。 | P2 就做小型联合发行或展会联盟，合作更早成为主玩法，同时需要伙伴目标和退出规则。 |

## 7. 完整版目标：固定历史开局，任选城市创业

2026-11-28 确认。以 1970 年为共同起点，每局从同一份产业世界状态开始。各地区已有对应的公司、产品、消费者、平台和技术条件。玩家选择任意已建模的城市创办公司，加入这个共同世界。AI 公司和产业会继续经营，玩家的产品、技术投入与合作也能改变后续的竞争格局和产业演化。

工作室选址与消费市场的开放规则分别计算。即使某地当时缺少成熟的消费市场，玩家也可以在那里创业。以 1970 年在中国城市开局为例，具体城市与历史参数待内容校准。起步阻力可以来自当地渠道、设备与技术获取、专业人才供给和购买力。玩家可以从条件允许的小规模产品做起，通过培养人才、积累技术和寻找合作逐步打开机会，最终有可能改变本地乃至全球产业格局。

完整版验收采用同一初始世界做对照：无玩家干预时产业仍会演化。换城市会改变早期可行策略。持续经营后，玩家造成的可观察变化能在产业档案中追溯到相关产品、企业、技术或合作。

现阶段先按已接受的方案做旧金山、伦敦和东京，逐个验证城市成本、本地需求、在售作品、竞争对手与发行选择是否形成真实取舍。

### 当前可玩范围

| 开局城市 | 早期街机偏好 | 本地开局竞品 |
|---|---|---|
| 旧金山 | 街机 | 月雀工作室《弹珠冲刺》 |
| 伦敦 | 射击，玩家相对更在意价格 | 北极星互动《星际巡航》 |
| 东京 | 格斗，玩家相对较少受价格变化影响 | 街机之王《街头拳王》 |

三地共享 1970 年世界。地区受众规模读取实际平台覆盖，品类权重和价格敏感度进入早期街机的购买意向计算。本地作品上市时有曝光优势，仍可销往其他开放市场。玩家可以查看地区竞品、销量与发行商覆盖，在签署发行合同时选择该发行商覆盖的地区。

「项目 → 技术研发」提供精灵动画工具和音效编辑工具。玩家一次研究一项，费用当期入账，经过相应天数后用于新立项，减少美术或音频工作量。立项预览会标明已应用的工具。此处属于科技玩法的首个可玩范围，完整版还需要城市历史条件、技术扩散、专有实现、动态突破和产业编年史。
