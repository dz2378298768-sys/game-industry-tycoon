## 一、问题定性

**不是翻译资源缺失，是文案未走翻译链路。** 词条本身完整：

| 检查项 | 结果 |
|---|---|
| `src/i18n/en.json` | 898 键，含中文值的条目 **0** |
| `src/i18n/zh-CN.json` | 898 键，与英文键集合完全一致 |
| UI 层 `t()` 调用 | 830 处 |
| 语言切换机制 | `setLocale` → store `set({ locale })` → `refresh()` → 组件重渲染，机制正常 |

切换后大部分界面确实变英文，残留中文集中在**动态文案**（错误提示、状态提示、审计描述），而非静态界面标签——这与"部分内容还是中文"的实测现象吻合。

---

## 二、根因链路

核心缺陷在 `src/ui/state/game-store.ts:92`：

```ts
function localizeError(errorCode: string | undefined, message: string | undefined, fallback = 'error.unknown'): string {
  const key = errorCode ? ERROR_I18N[errorCode] : undefined
  if (key) return t(key)
  return message ?? t(fallback)   // ← 未命中映射就原样吐领域层中文
}
```

`ERROR_I18N` 是一张**手工白名单**（61 个错误码）。只有命中白名单的错误消息才翻译；没命中的，直接把领域层返回的中文 `message` 显示给玩家。领域层本就用中文写文案，于是英文模式下漏出中文。

### 漏网量化

| 漏网类型 | 位置 | 数量 |
|---|---|---|
| 错误码未进 `ERROR_I18N` 映射表 | `game-world.ts` | 3 个：`PROJ_NOT_FOUND`（表中实为 `PRJ_NOT_FOUND`，**拼写差一个 O**）、`CONTRACT_CONTROL_LOCKED`、`D03_CANDIDATE_NOT_FOUND` |
| 失败返回无错误码、仅中文 `message` | `game-world.ts` | **11 处**（如"项目已暂停，请先恢复""员工不属于该公司，无法分配"） |
| `?? '中文兜底'` | `game-world.ts` | **16 处** |
| 硬编码中文（完全未走 `t()`） | `project-detail.tsx` | **8 行**：toast 2 处（142/735）、`blockHint` 6 处（167/171/173/175/177/179） |
| 领域层展示文案（去注释后含中文行） | 全 `src/domain`、`simulation`、`application`、`content` | **365 行**，其中 `game-world.ts` 83 行、`save-schema.ts` 44 行、`ai-planner.ts` 34 行 |

### 测试为什么没发现

`src/ui/__tests__/i18n-parity.test.ts` 只做两件事：

1. `expect(zhKeys).toEqual(enKeys)` — 校验 key 集合一致；
2. 校验每个值是非空字符串。

它**从不校验**：

- UI 是否真的调用了 `t()`（硬编码中文检测不到）；
- 领域返回的 `message` 是否已在 `ERROR_I18N` 中登记；
- 英文模式下是否存在渲染出的中文字符。

这是测试盲区，彻底治理必须补齐这三类断言。

## 三、彻底治理方案（P2 · SUP-08）

目标：**领域层零展示文案，UI 零硬编码文案，翻译链路全覆盖且被测试锁死。**

### 3.1 领域层结构化

- 所有返回给 UI 的 `message` 改为**错误码 + 结构化参数**，不再内嵌中文句子。
  - 现状：`message: \`现金不足，入职成本需要 $${cost}。\``
  - 目标：`{ errorCode: 'EMP_INSUFFICIENT_CASH', params: { amountCents: cost } }`
- 领域层的中文仅允许保留在**不进入 UI 的位置**：日志、审计追溯用的 `description`（须确认是否被 UI 渲染，若渲染则同样改造）。
- 修正 `PROJ_NOT_FOUND` / `PRJ_NOT_FOUND` 拼写不一致——统一为一个规范码。

### 3.2 i18n 层支持插值

`src/i18n/index.ts` 当前 `t(key)` 只做字典查表，不支持参数。扩展为：

```ts
t(key: string, params?: Record<string, string | number>): string
```

英文/中文词条用 `{amount}` 占位符，UI 侧统一 `t('error.insufficientCash', { amount: ... })`。

### 3.3 UI 层收口

- `localizeError` 改为接受 `errorCode + params`，不再接受领域层的自由文本 `message`；确需自由文本时必须先经白名单。
- `project-detail.tsx` 8 处硬编码中文全部改用 `t()`，`blockHint` 用插值。
- 消除 `?? '中文兜底'`：兜底一律用 `t('error.unknown')` 或具体错误码。

### 3.4 测试锁定（防回归）

在 `i18n-parity.test.ts` 增加三组断言：

1. **UI 硬编码检测**：扫描 `src/ui/**/*.{ts,tsx}` 去注释后，除 `t()` 键名与词典引用外不得含 CJK 字符；
2. **错误码全覆盖**：game-world 所有显式 `errorCode` 字面量 ⊆ `ERROR_I18N` 键集合；无错误码的失败返回数为 0；
3. **英文渲染检测**：以 `en` locale 渲染关键页面快照，断言输出中无 CJK 字符。

## 四、验收标准（SUP-08 完成条件）

1. 英文模式下，玩家可触达的全部界面与提示无中文字符（含 toast、blockHint、错误弹窗、状态徽标、审计描述若可见）；
2. 领域层返回给 UI 的失败结果中，裸中文 `message` 为 0；
3. `t()` 支持插值，双语词条占位符一致；
4. 三组回归测试落地并通过，四命令全绿；
5. 真机切换语言实测取证（英文→中文→英文往复），记录截图与用例。
