# REC-04C 推荐范围技能门槛与瓶颈复验

| 字段 | 内容 |
|---|---|
| 日期 | 2026-11-26 |
| 负责 | 数值 Agent |
| 场景 | seed `2404`；首项目 `core intensity 1 + episodes intensity 1`；Day 60 确认五学科候选；到岗后 Day 90 分配；起始现金 `$120,000`；预算容量 `$136,000`；项目承诺 `$61,200`；默认薪资/招聘费/6 个月 AvailableCash 规则不变 |
| 目的 | 找到不依赖全员 Lv5 的最低研发技能门槛，并区分研发瓶颈与财务瓶颈 |

## 1. 复验方法

使用真实 `GameWorld` 路径：创建推荐范围项目，推进到 Day 60；按学科选择候选，冻结指定 `skillLevel` 后走正式候选池招聘；招聘费和月薪承诺由生产路径注册；等待 `PendingHire` 到岗并在 Day 90 分配；逐日推进至 Day 240/270。薪资、费用、AvailableCash、项目承诺和破产阈值均未修改。技能覆盖用 `f_skill(2)=0.8`、`f_skill(3)=1.0`、`f_skill(5)=1.4` 的既有公式。

## 2. 可复现结果

岗位顺序为 `[design, code, art, audio, qa]`。

| 技能组合 | READY 日 | Day 240 账面现金 | Day 240 AvailableCash | Day 270 结果 |
|---|---:|---:|---:|---|
| `[3,2,3,2,2]` | 226 | `$5,667` | `-$55,533` | 现金 `-$5,317`，项目暂停 |
| `[3,3,3,3,3]` | 226 | `$10,506` | `-$50,694` | 现金 `-$478`，项目暂停 |
| `[3,3,4,3,3]` | 211 | `$12,373` | `-$48,827` | 现金 `$1,390`，项目仍待交付 |
| `[4,4,4,3,2]` | 203 | `$14,312` | `-$46,888` | 现金 `$3,329`，项目仍待交付 |
| `[5,5,5,5,5]` | 187 | `$22,361` | `-$38,839` | 现金 `$11,378`，项目仍待交付 |

对 32 个 `2/3` 组合的扫描显示：

- `design=2` 时，即使其他学科为 3，最早约 Day241 才 READY；
- `art=2` 时，`design=3` 也无法在 Day270 前稳定达到 READY；
- `[3,2,3,2,2]` 已达到 Day226 READY，说明 code/audio/qa 不需要强制 Lv3 才能完成推荐范围；
- 其他三个学科降到 Lv2 会延迟或降低现金余量，但不是推荐范围的首要 READY 阻塞；
- 全员 Lv5 只提前完成日期并减少研发期间工资/项目支出，不能消除六个月承诺造成的负 AvailableCash。没有上市收入时，Day270 前后现金转负是财务时序问题，不是继续提高技能可以根治的问题。

## 3. 对用户观察的解释

用户观察到 Day240 `design=100 / code=88 / art=74 / QA=100`，与 `art` 和 `design` 的有效产能不足导致的跨日瓶颈一致。当前推荐范围的稳定最小研发门槛是 `design >= 3`、`art >= 3`；code/audio/qa 可从 Lv2 起步，但 UI 必须把预计 READY 日期和瓶颈学科显式显示出来。音频不能被隐藏为“无需岗位”，否则会重新引入 REC-04A 的职责缺口。

## 4. 推荐设计规则

在不修改经济锚点的前提下，首项目推荐招聘提示采用“瓶颈门槛”而不是“全员高技能”规则：

1. 推荐范围首次确认时，将 `design >= 3`、`art >= 3` 标为首项目 READY 门槛；code/audio/qa 显示 Lv2 为可运行下限，Lv3+ 为提前完成选项。
2. 招聘候选卡与项目页按学科显示“预计产能/预计 READY 日”，使用同一项目快照和候选技能值，不伪造成功保证。
3. 若玩家选择 design 或 art 低于 3，系统应明确警告“预计在当前现金跑道耗尽前无法 READY”，但允许继续选择。
4. 到 READY 后必须提示立即交付/上市；技能门槛不能替代上市收入。若玩家保持 READY 但不上市，继续支付工资是可预期的策略后果。
5. 不把“Day270 仍有正现金”作为技能门槛验收条件；该条件依赖交付/上市/销量收入，属于 REC-04E/REC-07 闭环验收。

## 5. 限制与后续输入

本轮是单 seed、单城市、固定最低岗位数的敏感性扫描，不能代表所有候选薪资和市场 seed 的完成率。REC-04E 仍需由体验 Agent 在默认参数下验证从招聘到交付、上市和收入的真实电脑端路径。REC-06/07 应使用本报告的 `readyDay`、账面现金、AvailableCash、runway 和承诺剩余期数作为财务/销量输入，不得通过提高资金或暗改工资解决。
