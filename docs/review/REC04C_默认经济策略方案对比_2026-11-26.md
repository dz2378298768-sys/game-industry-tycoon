## 1. 已验证事实

冻结以下锚点后，默认 `core + progression + episodes` 结构、五学科最低报价招聘在 10 个 seed 中没有自然达到 `READY_TO_DELIVER`。招聘完成后 `AvailableCash` 约为负值，五人六个月薪资承诺与一次性招聘费合计约 `$59.8k-$66.1k`。提高初始资金或隐藏负数可以暂时绕过现象，但不能作为正式验收证据。

将首项目范围精简为 `core intensity 1 + episodes intensity 1`，不修改现金和薪资锚点时，5 个 seed 中有 4 个达到 `READY`，约 3 个在 Day 200 前后完成上市；仍有 1 个因长期负现金在 Day 211 破产取消。该结果说明主要敏感因素是项目范围与承诺释放节奏，候选池覆盖不是唯一瓶颈。

## 2. 可行设计选项

### 方案 A：首项目精简范围向导

首个 `ExecutionProject` 创建向导提供一个“首项目推荐范围”，默认只启用 `core intensity 1 + episodes intensity 1`，`progression` 作为玩家主动追加的范围。项目模板与规则不变；改变的是首项目的产品范围选择。

| 项目 | 结果 |
|---|---|
| 保持的锚点 | 起始现金、市场薪资、招聘费、六个月承诺、HRB、项目容量/承诺 |
| 预期收益 | 降低 design/code/art/audio 的总工作量；提高首项目在负现金前达到 READY 的概率 |
| 玩家代价 | 首项目默认内容较少；玩家需明确选择追加范围和新增承诺 |
| 必须裁定字段 | `firstProjectScopePolicy`（`recommended`/`mandatory`）；默认模块集合；追加模块是否需要重新显示 AvailableCash/runway |
| 工程影响 | 仅影响首项目向导和模板快照；不改变通用 WorkPackage 公式 |

这是当前最小改动、最容易回滚的设计选项。推荐先采用 `recommended`：允许玩家切换完整结构，同时在确认前显示完成风险与承诺影响。

### 方案 B：首项目招聘节奏与岗位提示

保留完整产品结构，但首项目向导按工作包依赖提示“先招当前瓶颈岗位”，并允许玩家只为已启用模块招聘必要学科。REC-04A 保证候选覆盖，UI 负责显示“未启用模块不需要立即招聘”。

| 项目 | 结果 |
|---|---|
| 保持的锚点 | 起始现金、薪资、招聘费、承诺窗口、产品结构公式 |
| 预期收益 | 降低一次性五人承诺造成的现金压力；避免为未启用模块提前招聘 |
| 玩家代价 | 需要理解依赖与到岗延迟；分批招聘会延长日历时间，不能保证所有 seed 在现金耗尽前完成 |
| 必须裁定字段 | 模块到学科需求映射；首项目推荐招聘顺序；待到岗人员是否占管理容量；缺岗时是否允许继续推进 |
| 工程影响 | 招聘页提示、项目页缺岗提示、首项目向导；核心数值公式不变 |

方案 B 可以作为方案 A 的配套提示，但单独采用时不能承诺首项目稳定可完成。数值实验中每 7 天招聘一人的策略没有改善默认完整结构的 READY 比例。

### 方案 C：首项目失败保护与范围降级

保持完整结构和招聘锚点；当首项目在接近上市前触发破产风险时，提供一次明确的玩家决策：取消未开始模块、释放对应未生效承诺，或接受项目取消。该规则属于产品状态机，不是数值补丁。

| 项目 | 结果 |
|---|---|
| 保持的锚点 | 起始现金、薪资、招聘费、六个月窗口、基础工作量公式 |
| 预期收益 | 让现金压力转化为可解释的产品决策，减少无提示的破产取消 |
| 玩家代价 | 增加范围变更与审计状态；玩家可能主动牺牲内容换取上市 |
| 必须裁定字段 | 可降级模块；降级时的已完成进度保留规则；承诺释放时点；是否允许降级后重新评估交付闸门 |
| 工程影响 | 新增范围变更状态、承诺释放和交付闸门重算；需 REC-04 后续批次，不应与 REC-04B 混做 |

方案 C 解决的是失败可解释性与补救，不保证默认完整结构的完成率，应在 REC-06 财务补救/反馈批次处理。

## 3. 推荐裁定与已执行决定

主设计已批准并执行 **方案 A（`recommended`）+ 方案 B 的可见性提示**，不改变冻结锚点。首项目创建时保存 `scopePolicy` 和模块快照；招聘页与项目页共用同一模块到学科需求派生结果。玩家主动选择完整结构时，界面必须在确认前展示预计招聘承诺、AvailableCash 和 runway，不能暗中替换模板。该决定已登记于 `ADJ-2026-11-26-REC04C-首项目范围推荐.md`。

方案 C 留给 REC-06，作为破产前的显式补救，不纳入 REC-04E 的首条默认成功证据。
