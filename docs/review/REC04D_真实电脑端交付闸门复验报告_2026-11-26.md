## 已验证的真实 UI 行为

1. 新档 `REC04D 交付验证公司` 从 Day 0 创建项目 `闸门状态验证游戏`，默认预算承诺 `$61,200`，可用现金 `$58,800`。项目详情的“交付与上市”入口可达。
2. 在未有团队、进度为 0%、QA 为 0%、WP 全部未开始的项目上打开交付页，页面显示“正式版”和“抢先体验版”资格均为“评估不可用”，并显示方向档信息；没有把未知状态伪装成 PASS。
3. 交付页明确解释“交付资格需要质量评估数据；数据不可用时会明确显示‘评估不可用’，不会推测结论。”未解决项区域显示“交付闸门评估不可用或未通过”。
4. 点击“交付确认”后打开披露确认弹层，弹层再次显示“EA 披露项信息不足”与“交付闸门评估不可用或未通过，提交禁用：项目未处于可交付态（READY_TO_DELIVER）”；“确认交付”按钮为 disabled。点击没有绕过闸门或创建交付状态。
5. 定价三档和营销预算三档可见：低价 `$0.21`、中价 `$0.28`、高价 `$0.35`；营销 `$100/$500/$1,500` 每天每渠道。默认中价、标准投放被选中。渠道选择器提供社交媒体、展会、广告投放。

## 阻塞与边界

- 当前新档没有招聘、团队和研发推进，不能自然到达 `READY_TO_DELIVER`；因此本轮不能把“评估不可用”当作自然 READY 的正式交付证据，也没有使用测试注入、提高资金或手写状态跳过路径。
- REC-04C 的范围推荐已有批准裁定（`ADJ-2026-11-26-REC04C-首项目范围推荐.md`），代码也已有推荐/自定义入口；本轮没有重复复验该向导。REC-04E 的默认参数完整闭环仍需先完成五学科招聘、分配、研发和自然 READY。此处仅确认未 READY 时 UI fail-closed 行为。
- 交付弹层在信息不足时仍显示“EA 披露项信息不足”，并阻断确认，符合 fail-closed；自然 READY 后应再验证真实披露清单、资格 PASS、确认交付、计划日上市及销量/收入。

## 候选确认/到岗时序修复（代码验证）

该次浏览器证据暴露的规则错误已修复：候选有效期现在只约束玩家确认招聘的日期；确认时仍拒绝已过期候选，但确认成功进入 `PendingHire` 后，不再因为到岗日晚于候选池截止日而撤销。`rec04b-pending-hire.test.ts` 新增正反两条断言，招聘/到岗/招聘 UI 定向测试共 16 项通过，typecheck 与 lint 通过。体验 Agent 需用新构建重跑上述默认策略；本报告中修复前的失败记录保留为问题发现证据。

REC-04D 当前可标记为 `PASS_WITH_NOTES`（未 READY 时的真实资格查询、阻断原因、确认按钮禁用和价格/营销控件均有浏览器证据）。自然默认路径的 REC-04E 仍为 `BLOCKED`，REC-04 / SUP-01 继续 `NOT_VERIFIED`，直到默认参数下完成自然 `READY_TO_DELIVER → 交付确认 → 计划日上市 → 销量/收入` 路径。
