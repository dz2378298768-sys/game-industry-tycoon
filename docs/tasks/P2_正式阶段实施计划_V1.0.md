## 一、阶段出口

P2 完成时，玩家应能在同一历史窗口、地区、平台和类型下，选择不同的玩法模块组合，观察两个消费者群体对产品的不同反应，比较成本与销售结果，并把第一款产品的真实结果带入第二款产品的设计、预算或发行选择。

P2 的阶段出口包含四个必须同时成立的结果：

1. 产品模块是玩家可理解、可保存、可复盘的设计选择，不是隐藏参数。
2. 消费者群体的预算、偏好、观望和退款反馈来自同一套可重放市场状态。
3. 同类型不同模块组合在同一市场条件下产生可解释差异，差异能追溯到模块、价格、质量或市场事实。
4. 第二款产品能读取第一款真实结果，并让玩家做出至少一个不同于默认方案的经营选择。

## 二、四个开发波次

### P2-A 产品表达与消费者基础

目标是建立可验证的产品设计选择和最小消费者群体模型。

交付内容：

- 两套同类型可完成的玩法模块组合，以及模块依赖、强度和缺失来源规则。
- 单历史窗口、单地区、单合法平台和两个可区分消费者群体。
- 群体预算、偏好、购买空间、观望和退款输入，接入现有需求池和销售入口。
- 产品快照、存档迁移和复盘查询字段。

退出条件：

- 玩家能在向导中选择两套有效组合。
- 两个群体对同一产品的购买意向或观望原因有可解释差异。
- 触达人数互斥且可重放，缺少来源时 fail-closed。
- 产品选择经过存档和读档后保持一致。

对应任务：P2-01，必要时拆分为模块契约、群体输入和存档迁移子任务。

### P2-B 市场反馈与结果解释

目标是让玩家能从销售、退款、口碑和成本结果反推产品选择的后果。

交付内容：

- 模块组合到工作量、成本、受众匹配和购买意向的来源链。
- 市场页的估算信息和产品复盘页的实际信息分层。
- 销量、收入、退款、观望和媒体反馈的事实记录。
- 最小品牌记忆与衰减规则，记录群体对定位兑现和失约的反馈。
- 产品详情中的结果归因，至少区分模块匹配、价格、质量和市场状态。
- 同 seed 对照模拟和存档续跑确定性验证。

退出条件：

- 同一市场条件下交换模块组合能够改变至少一项成本、受众或销售结果。
- 页面能显示结果来源，不使用无法解释的综合分数。
- 品牌记忆能帮助相近定位的下一款，但不能保证成功，失约会产生可观察的衰减。
- 玩家能指出至少两个造成结果差异的事实。
- 失败或缺源状态有明确提示，不生成伪造反馈。

### P2-C 第二款决策与商业选择

目标是把第一款产品结果接入第二款产品的真实经营决策。

交付内容：

- 第一款产品的模块选择、实际成本、销量、退款、口碑和市场反馈摘要。
- 第二款向导读取至少一项真实结果，并提供不同的续作、转型或成本方案。
- P2 后段加入自发行与一份真实发行报价的可比较选择。
- 报价显示预付款、分成、地区或平台范围、期限、交付条件和退出后果。
- 合同和销售继续使用统一账本，不新增旁路收入。

退出条件：

- 玩家能在第二款立项前看到首款结果事实。
- 至少一个首款结果会改变第二款的可见选择、成本、预算或发行条件。
- 自发行与发行报价可以比较最差情况、现金时点和净收入。
- 旧档没有相关结果时显示数据不足，不伪造继承效果。

### P2-D 整合与阶段验收

目标是完成完整 P2 玩家路径和独立验收。

固定试玩路径：

1. 新档进入市场页，查看两个消费者群体。
2. 创建同类型产品，分别选择两套模块组合。
3. 观察研发成本、工作包和现金影响。
4. 完成研发、交付和上市，查看销售、退款和反馈。
5. 在复盘页查看模块、群体、价格、质量和市场因素的归因。
6. 进入第二款向导，比较继承、转型和发行选择。
7. 保存、冷读档并续跑，确认关键结果一致。

阶段退出条件：

- 设计审核、编码审核、数值复核和桌面体验审核均通过。
- 同类型两套模块组合有可复现差异，且差异来源可解释。
- 两款产品之间存在真实反馈传递。
- 关键状态、现金、销量、退款和存档数据账实一致。
- P2 未完成项逐项登记，不能用测试全绿替代体验验收。

## 三、依赖与顺序

| 依赖 | 用途 | 处理方式 |
|---|---|---|
| 现有需求池和销售公式 | 消费者购买与市场结算 | 复用现有入口，先补群体状态和来源，不重写销售主公式 |
| 产品快照和模块内容 | 保存产品选择 | 先完成模块契约，再扩展市场输入 |
| 统一账本 | 成本、收入、退款和报价 | 所有新增商业结果必须进入现有账本 |
| P1 存档兼容 | 旧档读取 | 新字段可选，缺少 P2 数据时显示数据不足 |
| P2-01 | P2-A 主线 | P2-A 未通过前，不启动 P2-C 的发行报价实现 |

P2-A 和 P2-B 可以在文件边界清楚时并行。P2-C 依赖 P2-B 的结果来源稳定。P2-D 必须等待 P2-A～P2-C 的退出条件全部满足。

## 四、明确不纳入 P2

- 多方商业联盟、复杂伙伴网络和产业关系，归 P3。
- AI 企业完整经营、合作和发行决策，归 P3。
- 多地区、多平台、跨时代消费者结构和平台更替，归 P4。
- 技术扩散、历史产业事件和全球编年史，归 P4。
- 关键人才、导师、组织授权和管理容量，归 P5。
- 跨多年品牌生态、复杂生命周期、更新和扩展系统，作为 P2 后段或 P6 的独立任务，不能自动混入 P2-01。

## 五、质量与证据要求

每个波次都必须提供设计契约、生产调用证据、定向测试、数值对照和玩家路径证据。涉及公共状态、存档、账本或销售公式的任务按 L3 处理，必须经过独立编码审核和桌面体验审核。讨论稿只提供设计方向，不能直接替代任务卡、正式规格或验收报告。

## 六、P2 维护规则

- 当前状态只在本计划、`docs/阶段规划.md` 和 `docs/STATUS_进度快照.md` 三处汇总。
- 每个子任务必须链接本计划的波次和退出条件。
- 范围升级到 P3、P4 或 P5 时，先登记阶段边界变更，再创建任务卡。
- 任一波次出现数据来源不明、重复计数、非确定性或玩家无法解释结果时，状态回退到 `FIX`，不得进入下一波次。
