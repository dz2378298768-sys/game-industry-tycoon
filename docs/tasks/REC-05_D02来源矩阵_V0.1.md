## 当前结论

REC-04D 的生产闸门接线已经满足“真实字段求值 + 缺失字段 fail-closed”。REC-05 BuildFacts 来源契约已冻结并接线：QA 仍只有标量缺陷等级；交付前档位取冻结快照内容包档位总和，实际成本取项目关联账本支出，无法追溯时阻断；成功 Build 与闸门使用同一事实快照，不再写占位 0。REC-05 仍需补 QA 缺陷明细、D-06 能力等级和独立审核。

前置裁定见 `docs/decisions/ADJ-2026-11-26-REC05-D02来源契约前置.md`；BuildFacts 具体来源见 `docs/decisions/ADJ-2026-11-26-REC05-BuildFacts来源与事实时点.md`。REC-04E 的真实浏览器样本到位后再做端到端接线验收。

## 接线顺序

1. **QA 缺陷簇（设计前置）**：明确 D-02 的 `severity` 与 D-03 当前标量缺陷口径如何对应；如规则要求可区分 E 级，须有确定性的缺陷明细权威实体及产生/修复/存档语义。不得从 `finalDefectLevel` 任意切分或伪造 defectId。
2. **Build/成本簇（已接线）**：交付前 `actualCost`、`deliveredTier` 已按 ADJ-2026-11-26-REC05-BuildFacts 来源与事实时点接到真实项目状态；Build 作为同一事实的已交付快照留存。下一步只做独立审核、旧档反证和体验可见性复核。
3. **能力簇**：盘点 D-06 的真实能力快照接口，若不存在先建立设计裁定和 `UNAVAILABLE` 迁移口径，禁止工程自行编造能力等级。
4. **档案相似度**：等待 D-07 口径后单独裁定；在此之前维持 `unavailable_p1`，不阻塞已登记的 fail-closed 路径。

## 验收门

- 每个字段只有一个生产权威来源，来源可从运行时对象追溯到存档字段或事件；提交前与提交后的事实时点定义一致。
- 真实缺失仍显示 `degraded`/`UNAVAILABLE`，不能以 `0`、空数组或 `true` 伪造通过。
- 同一存档重复评估逐字段一致；交付失败不创建 Build，交付成功只创建一份幂等 Build；Build 的成本与档位不得为占位 0（除非权威计算结果确为 0）。
- 体验 Agent 能在交付页看到每个阻断字段的可读原因；英文模式不出现裸中文。
- REC-05 通过后，REC-04D 的 `provenance` 清单必须更新为实际生产来源，REC-04E 的真实浏览器证据必须重新采集。

## 职责

- 设计 Agent：冻结字段契约、状态机、缺失语义和错误码。
- 工程 Agent：按字段簇接线并提供存档/幂等/反证测试。
- 数值 Agent：验证缺陷、成本和能力字段对闸门及现金的影响，不改锚点。
- 体验 Agent：真实电脑端验证阻断信息与成功交付反馈。
- 主 AI：协调依赖、收集独立审核、更新 REC-04/05 台账。
