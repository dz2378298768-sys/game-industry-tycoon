# REC-06 P1 口碑与销量归因

依据 ADJ-2026-11-24-26 B1–B5 与恢复路线 REC-06。口碑、退款和销售归因都是玩家查看上市结果时的只读投影。

| 展示项 | 来源和时点 | 缺失或读档行为 |
|---|---|---|
| 媒体评价档 | 已上市产品的 `computeReviewLift` 有效评价分，优先用 `reviewScore`，否则用上市锁定的 `finalQualityScore`。低于 50 为偏负面，50 至低于 75 为褒贬不一，75 起为偏正面。 | 上市产品存档可立即派生。无产品或有效分越界时只显示暂无评价。产品列表、详情和复盘复用同一口径。 |
| 模型退款率 | 当前退款模型 `computeRefundRate` 读取上市时记录的缺陷等级。展示模型比例，销量取整会影响预计退款件数。 | 无销售记录时不展示率。存档保留缺陷等级与销售记录，可重新派生。 |
| 累计已入账退款率 | 销售记录的累计 `actualRefundUnits` 除以累计毛销量。退款周额仍从已入账退款批次汇总。 | 存档可恢复。无销量时无可比较的退款率。 |
| 销量归因 | 产品最近一次有销量的游戏日，汇总已结算市场与平台下的需求池切片。可触达件数、购买意向缩减、分配缩减与销售记录的当日毛销量相符。 | 会话只缓存各产品最近一次有销量日。存档缺少历史需求池切片，读档后显示信息不足，下一次产生销量时恢复。历史销量、净销售额和退款事实仍可查看。 |
| 复盘证据 | 最近上市的本公司产品。设计项指向源项目选定的类型，执行项取上市缺陷等级，市场项取最近已结算日的毛销量，财务项取扣除已入账退款的累计净收入。 | 每项独立判断有无源数据。有源时可从该项一步进入项目或产品详情。 |

## 需求池与旧归因接口

生产游戏固定走 C1 需求池。`explainSales.topDrivers` 只在旧 M2 管线产生，该算式无法对账 C1 的销量。REC-06 使用真实需求切片的三步解释：

1. 以 `floor(audienceUnits)` 为可触达件数。
2. 以 `floor(audienceUnits) − floor(poolUnits)` 为购买意向阶段减少的件数。该阶段受受众与平台匹配影响，REC-05 将价格弹性也纳入这一阶段。
3. 以 `floor(poolUnits) − allocatedUnits` 为分配阶段减少的件数。分配阶段受自身可售性、认知与相对吸引力，以及同一需求池内其他产品影响。

每个市场与平台须在当天有该产品已结算的销售记录才纳入。这个差分可以逐切片相加，三项合回已入账销售记录的日毛销量。价格、质量和认知度等只作为模型含义解释，当前数据无法识别它们各自造成的独立销量变化。

## 验收

- P-10 对照评价分 49、50、74、75 检查档位，比较已入账退款率和不同缺陷等级下的模型退款率。
- 通过生产工厂和正常销售结算推进两个同市场产品，确认购买意向阶段与分配阶段均产生变化，三步合回销售记录。
- 读档后确认销量、口碑和退款仍可查。历史归因降级，新成交后自动恢复。
- P-12 查看复盘产品对应的证据，再跳转核对详情。媒体卡为档位摘要，历史评价和 BrandMemory 不在 P1 范围。
- 浏览器验收由体验 Agent 执行，须用完成真实上市及销售的桌面端存档验证玩家能解释三项原因。
