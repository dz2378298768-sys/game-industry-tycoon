# REC-08 人才身份、到岗与分配

招聘卡使用候选人物的姓名、现有职级、学科技能、报价和可入职时点。人名从独立内容池确定性生成，首次候选到正式入职始终使用同一人物姓名。旧档内的生成占位名在招聘和员工界面按同一算法展示，存档数据保持原样。

| 展示 | 运行来源 |
|---|---|
| 在职与管理容量 | 在职人数取占用名额的 Employment，含试用、在职与离职交接。待到岗只读取 `PendingHire.state === 'pending'`，与招聘命令的容量守卫一致。旧任职缺失时回退已在职的 Employee 记录。 |
| 待到岗及确认月薪 | PendingHire 快照的到岗日、接受报价、学科、技能与职级。员工页与招聘页共用这份显示。 |
| 工资 | 未来月薪承诺来自账本承诺，已兑现工资来自工资流水。 |
| 履历 | 关联人物的真实 PersonEvent，过滤仅确认待到岗的事件，展示正式到岗以及已产生的后续人事记录。带真实等级的升级事件显示其学科和新等级。 |
| 项目分配与缺岗 | 玩家项目实际 `teamAssignments` 提供项目和分配比例。仍有工作量且项目执行投影返回零产能的学科显示为缺岗。 |

## 保留问题

- **OPEN-PROJ-5**。D-03 已有记录技能成长的服务方法。当前的生产调度没有调用它，工作日志只记录工作包和学科合计。完成工作包后如何识别个体贡献，仍需单独确定规则和存档口径。当前履历保留已有的人事记录。
- 人物性格、任命或导师以及留任风险展示仍需 D-03 后续真实来源和设计裁定。招聘使用规则已生效的资历、技能、工资与到岗日。

验收包含真实候选确认、待到岗名额、自然到岗和项目分配，覆盖同一人物跨阶段的身份一致性。独立桌面端体验仍需结合 P1 完整玩家路径留证。
