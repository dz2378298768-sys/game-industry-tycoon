## 1. 目标
定义 P1 最小的人才与组织系统：人如何被雇佣、如何分配到项目学科、如何产出日产能 `Cap_d`、如何成长与流失。为 Project 执行的 `Cap_d`/`burden_d` 提供唯一权威来源。

## 2. 范围（IN）
1. **实体与字段**：`Person`（人本身：属性、技能画像、年龄、士气）、`Employment`（雇佣关系：岗位、薪资、合同期、分配）；严格遵循基线「Person/Employment 分离」（人可换雇主、同一人不可重复雇佣）。
2. **技能与产能**：学科（design/programming/art/qa）技能等级如何映射到 `Cap_d`（必须给出可执行公式，与 Project §6.3 对齐）；`burden_d`（一人多项目分摊）规则。
3. **雇佣与流动**：招聘渠道/周期/成本；离职诱因（士气/薪资/项目失败）；P1 最小可行集（不做完整劳动力市场模拟，标 DEFERRED）。
4. **成长**：做项目带来的技能增长（P1 可为简化规则，标 TUNING）。
5. **薪资与账本**：工资支付走统一账本 `salary` 类别；承诺支出与跨月规则。
6. **与 Project 的接口**：项目如何查询某学科可用 `Cap_d`（输入输出契约、调用时机、错误码）。
7. **迁移映射**：现有 `employee.ts` 哪些 KEEP / EXPAND / REWORK（对照基线迁移裁定表）。
8. 状态与生命周期（在职/休假/离职/解雇）、异常边界、存档要求、性能要求、≥12 TC、未决项 OPEN/TUNING。

## 3. 非目标（OUT）
- 不做员工私生活、家庭、通勤（基线 REJECT）。
- 不做完整劳动力市场/行业人才竞争（P5 范围，DEFER）。
- 不做办公室空间/设施管理（另行设计）。
- 不做股权/期权激励。

## 4. 验收标准
- [ ] 覆盖协作规范 2.3B 的 18 项最低要求。
- [ ] `Cap_d` 公式可执行，符号全定义，与 Project §6.3 无冲突。
- [ ] Person/Employment 分离落地（同一人不可双重雇佣有规则）。
- [ ] 薪资与统一账本接口一致（不改现金、走承诺）。
