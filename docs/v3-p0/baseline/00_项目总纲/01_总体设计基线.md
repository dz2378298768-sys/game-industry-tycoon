# Game Industry Tycoon 总体设计基线

## 1. 一句话定义

一款以电子游戏产业为舞台、以公司经营为核心、以产品创造与市场竞争为驱动、以时代和产业演化为背景的深度经营模拟游戏。

玩家创办并经营自己的电子游戏企业，在不断变化的全球产业中设计产品、组织人才、配置资源、选择商业模式、建立合作关系，并亲自创造一段可能偏离真实历史的电子游戏产业史。

## 2. 产品愿景与玩家目标

### 2.1 不设强制终极目标

玩家的最终目标由玩家自己决定。游戏不设置必须成为全球最大公司、必须上市、必须活到某一年或必须击败某个对手的唯一胜利条件。

游戏提供持续运行的产业平台，以及足够丰富的机会、约束、竞争、合作和长期后果。可以成为精品独立工作室、类型专家、知名开发商、发行商、多工作室集团、技术创新者，也可以经历失败、转型、重组或主动退出。

“跨时代经营”是世界跨度与体验愿景，不是强制胜利条件。2026 年是当前历史模拟内容的暂定边界，不是玩家必须结束经营的日期；2026 年之后的未来产业模拟暂不纳入当前规划，未来是否扩展另行立项。

### 2.2 玩家身份

玩家是企业创始人和经营决策者，不是亲自操作每个员工的项目经理，也不是只负责研发的制作人。玩家决定企业做什么、为什么做、投入多少、与谁合作、承担什么风险；团队负责把战略转化为执行。

### 2.3 体验目标

玩家应持续体验到：
- **创造感**：设计一款有独立身份的游戏，而不是生产一组抽象数值。
- **经营张力**：资金、人才、工期、质量、市场窗口和机会成本互相冲突。
- **因果理解**：成功和失败能追溯到产品设计、团队执行、市场匹配和商业决策。
- **产业参与感**：AI 企业、消费者、平台、技术和人才并不围绕玩家静止等待。
- **历史成就感**：多年后能回顾某款作品、某位人才或某次决策如何改变公司乃至产业。
- **策略自由**：不同企业定位都能形成长期可行路线，不存在唯一最优经营模板。

## 3. 核心循环

### 3.1 企业循环

观察产业与市场 → 识别机会/风险 → 制定公司战略 → 配置资金、人才和能力 → 执行产品与商业计划 → 获得市场反馈 → 调整组织和产品组合 → 形成长期资产与历史影响。

### 3.2 产品循环

发现需求或创意 → 产品定位 → 玩法与内容设计 → 可行性和项目规划 → 团队研发 → 测试与交付决策 → 发行上市 → 销售与口碑反馈 → 更新/扩展/续作/停止维护 → 产品档案与经验沉淀。

### 3.3 产业循环

企业决策 → 产品供给与竞争 → 消费者行为与市场变化 → 企业收益、声誉、人才与技术变化 → 合作/竞争关系重组 → 新企业、新产品、新技术与新趋势。

这三个循环必须互相作用。若产品循环不影响公司长期能力，企业循环就会变成财务表格；若企业循环不影响产业格局，世界就会变成静态背景；若产业变化不反馈到玩家决策，历史系统就只是新闻墙。

## 4. 世界与时间

### 4.1 独立演化世界

世界必须在玩家不采取行动时继续运行。AI 企业会创办、扩张、转型、合作、竞争、衰退或破产；消费者偏好会变化；平台会兴起和退出；技术会扩散或被企业掌握；人才会流动；产业格局会改变。

世界演化不等于所有实体都需要逐日微观模拟。按决策重要性采用不同时间尺度：每日处理交易和项目执行，月度处理企业战略，季度/年度处理产业结构与历史总结。

### 4.2 历史与架空

真实历史作为初始世界和准入参考，不作为强制剧情。真实公司、产品、平台、人物、技术和事件可在有可靠资料时进入世界；它们后续的经营结果由模拟因果决定，允许出现不同于现实的成功、失败、提前突破、延迟突破、替代者和架空创新。

历史事件采用“历史条件 + 动态触发 + 模拟结果”的混合方式。历史资料决定某些条件何时可能出现，企业能力、市场机会、技术积累和竞争关系决定事件是否发生及其结果。不得用固定脚本强制玩家世界复刻现实。

### 4.3 时间范围与节奏

- 起始时代：1970 年，具体开局日期可由情景决定。
- 当前历史内容边界：暂定 2026 年。
- 游戏日期按天推进，玩家可暂停和调整速度。
- 每日模拟不意味着每日都要求玩家操作。
- 月度为企业财务和 AI 经营的重要节奏；季度、年度用于趋势报告、战略复盘和编年史。
- 结算周期按业务性质区分，不强制所有系统使用同一周期。

### 4.4 全球地理

世界是全球电子游戏产业模拟。地区差异影响购买力、消费者偏好、平台覆盖、人才供给、工资租金、发行成本、法规环境和技术生态。

玩家可在开局时选择任意已开放地区创办公司。地区提供不同机会和约束，不存在永久最优出生点。玩家可逐步跨地区招聘、建立办公室/分公司、组织跨国团队、发行和营销。国家级细节按玩法价值分阶段开放；经济模拟优先采用可解释的市场区域聚合，历史和叙事可保留更细的国家信息。

## 5. 企业、组织与商业身份

### 5.1 企业形态动态演化

玩家不选择一个永久锁定的“职业类型”。企业从实际经营活动自然形成业务身份：独立工作室、专业开发商、发行商、多工作室集团或综合企业。AI 企业使用同源规则。

公司扩张必须带来新的管理问题和决策，不得仅把员工数、项目数和金额放大。成长阶段由多条件触发，如稳定收入、品牌、组织能力、产品组合和市场影响力。

### 5.2 组织抽象

企业内部采用层级化管理：
- 普通员工：有独立身份、岗位、能力、薪酬和经历，日常行为由系统自动处理。
- 核心人才：更细致地模拟能力、成长、职业诉求、关系和流动。
- 负责人/管理者：影响团队协调、资源分配、组织扩张和管理跨度。
- 工作室/部门：承接项目、能力建设和经营责任。

玩家主要管理团队、负责人和核心人才，不逐人审批普通员工的每日任务。公司规模越大，越依赖授权、管理能力和组织结构。

### 5.3 企业文化

企业文化不做成庞大独立模拟器。它是组织管理的综合状态，由管理风格、工作制度、创作自主度、质量标准、薪酬公平、晋升机会、团队信任和历史行为共同形成。文化影响人才吸引、留任、协作、创新和冲突；文化不能用单一“文化分”替代具体机制，也不要求玩家管理无关的员工私人生活。

## 6. 人物与人才

人物是产业参与者，不只是员工属性容器。每个人物至少拥有身份、能力、职业经历、当前状态和所属组织；重要人物拥有更深入的性格倾向、职业诉求、成长轨迹和关系。

### 6.1 人物分层
- 全体员工：独立身份、基础能力、薪酬、岗位、职业经历、流动状态。
- 核心人才：专业能力、成长、性格/诉求、留任风险、重要项目经历。
- 产业名人：完整职业历史、行业声誉、标志性作品/技术/团队影响。
- 历史人物：以可核实史实作为参考，允许架空发展；使用时须审查资料、授权和法律边界。

### 6.2 人物行为

人才可能求职、跳槽、被挖角、晋升、转岗、创业或带领团队流动。行为受薪酬、能力成长、创作自由、稳定偏好、管理关系、团队关系、企业前景和外部机会共同影响。

人物关系只模拟有经营意义的类型：导师/学生、长期合作伙伴、上下级、职业竞争者、团队信任和派系关系。不得扩展为复杂私人生活模拟。

### 6.3 玩家干预

玩家可以招聘、培养新人、安排导师、培训、提拔、任命负责人、分配重要项目、跨地区调动、授权管理工作室和支持员工创业。玩家可以影响职业发展，但不能保证人物按指令成长；个人能力、性格、诉求、经历和环境共同决定结果。

## 7. 产品与玩法创造

### 7.1 产品是核心实体

每款游戏都有独立身份和长期档案。产品不只是销量数字或项目完成后的临时对象。它拥有设计方案、版本、研发团队、成本、质量、平台、地区、价格、营销、销售、评价、口碑、生命周期、更新、续作关系和产业影响。

### 7.2 分层设计深度

- **定位层**：名称、类型、题材、视角、结构、规模、平台、受众、卖点和商业定位。
- **玩法层**：战斗、探索、成长、任务、建造、经营、叙事、社交等可组合玩法模块。
- **深度层**：高级模式可进一步配置关键机制内部规则、节奏、资源循环、敌人/关卡结构和系统依赖。

默认体验以组合已有玩法模块创造新产品为主。动态生成新玩法概念逐步开放，不把无限自由配置作为早期开发前提。高级深度设计必须改变工作量、技术要求、受众匹配或产品表现，否则不应成为无效参数。

### 7.3 设计与生产分离但互相约束

玩家表达产品设计，系统将设计拆成模块、工作包和研发任务；团队自动安排执行。玩家管理目标、范围、优先级和资源，不手动操作每一条底层任务。设计方案必须影响成本、周期、人员需求、技术风险、质量和市场表现。

### 7.4 质量与完整度分离

至少区分：
- 设计质量：方案的结构、创新、体验潜力和市场匹配。
- 实现质量：团队执行质量、技术稳定、内容表现和缺陷情况。
- 产品完整度：是否达到该产品类型和交付形式所需的核心内容、系统、技术与交付要求。

不得把三者压缩成一个百分比。不同产品类型应有不同的核心交付标准。正式版、抢先体验版、测试版等交付形式允许不同完整性要求，但玩家必须承担相应市场预期和声誉后果。

## 8. 消费者、市场与品牌

### 8.1 分层消费者模型

消费者采用有差异的群体模型，不模拟每个消费者的日常生活。群体差异包括地区、年龄/用户类型、游戏偏好、消费能力、价格敏感度、质量偏好、平台偏好、品牌认知和对新类型的接受程度。

群体的规模、兴趣和行为可以变化。市场不是一池永远固定的需求数字；产品供给、平台扩张、文化趋势、口碑和技术变化可以创造、转移或压缩需求。

### 8.2 品牌长期记忆

消费者群体会积累对开发商、发行商、产品系列和购买体验的认知。品牌可以提高关注、初始期待和购买倾向，但不能替代产品本身。高质量和兑现承诺建立信任；低质量、欺骗性营销和糟糕售后损害信任。品牌影响必须按群体和产品领域区分，不能是对所有产品通用的万能加成。

### 8.3 动态产品生命周期

产品可以经历上市、增长、成熟、衰退和长尾，但阶段不是固定天数。销量轨迹由市场需求、产品质量、口碑、价格、营销、平台用户、竞争产品、更新、扩展和续作共同决定。老产品可能因折扣、平台迁移、内容更新、文化事件或系列新作重新流行。

## 9. 企业关系与合作

企业之间构成产业关系网络，而不是孤立竞争者。关系场景包括竞争、客户/供应商、委托外包、联合开发、联合发行、渠道服务、技术服务、投资和人才流动。

统一采用同一商业流程：**机会出现 → 信息评估 → 谈判/报价 → 合同 → 履约 → 结算与结果 → 关系和声誉变化**。业务场景是合同框架的应用，不为每种合作另造互不兼容的系统。

同一对企业可以在一个业务上合作、另一个业务上竞争。AI 企业可独立提出合作、拒绝、反报价、争夺人才或改变战略。未来联机若立项，真人企业与 AI 企业应共用底层商业规则；当前不为联机牺牲单机设计。

## 10. 科技、平台与产业结构

### 10.1 科技

科技采用历史参考、动态突破、混合所有权：
- 基础原理和行业知识会逐渐扩散。
- 高级实现、工具链、工艺诀窍和专有技术可由企业掌握。
- 技术突破受知识积累、人才、研发投入、设备/平台条件、产业合作和竞争影响。
- 玩家与 AI 可以提前或延后历史突破，也可能创造现实历史中不存在的新技术。

科技不是所有公司共享的简单节点开关，而是技术领域、能力水平、实现方案和可获取知识的组合。技术必须改变产品设计、生产效率、质量、兼容性或市场机会。

### 10.2 平台

平台是外部产业参与者和市场基础设施。平台生命周期、用户规模、地区覆盖、受众结构、技术标准、抽成、准入规则和生态吸引力共同影响产品。当前不把玩家运营游戏平台作为核心业务；平台运营商可以作为 AI/历史企业存在，但其完整经营模拟后置。

### 10.3 产业结构

市场集中度、平台更替、类型兴衰、技术扩散、人才流动、公司进入退出和合作网络共同形成产业格局。产业观察 UI 是展示层，不应先于真实模拟规则。

## 11. 产品历史与产业编年史

### 11.1 产品档案

每款产品永久保留关键设计、研发、团队、成本、决策、版本、上市、竞品、销量、财务、评价、更新、续作和影响记录。档案应支持多年后回顾“为什么成功/失败”以及产品对后续作品和产业的影响。

### 11.2 企业与人物历史

企业档案记录成立、业务变化、产品组合、合作、竞争、组织扩张、危机、重整、破产、收购/更名等重要节点。人物档案记录职业经历、关键作品、团队关系、成就、争议和创业/流动。

### 11.3 动态产业编年史

编年史不是随机新闻列表。它记录并关联重要事件：企业成立/破产/转型、代表产品、技术突破、平台兴衰、市场变化、人物职业节点和玩家企业影响。每条事件应能追溯触发原因、参与实体、时间、结果和后续影响。新闻只呈现重要事件，完整历史保存在实体档案中。

## 12. 经济与危机

经济系统要支持经营选择，而不是只展示现金。玩家必须理解现金、利润、承诺支出、应收应付、项目投入、产品收入、合同义务和未来跑道之间的关系。

破产是经营失败的因果结果，不是随机惩罚。危机过程应提供可理解预警和有限补救窗口。可选补救包括缩减范围、暂停项目、削减成本、裁员、转租、终止合同、出售可出售资产、寻求发行预付款或重整。重整不是免费复活，必须留下债务、资产、声誉、人才和控制权后果。沙盒可允许失败后继续观察世界；是否继续由玩家选择。

## 13. 玩家体验与信息呈现

每个经营界面优先回答四件事：
1. 当前发生了什么？
2. 为什么发生？
3. 我有哪些有意义的选择？
4. 每个选择会付出什么代价、带来什么风险？

信息按层级呈现：概览给出信号，详情解释原因，深入页面提供可操作配置。默认自动化处理重复工作；玩家可进入高级控制，但不应被迫微观管理。

通知按重要性分级并合并。重大风险、合同承诺、关键人才流失、产品交付决策需要明确提示；普通每日交易不应打断玩家。

## 14. 核心设计红线

- 不设置强制终极胜利条件。
- 不把产品做成可互换的数值生产单元。
- 不让 AI 获得不透明的经济特权。
- 不让世界依赖玩家行动才演化。
- 不模拟无经营价值的私人生活和每个消费者个体。
- 不把所有商业关系做成独立重复系统。
- 不把真实历史做成强制脚本。
- 不把科技做成只有解锁图标的线性树。
- 不用员工、项目、金额简单膨胀制造后期深度。
- 不用单一综合分数掩盖产品质量、完整度和市场匹配的差异。
- 不因已有代码或旧版冻结声明阻止必要的产品级重规划。
- 不因宏大愿景把所有系统同时塞进当前开发阶段。

## 15. 系统设计六道审查

每个新系统或重大扩展必须回答：
1. 必要性：没有它，核心体验会缺失什么？
2. 游戏性：它创造什么玩家决策、代价和反馈？
3. 重复性：是否已有其他系统承担同一职责？
4. 扩展性：能否支撑未来内容而不推翻底层？
5. 实现成本：开发、数据、测试和维护成本多大？
6. 运行成本：长期模拟、存档、UI和性能开销是否合理？

无法形成明确玩家决策或世界因果作用的内容，不进入当前规划。
