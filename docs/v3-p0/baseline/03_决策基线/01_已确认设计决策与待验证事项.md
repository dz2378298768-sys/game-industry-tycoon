# 已确认设计决策与待验证事项

## 1. 用户已确认的长期方向

| 主题 | 决策基线 |
|---|---|
| 玩家目标 | 玩家自行决定；游戏提供持续演化的产业平台，不设置强制终极胜利目标 |
| 世界演化 | 独立演化；玩家不行动时 AI、市场、技术和产业仍持续变化 |
| 历史模式 | 真实历史为参考，允许玩家和 AI 改变历史结果 |
| 历史事件 | 历史条件 + 动态触发 + 模拟结果 |
| 时间范围 | 1970 至当前历史内容边界暂定 2026；不代表 2026 强制结束经营 |
| 时间推进 | 按天推进，可调节速度；不同经济事项可采用不同结算周期 |
| 地理范围 | 全球主要产业地区和市场 |
| 创业地区 | 玩家可在任意已开放地区创办公司，地区提供不同机会与约束 |
| 跨国经营 | 支持跨地区招聘、办公室/分公司、全球发行和营销，深度分阶段开放 |
| 企业形态 | 企业可从工作室动态发展为开发商、发行商、多工作室集团或综合企业 |
| 企业关系 | 竞争与合作并存；同一企业对可在不同业务上同时合作和竞争 |
| 消费者 | 差异化偏好与行为的群体模型，不模拟每个消费者个体生活 |
| 品牌 | 消费者群体具有长期品牌记忆；品牌不能替代产品质量 |
| 产品生命周期 | 动态生命周期，允许长尾、重新流行和再激活 |
| 产品档案 | 每款产品拥有长期、可追溯历史档案 |
| 产业编年史 | 记录企业、产品、人物、技术、平台和市场变化及因果 |
| 人物系统 | 独立人物系统，支持职业发展、跳槽、挖角和创业 |
| 人物分层 | 普通员工、核心人才、产业名人；历史人物按资料和法律边界处理 |
| 人物性格 | 有限性格和职业诉求，影响招聘、留任、协作和流动 |
| 人物关系 | 只模拟有经营意义的导师、合作、上下级、竞争和团队关系 |
| 人才培养 | 玩家可以培养、安排导师、培训、提拔、任命负责人、分配项目和跨区调动 |
| 企业文化 | 不做庞大独立系统，作为组织管理与人才吸引力的综合机制 |
| 产品设计 | 分层设计；玩家既设计产品，也管理团队把设计实现 |
| 玩法创造 | 先通过组合已有玩法形成新类型，逐步发展动态创造 |
| 玩法深度 | 默认配置影响复杂度和制作深度；高级模式允许深入机制配置 |
| 研发参与 | 玩家在研发中定期参与关键设计决策 |
| 研发执行 | 自动分配为主，玩家调整优先级、资源和范围 |
| 续作 | 支持产品系列化 |
| 上市后更新 | 支持统一更新机制，再逐步扩展内容形式 |
| 外包合作 | 支持模块级外包和跨企业合作 |
| 产品历史价值 | 商业成绩、品质、创意和产业影响都重要 |
| 交付形式 | 正式版、抢先体验版、测试版等有不同完整度标准和市场后果 |
| 科技 | 历史参考、动态突破、混合技术所有权；基础知识扩散，高级实现可专有 |
| 联机 | 不是当前开发目标；未来若立项，真人与 AI 共用底层商业规则 |

## 2. 总设计师默认裁定

以下为总设计师为保持系统一致性作出的设计基线，不要求用户逐项确认；有新证据或试玩结果时可修订。

1. 不建立复杂员工私人生活模拟；人物系统只深入影响经营和产业。
2. 企业文化作为综合组织状态，不单独建立庞大数值系统。
3. 企业合作统一采用机会、谈判、合同、履约、结算流程，避免每种业务重复造系统。
4. 市场模拟采用群体聚合和多时间尺度，不逐消费者微观模拟。
5. 玩家管理战略、关键节点和资源，普通日常工作自动化。
6. 科技必须影响产品、效率、质量或竞争机会；纯收集式科技树不进入设计。
7. 历史事件必须有因果条件和游戏影响；纯百科新闻不进入核心事件系统。
8. 产品设计自由度分层开放；不以无限参数配置作为早期目标。
9. 全球模拟采用地区聚合与历史细节分层，避免每个国家都承担同等模拟成本。
10. 后期复杂度来自组织、产品组合、人才和产业关系，不来自简单扩大员工和项目数量。
11. AI 与玩家共用规则，差异来自策略、能力、风险偏好和信息，而非作弊加成。
12. 未来联机不能成为当前单机设计的前置负担。

## 3. 待专项设计但方向已确定

这些内容需要后续规格细化，不代表方向未定：
- 各地区市场聚合层级、国家展示与经济结算的映射。
- 产品类型的核心完整度标准和交付等级。
- 玩法模块库、组合规则、依赖和动态新类型生成的阶段边界。
- 消费者群体的动态分裂/合并、偏好变化和品牌记忆衰减。
- 人物性格/职业诉求的最小特征集合及关系影响范围。
- 公司组织层级、负责人授权边界和工作室独立经营程度。
- 技术领域、知识扩散、专有实现、授权和突破判定。
- 产业编年史事件等级、归档频率和历史压缩策略。
- 全球跨区经营的税费、语言、本地化、发行和团队协调抽象深度。
- 破产、重整、解散与沙盒继续观察之间的模式关系。

## 4. 必须通过模拟或试玩验证的事项

- 不同经营路线是否长期可行且不存在单一最优解。
- 品牌是否有意义但不过度滚雪球。
- 玩法设计复杂度与研发工作量是否形成有趣取舍。
- 产品完整度是否能被玩家理解并影响市场预期。
- AI 是否能在多种子、多年代中存活、分化、合作和退出。
- 消费者群体规模、偏好变化和市场需求是否稳定可解释。
- 人物关系和职业诉求是否创造有价值决策，而非随机事件噪声。
- 全球市场是否增加战略空间，而不是增加重复操作。
- 历史档案和编年史是否增强回顾与成就感，而不是制造大量无用日志。
- 多年代存档的性能、内存和历史压缩是否可接受。

## 5. 变更规则

- 用户确定的方向不可被执行代理自行改写。
- 总设计师可以对具体机制作出默认裁定，但必须标记为 `DESIGN_BASELINE`，并解释理由。
- 试玩、模拟或工程证据推翻设计假设时，应提出修订方案，不得为了维护旧决定压制证据。
- 任何范围扩张都必须说明新增决策、系统依赖、开发/维护成本、运行成本和被推迟的替代项。
