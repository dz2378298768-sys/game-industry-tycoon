# 主 AI 设计裁定 — HRB 语义（R-08）

- 裁定编号：ADJ-2026-11-21-01
- 对应问题：设计审核报告 R-08（MAJOR，HRB 与规模裁定冲突）
- 裁定人：主 AI（项目总负责人）
- 依据：总体设计基线 V3.0 §7.3/§14「不用员工、项目、金额简单膨胀制造后期深度」；系统地图 §4.1「规模仅作为预设」；迁移裁定表「项目规模和功能清单→REWORK：从规模参数转为可组合的产品蓝图与模块化范围，规模仅作为预设」；协作规范 §2.2E「一般设计取舍由主 AI 自行裁定」

## 裁定内容

**HRB（Human Resource Budget）不得作为全局工作量乘子存在。**

1. 工作量 `W_d` **只能**由产品结构（模块实例档位、槽位占用、深度选项、内容包）经四通道公式导出。不得存在任何与结构无关的连续全局乘子。
2. HRB 重新定义为**玩家显式作出的人力预算承诺**：它是玩家"愿意为该项目投入多少人力/资金上限"的决策，不是产品规模的描述。
3. HRB 的作用是**单向可行性检查**：将结构导出的 `W_d` 与 HRB 比较，产出「可行 / 需缩减范围 / 需追加预算 / 需延期 / 需降低质量目标」等可判定结论与代价提示。**不得反向缩放 `W_d`**（禁止 `HRB_scale × W_d` 形式的公式）。
4. HRB 与 Project 成本的口径关系必须单向：预算是约束，实际成本由工作量与团队产能决定；预算不足触发玩家决策，不得由系统自动缩小工作量来"自洽"。
5. `qualityCeilingBand` 的 HRB 映射（OPEN-O5）**从确定输出契约中移除**：在 D-02（产品完整度与交付标准）和 Project 规格对齐前，D-01 只能把质量上限标记为 OPEN / 待下游提供，不得承诺该字段。

## 理由

- 若 HRB 作为全局乘子，效果等同于被 REWORK 移除的"单一规模参数"换名复活，违反迁移裁定；同时与 §4.3「规模由结构自然导出」形成互斥答案，编码 Agent 无法判断服从哪条规则。
- 若 HRB 作为预算承诺，则保留了玩家有价值的经营决策（投入多少、范围要砍哪里），符合基线「真实成本与机会成本」要求，且不增加单一规模分数。
- 此项属于一般设计取舍（不涉及用户已确认方向或设计原则的修改），主 AI 有权裁定；如后续模拟或试玩证明此裁定损害体验，可依规范 §8.2 提出修订。

## 执行要求

设计 Agent 在 V0.2 中按此裁定整改 R-08 与 R-07，审核 Agent 复审时以本裁定为审核依据之一。本裁定不修改总体设计基线 V3.0。
