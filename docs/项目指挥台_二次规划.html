当前策略 V2.3：按风险选择通道，按依赖图调度。

低风险任务走 FAST，常规跨模块任务进入 STANDARD 批次，核心规则与跨系统任务走 STRICT。速度来自并行和复用，质量门槛保持不变。

FAST · L1

任务卡 → 实现 → 定向验证 → 主 AI 验收。触及核心规则、接口或存档时升级。

STANDARD · L2

批次规格 → 一次设计审核 → 最多两条编码流并行 → 批量独立审核 → 集成验收。

STRICT · L3

核心规则、财务、存档、跨系统闭环和阶段出口，保留完整双闸门与专项评估。

角色分工与权限

主 AI / 项目统筹

拆分任务、裁定冲突、维护基线、阶段验收。不能冒充独立审核。

设计 Agent

编写规格、状态、边界和场景。不得自审自关。

设计审核 Agent

独立检查完整性、一致性、可实现性和风险。

编码 Agent

按批准规格实现，补齐正反向测试，不扩大范围。

编码审核 Agent

复核实现、反证、测试真实性和回归影响。

体验/模拟评估 Agent

有运行版本时真实试玩或模拟；没有运行版本不得声称完成。

批次调度与并行边界

批次不替代任务：每个任务保留自己的 ID、验收口径和审核结论。无依赖、接口已定、文件无冲突的任务并行；主编码默认最多两条流。同一状态机、账本或存档结构只开一条写入流。
需求分级→依赖图与文件所有权→并行实现→批量审核→集成窗口

交接最小内容

必须可继续工作：任务/批次 ID、状态、本轮完成、修改文件、规格依据、验证命令与结果、审核结论、遗留问题、下一步和证据路径。稳定信息只引用，不重复粘贴。
