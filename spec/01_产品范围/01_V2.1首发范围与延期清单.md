# V2.1 首发范围与延期清单

## 1. 产品核心承诺

玩家经营一家电子游戏公司，从小型工作室起步，通过制作、销售和持续经营游戏建立现金流、口碑、品牌与IP资产。玩家的主要乐趣来自产品决策、团队组织、市场判断和公司成长，而不是管理大量彼此独立的后台系统。

**首发主线：游戏研发商 + 轻量发行经营。** 玩家可以自研自发，也可以与外部发行商签约；随着公司成长，可建立有限的内部发行能力。外部平台作为销售渠道和市场环境存在，但玩家不经营平台本身。

## 2. 首发必须完整实现

| 系统 | 首发实现边界 | 玩家核心决策 |
|---|---|---|
| 公司与财务 | 现金、收入、费用、预算、应收应付、破产预警 | 花多少钱、保留多少跑道、何时扩张 |
| 员工与团队 | 招聘、岗位、技能、薪资、团队分配、疲劳/士气简化 | 招谁、团队如何组合、是否外包/加班 |
| 研发项目 | 概念、预制作、制作、QA、完成；范围与变更 | 做什么、做多大、做到什么质量、何时上市 |
| 产品生命周期 | 定价、上市、补丁、折扣、退市/长尾 | 何时卖、卖多少钱、是否继续投入 |
| 市场与销售 | 目标市场、需求、口碑、竞品、销量和退款 | 目标人群、产品定位、竞争窗口 |
| 营销 | 2–4种清晰渠道、预算、活动时长、目标人群 | 营销投入和研发投入如何取舍 |
| 发行合作 | 自发行或外部发行合同，简化分成与里程碑 | 用分成换取渠道/营销/资金确定性 |
| AI竞争者 | 以工作室/发行商为主，有限数量、共用规则 | 观察竞品、抢窗口、差异化定位 |
| 时间与历史 | 1970起步、年代技术/平台准入、每日模拟 | 选择时代机会并适应市场变化 |

## 3. 首发明确延期

| 内容 | 首发处理 | 延期原因 |
|---|---|---|
| 玩家运营游戏平台 | DEFERRED，仅作为外部市场平台 | 网络效应和双边市场是独立大型系统 |
| 玩家经营商业游戏引擎 | DEFERRED；研发工具仅作内部能力/科技加成 | 授权生态、兼容性、开发者关系复杂 |
| 硬件设计与制造 | DEFERRED | 供应链、产能、库存和资本开支会冲淡核心循环 |
| IPO、股票、复杂股权、融资 | DEFERRED | 非首发核心经营决策 |
| 并购与集团多事业部 | DEFERRED | 需先证明单公司经营循环有趣 |
| 多人联机、在线创意工坊 | DEFERRED | 技术和运营成本高 |
| 复杂国家税制/劳动法 | 简化成地区成本与税率参数 | 不值得在首发投入大量法律史数据 |
| 数百个历史公司与事件 | 精选代表性内容 | 内容准确性和维护成本 |
| 深度授权、订阅、云服务生态 | DEFERRED | 后期内容扩展 |

## 4. 保留但降级的系统

- **平台**：首发只定义平台的上市准入、用户规模、地区覆盖、抽成、技术限制、生命周期和受众结构。平台由历史公司/AI控制，玩家选择是否支持。
- **引擎**：首发作为内部研发工具能力，影响生产效率、稳定性和兼容性，不做独立引擎公司经营。
- **发行**：首发保留合同、分成、预付款/里程碑、营销支持、地区覆盖与控制权，不实现庞大法务模拟。
- **科技研究**：压缩成与研发生产直接相关的技术能力树，不独立构建庞大科研帝国。
- **世界市场**：首发使用少量可玩区域，区域之间在购买力、偏好、平台覆盖、价格敏感度和发行成本上有差异。

## 5. 首发区域建议

首发以6个宏观市场区域作为经济模拟单元：北美、日本、西欧、英国/其他英语市场（如数据结构允许可并入西欧）、东亚其他地区、其他地区。最终合并口径应避免重叠。建议首发实际使用：北美、日本、西欧、东亚其他地区、拉丁美洲、其他地区，共6区。国家可作为显示/历史叙事信息，不在首发按每个国家单独模拟全部经济。

城市选择首发简化为少量创业地点（约8–12个），只影响工资、租金、人才供给、税费和市场接近度。城市不需要独立人口经济模拟。

## 6. 首发内容量目标（建议上限/下限，不是硬凑数）

- 可玩市场区域：6
- 创业城市：8–12
- 可操作游戏类型：12–18个主类型，子类型作为标签
- 消费者群体：6–8个清晰群体
- 平台世代/代表平台：15–25个精选条目
- 技术节点：30–45个与研发/平台兼容相关的节点
- AI竞争公司：20–35家分阶段登场，避免1970年全量堆入
- 历史公司档案：30–50家精选，先保证时间和业务字段准确
- 历史事件：40–80个有玩法影响的事件
- 营销渠道：4–6种首发渠道

每条数据必须改变玩法、提供历史识别价值或支持关键规则。不能为了达到数字而生成重复条目。

## 7. 1970–2026时间范围的处理

保留1970-01-01开局与长期推进，但不要承诺所有地区、公司和产品在每一年都拥有同等史实精度。采用“核心历史节点准确 + 非核心市场抽象 + 历史之后自由模拟”。每个历史数据项必须标注精度与来源状态。首发阶段优先保证1970–2000的准入逻辑和关键平台节点，2000–2026用较高层级的市场/技术世代表达；后续再补精细史实。

## 8. 变更控制

本版范围决定为 `DECIDED`。Agent不得擅自将延期系统重新加入首发，也不得因为“架构预留”而创建未实现的UI入口。任何范围扩张必须说明：新增玩家决策、与核心循环的因果联系、开发成本、测试成本及替代删减项。
