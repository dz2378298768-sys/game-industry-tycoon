# 内容范围与数据质量

## 1. 内容策略

首发内容不是百科全书，而是支撑可玩的市场变化和历史氛围。每个数据项都要回答：它会改变什么规则、解锁什么内容、影响什么玩家决策？若没有答案，首发不制作。

## 2. 精简内容目标

| 数据域 | 首发目标 | 必需字段 |
|---|---:|---|
| 市场区域 | 6 | 购买力、偏好、价格敏感、平台覆盖、发行成本、年代变化 |
| 创业城市 | 8–12 | 工资、租金、人才供给、税费、市场接近度 |
| 游戏类型 | 12–18 | 基础受众、质量偏好、研发复杂度、生命周期特征 |
| 消费者群体 | 6–8 | 类型兴趣、价格敏感、质量偏好、平台可及性 |
| 平台 | 15–25 | 准入日期、地区、受众、抽成、生命周期、技术要求 |
| 技术节点 | 30–45 | 前置、年代准入、研发影响、平台关联 |
| AI公司 | 20–35 | 业务起始、战略、地区、规模、产品偏好、状态 |
| 历史公司档案 | 30–50 | 法人/品牌/电子游戏业务/领域业务分离，来源可追溯 |
| 历史事件 | 40–80 | 触发日期/条件、影响对象、持续时间、游戏效果 |
| 营销渠道 | 4–6 | 可用年代、成本、覆盖、受众、边际递减 |

以上是范围目标，不是完成声明。质量优先于数量。

## 3. 历史公司日期必须拆分

至少区分：法人/组织前身成立、品牌形成、电子游戏业务开始、具体业务领域开始、地区业务开始、业务终止/更名/收购。不得把早期非电子游戏业务成立日期直接标记为电子游戏公司成立日期。

## 4. 史实字段

每条史实记录必须包含：sourceId、sourceTitle、publisher、sourceUrl或档案编号、accessDate、claim、confidence、status、notes。关键日期至少有一个高质量来源；存在争议时保存冲突解释，不强行选一个日期。

状态：VERIFIED、PARTIALLY_VERIFIED、ESTIMATE、CONFLICTED、UNKNOWN、SIMULATED。模拟结果不可写入史实表。

## 5. 历史准入与自由模拟

历史日期只决定某公司/技术/平台何时具备出现资格。准入之后由AI和市场规则决定发展，不强制重现真实销量、产品和市场份额。历史模拟模式与沙盒模式可使用不同事件强度，但共用基本经济规则。

## 6. 数据质量门槛

- 不允许关键日期为空却标记VERIFIED。
- 不允许将未知数值写成0。
- 不允许重复实体或同一公司多个别名各自当作独立公司。
- 每个可玩平台必须有清晰准入、用户规模曲线或明确抽象规则。
- 每个事件必须对玩法产生可见影响，纯百科描述不进入首发事件系统。
- 每个数据文件通过Schema校验、引用完整性检查和重复项检查。

## 7. 数据分层

BaseDefinitions（稳定规则定义）、HistoricalWorld（史实准入与档案）、EconomyBalance（可校准参数）、GameRules（难度与模式规则）、Localization（文本）、UserMods（首发仅预留声明式数据契约）。内容与模拟代码分离。
