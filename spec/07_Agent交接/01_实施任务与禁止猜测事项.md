# Agent实施任务与禁止猜测事项

## 1. 实施原则

先实现深度闭环，再实现内容广度。Agent不得自行扩展首发范围，不得用占位数据伪装真实数据，不得把未校准参数写成最终常量。

## 2. 推荐工程顺序

1. 建立领域模型、日期、随机数、财务唯一入口和事件日志。
2. 实现员工/团队工作量与项目状态机。
3. 实现项目范围、质量维度、QA和产品生成。
4. 实现市场需求管线、定价、营销、销量和退款。
5. 实现产品生命周期、补丁和财务闭环。
6. 实现经营总览、项目、员工、产品、市场、财务UI。
7. 实现发行合作合同。
8. 实现有限AI竞争者。
9. 实现精简历史内容和年代准入。
10. 完成存档、长期模拟、平衡和UI测试。

## 3. 核心领域边界

- `GameCalendar`：唯一日期推进入口。
- `RandomService`：唯一模拟随机入口，存档保存状态与算法版本。
- `FinanceService`：唯一现金写入入口，所有交易幂等。
- `ProjectService`：项目状态、范围、团队分配和进度。
- `ProductService`：上市产品、价格、补丁和生命周期。
- `MarketSimulationService`：需求、认知、转化、销量和退款。
- `MarketingService`：营销活动和预算消耗。
- `ContractService`：发行合作合同与结算。
- `CompanyAIService`：候选行动生成、约束检查、评分和执行命令。

模拟核心使用纯TypeScript，不依赖React/DOM。UI通过命令调用领域服务，订阅领域事件或只读快照。

## 4. 禁止自行决定

Agent不得自行决定以下事项：
- 未定义的销售转化率、价格弹性、生命周期衰减率；
- 项目工作量、员工产能、质量乘数和疲劳影响；
- 历史公司成立/业务日期、平台准入日期；
- 初始工资、租金、研发成本和历史通胀换算；
- 破产宽限期、违约费用、税率；
- AI隐性加成和项目并发上限；
- 首发新增平台经营、引擎商业化、硬件制造、并购、IPO等功能。

如参数未定：使用明确配置项、状态标记和可测试默认值候选；不得伪装成已确认值。关键规则缺失时停止该模块并提交待决项。

## 5. 每个任务交付格式

- 修改文件清单；
- 实现的领域规则与接口；
- 新增/修改测试；
- 测试命令与实际结果；
- 未实现项；
- 未解决风险；
- 对存档/schema的影响。

禁止只回复“已完成”而没有可核查文件和测试结果。

## 6. Definition of Done

系统完成必须同时满足：规则与规格一致、领域测试通过、集成场景通过、UI行为符合页面规格、存档兼容、无越权写状态、失败路径可恢复、文档更新。没有执行的测试标记NOT_RUN，不得写PASS。
