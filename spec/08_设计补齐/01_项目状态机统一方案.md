# 项目状态机最终定义 V2.1.1（DECIDED）

> 本文档是项目状态机的**唯一权威定义**，所有其他规格文件中的旧定义以本文为准。

## 0. 决策总表

| 问题 | 决策 | 原因 |
|---|---|---|
| ProjectPhase 是否包含 PAUSED？ | **不包含**。PAUSED 不作为主状态枚举值。 | 暂停期间项目逻辑完全继承暂停前的主阶段，独立 phase 会导致大量重复守卫分支 |
| ProjectPhase 是否包含 CANCELLED？ | **包含**。CANCELLED 是终态枚举值。 | 取消是不可逆的终止，需要独立 phase 表示 |
| 暂停用什么字段表达？ | `isPaused: boolean` | 任何未上市阶段都可以暂停；暂停 = `isPaused: true` |
| 玩家可见状态是 phase 还是 phase + isPaused？ | 合并显示。"PRODUCTION + isPaused=true" → UI 显示"制作中（暂停）" | 玩家不关心内部字段拆分，只关心项目当前状态 |

## 1. ProjectPhase 枚举（仅 7 个值）

```typescript
type ProjectPhase =
  | 'CONCEPT'         // 概念与立项
  | 'PRE_PRODUCTION'  // 预制作
  | 'PRODUCTION'      // 制作
  | 'QA'              // 测试与修复
  | 'READY_TO_LAUNCH' // 上市准备
  | 'LAUNCHED'        // 已上市
  | 'CANCELLED'       // 取消（终态，不可逆）
```

**不包含 PAUSED、FAILED、RELEASE_SCHEDULED、DRAFT、EVALUATING、APPROVED、IN_DEVELOPMENT**。这些名字全部被折叠进上述 7 个主 phase。

## 2. Project 实体的状态相关字段（最终版）

```typescript
interface Project {
  // ... 其他字段省略 ...

  phase: ProjectPhase              // 主阶段枚举，取上表 7 个值之一
  subPhase: ConceptSubPhase | null // 仅 CONCEPT 阶段使用：'DRAFT' | 'EVALUATING' | 'APPROVED'
  isPaused: boolean                // true = 暂停中；false = 正常推进
                                   // LAUNCHED 或 CANCELLED 时必须为 false（不可暂停）
  cancellationReason: CancellationReason | null  // CANCELLED 时必填
  failureFlags: string[]           // 失败痕迹（如 ['high_defect_rate', 'market_window_missed']）
  // ...
}
```

**约束（TypeScript discriminated union 可表达）**：
- 当 `phase === 'CANCELLED'` 时，`cancellationReason` 必填，`isPaused` 必须为 false
- 当 `phase === 'LAUNCHED'` 时，`isPaused` 必须为 false
- 当 `phase === 'CONCEPT'` 时，`subPhase` 必填（'DRAFT' 初始值）
- 当 `phase !== 'CONCEPT'` 时，`subPhase` 必须为 null

## 3. 状态转换图（唯一权威版本）

```
                        ┌──────────────┐
                        │   CONCEPT    │ ◄── 创建项目（subPhase = 'DRAFT', isPaused = false）
                        └──────┬───────┘
                               │ 立项批准 → subPhase 变为 'APPROVED'，然后 phase 推进
                               ▼
                        ┌──────────────┐
                 ┌────►│ PRE_PRODUCTION│
                 │     └──────┬───────┘
                 │            │ 核心设计完成 + 技术验证通过
                 │            ▼
                 │     ┌──────────────┐
                 │     │  PRODUCTION  │
                 │     └──────┬───────┘
                 │            │ 范围完成度 ≥ 90% 或 玩家主动提前
                 │            ▼
                 │     ┌──────────────┐
                 │     │     QA       │
                 │     └──────┬───────┘
                 │            │ 上市决策（修复 / 缩范围 / 按期）
                 │            ▼
                 │     ┌──────────────┐
                 │     │READY_TO_LAUNCH│
                 │     └──────┬───────┘
                 │            │ 到达 plannedLaunchDay
                 │            ▼
                 │     ┌──────────────┐
                 │     │   LAUNCHED   │ ──► Product 实体独立开始生命周期
                 │     └──────────────┘
                 │
                 │  CANCELLED（终态）：
                 │   CONCEPT / PRE_PRODUCTION / PRODUCTION / QA / READY_TO_LAUNCH
                 │     任何阶段 ──► CANCELLED（玩家主动取消 / 连续 60 天 isPaused=true）
                 │   LAUNCHED 阶段不能取消（用 Product 退市功能代替）
                 │
                 │  isPaused 暂停/恢复（不改变 phase）：
                 │   任何 非 LAUNCHED、非 CANCELLED 的阶段
                 │     isPaused: false ──► true   暂停（玩家主动 / 预算耗尽自动）
                 │     isPaused: true  ──► false  恢复（玩家主动 / 预算问题解决自动）
```

## 4. 转换守卫（所有守卫在 ProjectService 内部统一执行）

| 操作 | 前置守卫 | 执行效果 |
|---|---|---|
| 创建项目 | 公司核心岗位 ≥ 1 人 | phase='CONCEPT', subPhase='DRAFT', isPaused=false |
| CONCEPT→PRE_PRODUCTION | subPhase='APPROVED'；预算上限合法；核心岗位预分配完成 | phase='PRE_PRODUCTION', subPhase=null |
| PRE_PRODUCTION→PRODUCTION | 核心设计文档确认；技术验证通过 | phase='PRODUCTION' |
| PRODUCTION→QA | **所有制作学科完成度 ≥ 90%**（设计/程序/美术等；不检查 QA 学科——QA 工作量是进入 QA 阶段后才开始推进的）；或玩家主动提前（qualityRiskFlag='early_qa'） | phase='QA' |
| QA→READY_TO_LAUNCH | 玩家做出上市决策并确认定价+发行+营销 | phase='READY_TO_LAUNCH' |
| READY_TO_LAUNCH→LAUNCHED | 当前 DayIndex ≥ plannedLaunchDay | phase='LAUNCHED'；isPaused=false；生成 Product 实体 |
| 暂停 | phase ∈ {CONCEPT, PRE_PRODUCTION, PRODUCTION, QA, READY_TO_LAUNCH} **且** isPaused=false（即 `phase !== 'LAUNCHED' && phase !== 'CANCELLED' && !isPaused`） | isPaused=true |
| 恢复 | isPaused=true | isPaused=false |
| 取消 | **`phase !== 'LAUNCHED' && phase !== 'CANCELLED'`**（逻辑 AND，不是 OR；任何 phase 是这两个终态之一就不能取消） | phase='CANCELLED', cancellationReason, isPaused=false |

## 5. 暂停的预算与进度影响

`isPaused=true` 期间：
- **学科工作量推进**：全部停止（effectiveWork = 0 for all disciplines）
- **预算消耗**：停止项目直接支出；已承诺支出（如合同）继续发生
- **团队分配**：不变，TeamAssignment 保留；但员工的每日项目产出 = 0
- **质量评估**：暂停期间不变化；恢复后继续从暂停前的状态推进
- **自动取消**：连续 isPaused=true 60 天（不是 60 个自然日，是项目实际暂停天数计数器）→ 系统自动触发取消流程
