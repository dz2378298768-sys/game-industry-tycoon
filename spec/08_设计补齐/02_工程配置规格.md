## 3. 目录结构约定（DECIDED）

```
src/
├── app/                    # 应用壳、路由、全局 Provider
├── ui/                     # React 展示组件层
│   ├── components/         # 可复用 UI 组件（表格、图表、按钮、弹窗）
│   ├── pages/              # 按业务页面分组的页面组件
│   ├── hooks/              # UI 层专用 hooks
│   └── state/              # Zustand store（仅 UI 快照和临时交互）
├── application/            # 命令/查询用例层
│   ├── commands/           # 命令对象定义 + 命令处理器
│   ├── queries/            # 查询用例（返回只读快照）
│   └── mediators/          # 跨 Service 协调器
├── domain/                 # 领域层（纯类型，无逻辑，无 React 依赖）
│   ├── entities/           # 实体类型定义（Company, Employee, Project, Product...）
│   ├── value-objects/      # 值对象类型定义（Money, DayIndex, QualityProfile...）
│   ├── enums/              # 枚举（ProjectPhase, MarketRegion, PlatformType...）
│   └── errors/             # 领域错误类型
├── simulation/             # 模拟核心（纯 TS，无 React 依赖）
│   ├── services/           # GameCalendar, FinanceService, RandomService...
│   ├── systems/            # 各每日阶段的纯函数
│   ├── phase/              # 每日阶段调度器
│   └── deterministic/      # PRNG、哈希、稳定排序
├── infrastructure/         # 技术适配层（浏览器 API、存档、文件加载）
│   ├── storage/            # IndexedDB 存档读写 + 压缩/解压
│   ├── loading/            # JSON 数据文件加载 + Zod 校验
│   └── time/               # 浏览器时间 API 适配（仅用于 UI 计时，不进入模拟）
├── content/                # 结构化内容数据（JSON）
│   ├── market_regions.json
│   ├── cities.json
│   ├── genres.json
│   ├── consumer_segments.json
│   ├── platforms.json
│   ├── technologies.json
│   ├── historical_companies.json
│   ├── historical_events.json
│   ├── marketing_channels.json
│   ├── contract_templates.json
│   └── economy_balance.json
├── i18n/                   # 本地化文本
│   ├── en.json
│   └── zh-CN.json
└── main.tsx                # 入口
```

**依赖方向规则（强制）**：

```
main.tsx → app → ui → application → simulation → domain
                        ↓
                   infrastructure (只被 application 调用，不被 domain 调用)
                        ↓
                   content (被 infrastructure/loading 读取)
```

**禁止**：domain / simulation 导入 React / DOM / 浏览器 API；application 直接修改 domain 实体；UI 层绕过 application 直接调用 simulation service。

## 4. Lint 规则要点（DECIDED）

- 启用 `@typescript-eslint/no-explicit-any`（例外必须注释说明并登记）
- 启用 `@typescript-eslint/consistent-type-imports`
- 启用 `react-hooks/rules-of-hooks` 和 `react-hooks/exhaustive-deps`
- 禁止 `Math.random()` / `Date.now()` / `new Date()` 出现在 domain 或 simulation 层
- 禁止直接修改 domain 实体属性，必须通过 application commands

## 5. PRNG 算法选型（DECIDED）

**选用**：`mulberry32` — 轻量、可复现、周期 2^32、实现仅数行、状态可完整序列化。

**派生子流规则**：每次需要随机值时，从 `saveSeed` 派生子流，派生公式：
```
subSeed = hash(saveSeed + 0x9e3779b9 + dayIndex + fnv1a(entityId + subsystemId + eventId))
```
其中 hash 使用简单稳定的整数混合（mulberry32 自己的混合函数即可）。这样新增随机调用不会影响其他系统的随机结果序列。

**算法版本标记**：`simulationAlgorithmVersion: 'mulberry32-v1'`，写入存档。PRNG 升级时递增版本号，旧存档迁移时保留原始版本但标记为 legacy。

## 6. 存档技术选型（DECIDED）

- **存储**：IndexedDB（浏览器原生，支持大对象，异步）
- **封装库**：idb-keyval（极简 API，够用）
- **压缩**：lz-string（纯 JS，压缩率好）
- **存档结构**：
  ```
  GameSave_v1 = {
    schemaVersion: number,
    simulationAlgorithmVersion: string,
    saveSeed: number,
    currentDayIndex: number,    // ✅ V2.1.6 统一 SaveMeta：不再有 randomState / prngState
    worldState: { ... },        // 完整领域状态快照
    eventLog: Event[],          // 可裁剪，保留最近 N 条 + 关键里程碑
    createdAt: DayIndex,
    lastPlayedDay: DayIndex,
    appVersion: string,
    platformInfo: 'web'        // 后续 Tauri 打包可扩展
  }
  ```

## 7. 构建与运行命令（DECIDED）

```
npm run dev          # 开发服务器
npm run build        # 生产构建
npm run preview      # 预览生产构建
npm run typecheck    # 仅 TypeScript 类型检查（CI 前置，只读）
npm run lint:check   # ESLint 仅检查，不修改文件（CI 前置，只读）
npm run lint:fix     # ESLint 自动修复可修复问题（本地手动执行，会修改文件）
npm run format:check # Prettier 仅检查格式（CI 可选，只读）
npm run format:write # Prettier 自动修正格式（本地手动执行，会修改文件）
npm run test:unit    # vitest 单元 + 集成测试（src/domain + src/simulation + src/application）
npm run test:ui      # vitest 组件测试（src/ui）
npm run test:e2e     # playwright E2E 测试（P1）
npm run test:all     # test:unit + test:ui + typecheck + lint:check（CI 主流程）
npm run test:deterministic  # 可复现性专项测试（同种子同输入 → 同哈希）
npm run test:calibration    # 参数校准脚本（运行 N 年模拟，输出指标报告）
```

**重要**：禁止在 CI 中运行 `lint:fix` 或 `format:write`（自动修改文件会导致 CI 不可预测的 diff）。自动修复命令仅在本地开发时手动执行。

首发仅做浏览器端（localhost dev / Vercel / GitHub Pages 静态部署）。Tauri Windows 封装安排在 P2，不在本轮交付。

## 9. 与 V2.0 工程架构的差异

| 项 | V2.0 规格 | 本补充 | 原因 |
|---|---|---|---|
| React 版本 | 未指定 | ^18.3 | 19 发布不足半年，生态未稳定 |
| Zustand 版本 | 未指定 | ^4.5 | 5.x 刚发布，API 有 breaking change |
| UI 组件库 | 未指定 | 不引 | 复古工业风定制，组件库反而拖累 |
| PRNG | "版本化 PRNG" | mulberry32 | 需要明确选型才能写代码 |
| 存档封装 | "IndexedDB" | idb-keyval + lz-string | 需要具体库才能写代码 |
| 目录结构 | 有目录名 | 有目录名 + 依赖方向规则 + ESLint 禁止项 | Agent 会违反分层，需要硬性约束 |
