# 领域实体与值对象完整字段定义

> 补充原因：各系统规格文档中零散描述了实体字段，但没有集中、完整、类型化的字段清单。Agent 无法知道某个实体到底有哪些可选字段、哪些是必填、字段之间有什么引用关系。本文件给出所有核心领域实体和值对象的完整字段定义。

## 0. 总体设计原则

- 所有 ID 使用 UUID 或命名空间 ID（格式：`{type}-{prefix}-{uuid}`），禁止数组下标或自增数作为持久化主键
- 所有日期用 `dayIndex: number`（整数，1970-01-01 = day 0），禁止 Date 对象进入领域层
- 所有金额用整数最小单位（美分），保存为 `number`，对外显示时除以 100
- 所有实体必须有 `version: number` 字段（乐观锁，每次写操作 +1）
- 所有实体必须有 `createdAt: DayIndex` 和 `updatedAt: DayIndex`
- 引用完整性由 Application 层在命令校验时保证，不指望 TypeScript 编译器

## 1. 值对象（Value Objects）

值对象不可变、无身份标识、靠值相等。

### 1.1 Money

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| amount | number | ✅ | 整数美分；正数为收入/资产，负数为支出/负债 |
| currency | 'USD' | ✅ | 首发只做美元，但保留多币种扩展可能 |

**运算规则**：两个 Money 相加必须 currency 相同；不同 currency 相加需要显式转换。所有四则运算结果自动截断为整数（除法向下取整）。

### 1.2 DayIndex

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| value | number | ✅ | 整数，1970-01-01 = 0 |

**运算规则**：
- `dayIndex + number`（加天数）→ DayIndex
- `DayIndex - DayIndex` → number（间隔天数）
- `DayIndex.toGregorian(): {year, month, day, isLeapYear}` → 只读查询

### 1.3 QualityProfile

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| gameplay | number | ✅ | 玩法/设计质量，0-100 |
| technical | number | ✅ | 技术稳定性，0-100 |
| content | number | ✅ | 内容完成度，0-100 |
| art | number | ✅ | 美术呈现，0-100 |
| innovation | number | ✅ | 创新性，0-100 |

**规则**：市场模型按消费者群体的偏好权重加权这五个维度，不只用总分。

### 1.6 TeamAssignment

| 字段 | 类型 | 必填 | 说明 |

## 3. 关系总览

```
Company ──1:N──► Employee            (companyId)
Company ──1:N──► Project             (companyId)
Company ──1:N──► Product             (companyId)
Company ──1:N──► Contract            (companyId)
Company ──1:N──► MarketingCampaign   (companyId)
Company ──1:N──► Transaction         (companyId)
Employee ──N:N──► Project            (通过 TeamAssignment)
Project ──1:1──► Product             (sourceProjectId)
Project ──1:N──► RangeItem           (scope[])
Project ──1:N──► ChangeLogEntry      (changeLog[])
Project ──1:N──► TeamAssignment      (teamAssignments[])
Product ──1:N──► SalesRecord         (salesByPeriod[])
Product ──1:N──► MarketingCampaign   (marketingCampaignIds[])
Contract ──1:1──► Project / Product  (productId 或隐含 projectId)
```

**所有引用都通过 ID 字符串，不通过对象直接引用**。这让存档序列化简单、循环引用零风险。
