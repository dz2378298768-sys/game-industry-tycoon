# 内容数据最小集规格

> 补充原因：V2.1/05_内容范围与数据质量.md 只给了目标数量（6 市场区域、8-12 城市、15-25 平台...）和必需字段列表，但没有明确每个 JSON 文件的完整字段定义、数据质量校验规则、V1.0 可复用数据清单。本文补齐这些。

## 0. 数据分层（DECIDED）

```
content/
├── BaseDefinitions/    # 稳定规则定义：类型、消费者群体、营销渠道、合同模板
├── HistoricalWorld/    # 史实准入：历史公司、平台、技术、事件
├── EconomyBalance/     # 可校准参数：economy_balance.json
├── GameRules/          # 难度模式规则
└── Localization/       # en.json / zh-CN.json
```

每个 JSON 文件顶层必须有 `_meta` 字段：
```json
{
  "_meta": {
    "version": 1,
    "schemaVersion": 1,
    "lastReviewDate": "2026-11-18",
    "dataStatus": "DESIGN",
    "notes": "首发最小集，部分数据为 ESTIMATE"
  },
  "<collectionName>": [ ... ]
}
```

## 12. 数据校验规则（每个文件的 schema 约束）

所有 JSON 文件通过 Zod 或 JSON Schema 校验，Agent 实现 `infrastructure/loading` 时必须严格执行：

| 规则 | 说明 |
|---|---|
| 所有 id 唯一 | 同一文件内不允许重复 |
| 引用完整性 | genreId、platformId、regionId 等引用必须存在于对应数据文件 |
| 数值范围约束 | probability ∈ [0, 1]；quality ∈ [0, 100]；multiplier > 0 |
| 日期/年份合法性 | earliestAvailabilityYear ≥ 1970；endYear ≥ startYear |
| priceSensitivity + qualityPrefWeight 等必须是合法的 QualityProfile | 每个维度 ∈ [0, 100] |
| 空值一律 null | 禁止 0 或空字符串伪装 unknown |

## 14. 数据录入优先级（给后续数据工作参考）

1. **economy_balance.json** — 实现的前置（TUNING 值必须先有）
2. **genres + consumer_segments + platforms** — 项目创建命令的必填引用
3. **market_regions + cities** — 公司创建命令的必填引用
4. **technologies.json（V1.0 复用 + 补字段）** — 项目和平台准入校验需要
5. **marketing_channels + contract_templates** — 上市和发行命令需要
6. **historical_companies.json（V1.0 复用 + 补日期）** — AI 竞争者列表
7. **historical_events.json** — 可后期补充（不阻塞核心循环）
