# P0 页面整改模板（8 页完整填写）

> 补充原因：V2.1/04_UI与交互整改/01_UI逐页规格整改标准.md 给出了 11 项强制模板，但没有任何页面完整填写。本文对 8 个 P0 页面逐一填写模板内容，作为 Agent 实现 UI 的直接依据。

---

## P0-1 经营总览（DailyHub）

### 1. 基础信息
- **页面 ID**：`daily_hub`
- **显示名**：经营总览
- **用途**：玩家每次进入游戏或推进日期时看到的第一个页面。核心目标："今天发生什么、我最危险的风险是什么、下一个要做什么决策"
- **进入方式**：游戏内主界面默认页面；导航栏"总览"按钮；首页快捷方式
- **退出/返回**：导航栏切换到其他页面；ESC 返回菜单

### 2. 页面布局（1920×1080）
- **顶栏（全宽 × 48px）**：游戏标题 | 当前日期（dayIndex + 公历）| 模拟速度控制（暂停 / 慢速(0.25天/秒) / 正常(1天/秒) / 快速(3天/秒) / 极速(7天/秒) / 单步(1天)）| 暂停按钮 | 设置图标 | 存档状态指示
- **左侧栏（280px × 全高 - 48px）**：
  - 公司名 + 成长阶段 + 品牌 / 技术 / 管理容量徽章
  - 员工总数 / 活跃项目数 / 产品数
  - 快速导航：总览 / 项目 / 员工 / 产品 / 市场 / 财务 / 发行 / 科技
- **中央主区（flex: 1 × 优先）**：
  - 上方：3 张风险预警卡（现金跑道 ≤ 60 天、项目预算 ≤ 20%、合同即将到期）
  - 中部：待处理决策列表（新立项批准、QA 决策、合同签署、营销活动）
  - 下方：进行中项目状态缩略 + 最新产品销售趋势图（ECharts 迷你版）
- **右侧栏（300px × 全高 - 48px）**：
  - 今日事件时间线（DayAdvanced 触发的所有领域事件，按时间排序）
  - 市场机会提示（竞品上市窗口、未满足需求、平台准入即将开启）
- **底部状态栏（全宽 × 28px）**：上次自动存档日 | 模拟算法版本 | 当前种子（开发模式显示）

### 3. 风险预警卡字段

| 字段 ID | 显示名 | 数据类型 | 单位 | 来源 | 默认值 | 是否可编辑 | 格式化 | 空值表现 |
|---|---|---|---|---|---|---|---|---|
| riskCategory | 风险类型 | enum | — | RiskAssessment | — | 只读 | 中文枚举显示 | 无风险时不显示此卡 |
| riskSeverity | 严重度 | enum | — | RiskAssessment | — | 只读 | 色条：低=绿/中=黄/高=红 | 同上 |
| riskValue | 风险数值 | number | 天 / % | RunwayForecast / Project.riskFlags | — | 只读 | 按单位格式化 | 同上 |
| riskAction | 建议操作 | string | — | RiskAssessment | — | 只读 | 中文文案 | 同上 |
| riskActionButton | 操作按钮 | — | — | — | — | 可点击 | 跳转到对应页面的命令 | 同上 |

### 4. 风险预警卡命令流程
1. 点击"查看详情"按钮 → 打开对应页面（项目详情 / 财务页）并自动滚动到相关位置
2. 点击"立即处理" → 执行 QuickCommand（如"暂停该项目" / "降低营销预算"），带确认弹窗
3. 每张卡有关闭按钮（不取消风险，仅在本次会话中隐藏）

### 5. 状态
- **首次加载**：显示 loading skeleton（1 秒内完成）
- **加载中**：骨架 + 日期保持上次值
- **空数据**：新公司（day 0）时风险卡区显示"欢迎界面"引导下一步操作
- **错误**：红色 banner + 重试按钮
- **无权限**：不适用（玩家永远有自己公司的权限）
- **模拟暂停**：速度按钮显示"已暂停"，可恢复

### 6. 窗口适配
- **1920×1080**：完整布局
- **1280×720**：右侧栏折叠为图标，中央区增加宽度
- **< 1280**：左侧栏也折叠，中央区全宽

### 7. 可访问性
- Tab 顺序：顶栏 → 左侧导航 → 中央风险卡 → 决策列表 → 右侧事件时间线
- 快捷键：`Space` 暂停/恢复，`N` 前进一天，`Esc` 返回上一级
- 状态变化颜色外还必须有图标或文字区分（不依赖颜色 alone）

## P0-2 项目列表（ProjectListPage）

### 1. 基础信息
- **页面 ID**：`project_list`
- **用途**：查看所有项目、筛选、批量暂停/恢复、进入详情
- **进入方式**：导航栏；总览页项目区点击"全部"
- **退出**：导航栏；ESC

### 2. 页面布局（1920×1080）
- **顶栏（48px）**：页面标题 + "全部项目 (N)" + 创建项目按钮
- **筛选区（56px）**：
  - 状态筛选：下拉多选（CONCEPT / PRE_PRODUCTION / PRODUCTION / QA / READY_TO_LAUNCH / LAUNCHED / PAUSED / CANCELLED）
  - 学科瓶颈筛选：下拉单选（无 / design / programming / art / qa）
  - 预算风险筛选：下拉单选（全部 / 安全 / 预警 < 30% / 危险 < 10%）
  - 时间排序：下拉（风险等级 → 预计完成日；预算消耗 → 剩余预算；创建日降序）
  - 搜索框：项目名称模糊搜索
- **主表格区**：项目列表
- **批量操作区（底部固定 40px，选中 ≥ 1 行时显示）**：暂停选中 / 恢复选中 / 取消选中（批量取消必须逐项确认）

### 3. 主表格字段

| 字段 | 类型 | 可排序 | 可筛选 | 说明 |
|---|---|---|---|---|
| 名称 | string | — | ✅ 搜索 | Project.name |
| 阶段 | enum | ✅ | ✅ 多选 | Project.phase + isPaused 合并显示（"制作中（暂停）"） |
| 学科瓶颈 | enum | ✅ | ✅ | ProjectService.getBottleneckDiscipline() |
| 预算消耗 | progress bar | ✅ | ✅ | ProjectBudget.spent / ProjectBudget.totalCap，颜色映射风险 |
| 预计完成 | day index range | ✅ | — | ProjectService.estimateTimeline() 区间 |
| 风险等级 | enum | ✅ | ✅ | ProjectService.getRiskAssessment().overallRating |
| 发起人 | string | — | — | 该项目的 TeamAssignment 中 roleOnProject = 'lead' 的员工姓名 |
| 范围项数 | number | ✅ | — | scope.length |

### 4. 表格交互
- 点击行 → 跳转到 ProjectDetail 页面
- 支持 Shift + 点击多行选择
- 行 hover 显示右侧小箭头，点击可快速暂停/恢复（单项操作，不需要确认弹窗）
- 批量取消项目：弹窗逐项列出，每项单独勾选确认

### 5. 状态
- **空数据**：提示"暂无项目" + 引导创建新项目按钮
- **加载中**：骨架表格
- **加载失败**：红色 banner + 重试按钮
- **数据过期**：每次进入页面时自动刷新；每 10 秒定时刷新

## P0-3 立项向导（CreateProjectWizard）

### 1. 基础信息
- **页面 ID**：`create_project_wizard`
- **用途**：创建新项目的 6 步引导流程
- **进入方式**：项目列表页"创建项目"按钮；总览页"快速立项"按钮
- **退出**：左上角返回按钮（返回上一步）；ESC（弹出确认是否放弃当前填写）

### 2. 步骤流程
```
Step 1: 产品定位 → Step 2: 范围/功能 → Step 3: 平台/市场 → Step 4: 团队/预算 → Step 5: 上市计划 → Step 6: 确认摘要
```
步骤条在顶部显示当前位置和已完成状态。

### 3. Step 1：产品定位

| 字段 | 类型 | 必填 | 默认值 | 校验 |
|---|---|---|---|---|
| 项目名称 | 输入框 | ✅ | 空 | 2-40 字符；同公司内不重复 |
| 游戏类型 | 下拉 | ✅ | 空 | 引用 genres.json |
| 目标消费群体 | 多选下拉 | ✅ | 空 | 引用 consumer_segments.json；至少选 1 个 |
| 产品卖点标签 | 标签输入 | ❌ | 空 | 最多 5 个标签 |
| 目标质量（玩法） | 滑块 0-100 | ✅ | 60 | 必须 ≥ 30 |
| 目标质量（技术） | 滑块 0-100 | ✅ | 60 | 必须 ≥ 30 |
| 目标质量（内容） | 滑块 0-100 | ✅ | 60 | 必须 ≥ 30 |

**实时计算面板**（右侧）：
- 预计基础工作量（WorkPoint，保守/基准/乐观区间）
- 预计研发复杂度倍数
- 团队建议规模

### 4. Step 2：范围/功能

- 初始范围根据类型自动生成建议模板
- 每行 RangeItem：名称 / 负责学科 / 工作点 / 市场吸引力 / 风险
- 支持添加 / 删除 / 调整工作点
- 实时显示总 WorkPoint 和学科分布（设计/程序/美术/QA 堆叠条）
- 警告：若某学科工作量超过合理范围 → 提示可能成为瓶颈

### 5. Step 3：平台/市场

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| 目标平台 | 多选下拉 | ✅ | 引用 platforms.json；earliestAvailabilityYear ≤ 当前年份 |
| 目标市场区域 | 多选下拉 | ✅ | 引用 market_regions.json |
| 核心平台 | 单选（从上步选择中挑） | ✅ | 决定开发优先级 |

**实时显示**：平台技术复杂度乘数、市场区域受众估算、平台抽成总额估算

### 6. Step 4：团队/预算

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| 总预算上限 | 数字输入 | ✅ | ≤ 公司现金余额 |
| 项目开始日 | 日期选择器 | ✅ | ≥ 当前日 + 1 |
| 目标完成日 | 日期选择器 | ✅ | ≥ 开始日 + 最小工期（系统计算） |

**团队分配区**：
- 显示所有可用员工（未分配或 allocationRatio 未满）
- 每行：员工姓名 / 当前角色 / 当前分配情况 / 可分配比例滑块（max = 1 - 已分配比例）
- 自动校验：所有员工 allocationRatio 总和 ≤ 1.0

**实时警告**：
- 预算率 = 申请预算 / 保守估算预算，显示 fundingFactor 影响
- 团队某学科无人覆盖 → 红色警告
- 工期过短 → 黄色警告（建议延期或加人）

### 7. Step 5：上市计划

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| 上市定价策略 | 单选（低价渗透 / 基准 / 溢价精品） | ✅ | 影响建议售价区间 |
| 建议首发日 | 日期选择器 | ✅ | ≥ 完成日 |
| 发行方式 | 单选（自发行 / 与发行商合作） | ✅ | 选合作时跳到合同选择子步骤 |
| 初始营销预算 | 数字 | ✅ | ≥ 0 |

**实时显示**：保守/基准/乐观销量区间、首发净收入区间（按价格×销量-平台抽成-预算）

### 8. Step 6：确认摘要

- 汇总前 5 步的所有选择
- 系统显示：保守预算 / 基准预算 / 乐观预算 三档估算（日期 + 金额 + 风险）
- 风险提示列表（如有）
- "批准立项"按钮（CONCEPT 状态 → 系统评估后进入 PRE_PRODUCTION）

### 9. 守卫规则

| 规则 | 说明 |
|---|---|
| 现金不足 | 总预算上限 > 可用现金 → 红色阻止，不能进入下一步 |
| 团队核心岗位缺失 | 无任何 programmer 可分配 → 阻止 |
| 目标日期冲突 | 员工该日期已有其他项目 100% 分配 → 警告 |
| 历史平台准入 | 选择 1983 年的平台但当前年份是 1975 → 红色阻止 |

## P0-4 项目详情（ProjectDetailPage）

### 1. 基础信息
- **页面 ID**：`project_detail`
- **用途**：单项目全生命周期管理（从立项到取消/上市）
- **进入方式**：项目列表点击行；总览点击项目卡

### 2. 页面布局
- **顶栏（48px）**：返回按钮 | 项目名 | 阶段徽章 | 状态徽章（暂停/取消/已上市） | 三个行动按钮（依阶段变化）
- **左侧详情卡（320px）**：
  - 基本信息（类型、平台、市场、发起人、范围项数）
  - 预算消耗（进度条 + 已花/上限/剩余）
  - 团队分配（员工列表 + 分配比例 + 岗位）
- **中央主区**：
  - 阶段时间线（CONCEPT → PRE_PRODUCTION → PRODUCTION → QA → READY_TO_LAUNCH，当前阶段高亮）
  - 四学科进度堆叠条（设计/程序/美术/QA 分别显示已完成比例 + 剩余 WorkPoint）
  - 当前质量估算五维雷达图（QualityEstimate vs QualityTarget 对比）
  - 范围变更日志（ChangeLog 列表，最新在顶部）
- **右侧风险与预测卡（300px）**：
  - 瓶颈学科（红色标识）
  - 预计完成区间（保守/基准/乐观）
  - 综合风险等级 + 各维度分解
  - 预算预警等级

### 3. 按阶段变化的行动按钮（顶栏右侧）

| 当前阶段 | 可用按钮 1 | 可用按钮 2 | 可用按钮 3 |
|---|---|---|---|
| CONCEPT | 批准立项 → PRE_PRODUCTION | — | 取消项目 |
| PRE_PRODUCTION | 预制作完成 → PRODUCTION | 提前进入制作（风险增加） | 暂停 / 取消 |
| PRODUCTION | 进入 QA | 提前进入 QA（质量风险） | 暂停 / 取消 / 调整范围 |
| QA | 修复后上市 → READY_TO_LAUNCH | 缩范围后上市 | 暂停 / 取消 |
| READY_TO_LAUNCH | 确认上市（到达 plannedLaunchDay 时） | 延期 | 取消 |
| LAUNCHED | 跳转到 ProductDetail | — | — |
| PAUSED | 恢复项目 | — | 取消 |
| CANCELLED | 查看取消原因 | — | — |

### 4. 调整范围弹窗

- 显示当前所有 RangeItem（完成度列 + 沉没成本列）
- 可增删改
- 底部三栏实时计算：变更前剩余工作量 → 变更后剩余工作量 / 变更前预计完成 → 变更后 / 预算影响

### 5. 进入 QA 决策弹窗

显示：
- 当前缺陷分布（低/中/高严重度）
- 预估修复时间（按当前 QA 人员有效产出）
- 三种选项的后果对照表（修复延期上市 → 缺陷 → 退款率 → 评价 → 品牌）

### 6. 上市决策弹窗

必须显示：
- 保守 / 基准 / 乐观三档销量和净收入区间
- 与同期竞品对比
- 市场机会窗口评估（竞品是否刚上市 / 是否有同类型扎堆）
- 确认前必须勾选"已理解上述风险"

## P0-5 产品详情（ProductDetailPage）

### 1. 基础信息
- **页面 ID**：`product_detail`
- **用途**：上市后产品全生命周期管理
- **进入方式**：总览产品区点击；项目详情 LAUNCHED 状态跳转；导航栏"产品"

### 2. 页面布局
- **顶栏（48px）**：返回 | 产品名 | 生命周期阶段徽章 | 上市日 | 来源项目跳转链接
- **左侧核心指标（300px）**：
  - 累计销量 / 累计净收入（大字显示）
  - 评价均值（星级）+ 评价分布条
  - 品牌影响（±N）
  - 缺陷等级（上市时 vs 上市后）
- **中央主区**：
  - **销量趋势 ECharts**（日/周/月切换，含毛销量、净销量、退款线）
  - **按市场/平台/群体分布**（饼图 + 表格）
  - **质量五维雷达图**（上市时 vs 当前）
- **右侧操作卡（300px）**：
  - 定价管理（当前价 / 建议区间 / 调整按钮）
  - 折扣活动（当前进行中 + 新建）
  - 补丁（历史列表 + 新建）
  - 内容更新（历史列表 + 新建，首发限 1 次）
  - 停止维护按钮

### 3. 定价管理

| 字段 | 类型 | 说明 |
|---|---|---|
| 当前售价 | 数字 | 按市场区分别显示，可单独调整 |
| 建议区间 | 显示 | 系统基于竞品 + 质量 + 受众 + 品牌给出的三档 |
| 价格历史 | 图表 | 折线图，含上市初始价、折扣、调价点 |
| 价格调整命令 | 按钮 | 带二次确认弹窗，显示调整后影响（保守销量变化 ±N%） |

**规则**：
- 上市首日 ≤ 14 天禁止降价（保护定价稳定性）
- 提价必须有理由（品牌上升 / 系列续作关联）

### 4. 补丁管理

| 字段 | 类型 | 说明 |
|---|---|---|
| 补丁版本 | 显示 | 自动递增 v1.0.0 → v1.0.1 |
| 修复缺陷列表 | 多选 | 玩家从 QA 报告中选择要修复的缺陷 |
| 预估开发工时 | 显示 | 系统计算基于 QA 人力和缺陷数 |
| 费用估算 | 显示 | 人工工时 × 日薪 |
| 缺陷修复率目标 | 滑块 | 默认 100% 选中缺陷，可调低 |

### 5. 补丁命令流程
1. 点击"新建补丁" → 弹窗显示可选缺陷列表
2. 玩家勾选 → 系统实时计算工时、费用、缺陷减少率、对评价和口碑的预期改善
3. 玩家确认 → 触发 IssuePatchCommand → 团队分配 → 开发 → 完成后缺陷减少、口碑修复启动

## P0-6 财务现金流（FinancePage）

### 1. 基础信息
- **页面 ID**：`finance`
- **用途**：现金管理、账本查询、现金流预测、收支汇总
- **进入方式**：导航栏"财务"；总览点击财务风险卡；底部状态栏点击余额

### 2. 页面布局
- **顶栏（48px）**：返回 | 当前现金余额（大字显示，格式化千分位）| 跑道月数徽章 | 税务状态徽章
- **上方三张预测卡**：
  - 30 日预测（保守 / 基准 / 乐观）

- **中央主区（Tabs 切换）**：

## P0-8 发行合同（ContractPage）

### 1. 基础信息
- **页面 ID**：`contract`
- **用途**：发行合作合同签署、管理、里程碑追踪

### 2. 页面布局
- **顶栏**：标题 + 新建合同按钮
- **状态 Tab 切换**：待签署 / 进行中 / 即将到期 / 已完成 / 违约
- **主表格**（同 ProjectList 风格）：合同列表
- **右侧详情卡**（点击某合同后显示）

### 3. 合同列表字段

| 字段 | 说明 |
|---|---|
| 发行商 | 公司名 |
| 模板类型 | Channel Only / Joint Marketing / Advance Payment |
| 关联产品/项目 | 跳转链接 |
| 分成比 | 玩家 % → 发行商 % |
| 预付款 | 有/无 + 金额 |
| 营销义务 | 发行商承诺金额 |
| 起始日 / 到期日 | day index |
| 状态 | 徽章 |

### 4. 新建合同弹窗（从立项向导 Step 5 跳转时）

| Step | 字段 |
|---|---|
| Step 1: 选择发行商 | 候选发行商列表（按公司实力 + 匹配度排序） |
| Step 2: 选择模板 | 3 种模板 + 对比表（分成、预付款、义务） |
| Step 3: 配置细节 | 覆盖区域、覆盖平台、合同期、可选修改项 |
| Step 4: 模拟现金流 | 系统展示：保守/基准/乐观 三档收入预测 + 预付款回收时间 + 玩家净收入区间 |
| Step 5: 确认 | 控制权保留评分 + 控制权放弃清单 + 二次确认 + 幂等键 |

### 5. 合同详情卡

- 里程碑时间线（未完成 / 进行中 / 已完成）
- 预付款状态（已收 / 待收 / 回收中）
- 分成结算历史（日期 + 结算期 + 金额）
- 发行商营销活动列表（若发行商有义务）
- 违约风险评估

### 6. 守卫规则

| 规则 | 说明 |
|---|---|
| 同一产品不能同时签 2 个 active 合同 | 阻止签署 |
| 发行商现金不足预付款 | 阻止签署，显示发行商当前预估现金流 |
| 质量门槛检查 | Product.reviewScore < threshold 时自动降级合同或触发违约 |

## 通用验收要点（所有 P0 页面）

| 验收点 | 标准 |
|---|---|
| 数据新鲜度 | 每次进入页面时从 Application 层重新拉取，不依赖旧快照 |
| 写操作幂等 | 所有按钮点击触发的命令都带幂等键，防重复提交 |
| 空状态设计 | 每个列表 / 图表 / 卡片都有"无数据"场景的友好提示 |
| 错误处理 | 网络/数据加载失败时不崩溃，显示可重试 |
| 日期格式 | 统一：YYYY-MM-DD（公历）+ dayIndex（括号内） |
| 金额格式 | 千分位 + 货币符号 + 负数红字 |
| 可解释性 | 所有预测/估算必须标注"保守/基准/乐观"并能点击展开依据 |
| 状态标签 | 所有状态显示必须同时有图标 + 文字，不依赖颜色 alone |
